# AI 教学智能体：平台调研与建设规划

日期：2026-10-20。面向：数学学院信息化建设。
定位：本文是**决策文档**，不是完成报告。所有"已验证"标注来自 2026-10-20 抓取的官方页面；"设计判断"是本项目结合现状给出的意见；"待核实"表示未取得一手资料。

## 0. 结论先行

1. 你现在的静态站不是要废弃的旧版，它是**唯一已经成熟的东西**：36 门课程目录、14 门真实数据、4 个数据守门员脚本。新系统应该长在它上面，而不是另起一个仓库。
2. 首发两个模块选得对，但**顺序要微调**：知识库问答的前提是"教材已经切片且能溯源到页码"，作业批改的前提是"题目已有稳定 ID 和知识点关联"。前者你还没有（教材未入库），后者你已经有 4807 题的现成资产。所以真正的第 0 步是**教材入库与切片**，不是写问答界面。
3. 数学学科有两个别人不会替你解决的硬骨头：**公式保真**（PDF→结构化）和**符号等价判定**（批改）。这两件事决定产品质量上限，建议在 S1 阶段就用最小样例验证，不要等做到一半才发现。
4. 不要做"全自动批改给正式成绩"。国内外所有成熟产品的共同做法都是 **AI 初评 + 教师确认**。证明题不要自动打分。

## 1. 对标调研

### 1.1 已核实的四个参照（2026-10-20 官方页面）

| 平台 | 官方定位（原文要点） | 值得借鉴 | 不能照搬 |
| --- | --- | --- | --- |
| **Khanmigo**（Khan Academy） | "always-available teaching assistant"；明确"doesn't just give answers，guides learners to find the answer themselves"；教师侧有 rubric 生成等工具；覆盖 K-12 到大学 | **不直接给答案**的产品原则；内容库与 AI 强绑定；教师工具与学生学习助手分开设计 | 它背后是 Khan 自建的海量内容库，你没有；它的商业模式是订阅制 |
| **Gradescope**（Turnitin 系） | 官方称 700M+ 题已批改、2600+ 高校、140k 教师；支持变长作业与固定模板作业（练习、测验、答题卡、考试） | **批改工作流**比"AI 打分"更值钱：答案分组、rubric、逐题分析、教师批量确认 | 它主要解决"批改效率"，不解决"教与学"；数学主观题深度有限 |
| **Class Companion** | 即时反馈 + AI 导师 + 无限重试；可自定义 rubric；LMS 同步（Canvas/Schoology/Google Classroom）；有作答诚信检测（粘贴、切屏、打字异常）；有学习洞察 | **无限重试 + rubric 对齐**；诚信信号作为产品功能而非道德要求；洞察页面向教师 | 它强在人文社科短答/作文，数学自动判定能力弱 |
| **MATHia**（Carnegie Learning） | "1-to-1 math coach"；按 **skill-by-skill** 粒度自适应；given just-in-time 的上下文提示；进度条与 Session/Skills/Student Detail/Standards 报表 | **技能级掌握度**与进度可视化；提示的粒度是"下一步该想什么"而不是"答案是什么" | 它是 6-12 年级，认知模型是人工建的（cognitive tutor），成本极高，不要试图复刻 |

**跨产品共性（这是最有价值的部分）**：

- AI 不直接给答案，给"下一步提示"——这是教育产品与通用聊天机器人的分界线。
- 批改产品卖的不是准确率，是**教师工作流的节省**（分组、批量确认、申诉处理）。
- 所有产品都做了**引用/来源**或 rubric 绑定，否则教师不信任。
- 所有产品都有 LMS/班级同步，否则数据孤岛。

### 1.2 国内生态（待核实，仅作方向参考）

以下为公开常识性归纳，**未取得一手页面验证**，具体能力请以厂商演示为准：讯飞（星火 + 智慧课堂/智学网，强在扫描阅卷与校本资源）、超星学习通（强在教材数字化与课程资源库）、雨课堂/学堂在线（强在课堂互动与教学过程数据）、好未来九章大模型 MathGPT（强在数学解题）、作业帮（强在题库与拍照搜题）。

**给你的判断**：国内厂商的护城河是**题库规模 + 扫描阅卷硬件 + 校本资源**。你不可能在题库规模上竞争，但你有两件他们没有的东西——**本院教材的原文**和**本院教师的教学意图**。所以产品定位必须写成"**基于本院教材的、可溯源的**教学智能体"，而不是"又一个题库/搜题产品"。

## 2. 需要开发的功能与模块

按"数据层 / 能力层 / 应用层 / 平台层"四层划分，标注优先级。P0 = 首发两模块必需；P1 = 一年内；P2 = 观察。

### 2.1 数据层（这是你真正的壁垒，也是当前最大缺口）

| 模块 | 内容 | 优先级 | 现状 |
| --- | --- | --- | --- |
| **教材库** | 教材元数据（书名/版次/ISBN/编者/版权状态）、PDF 原件、页码基准、来源 SHA-256 | P0 | **缺失** |
| **切片管线** | PDF→结构化文本，公式保真转 LaTeX，保留"页-段-公式"锚点 | P0 | **缺失** |
| **知识点库** | 层级知识点 + 稳定 ID + 教材页码锚点 | P0 | 有（14 门 4146 个），但**没有教材页码锚点** |
| **题库** | 题目、答案、难度、来源、变体 | P0 | 有（4807 题），但 1097 题的出处文字仍写"待核" |
| **知识点-题目关联** | 题↔知识点多对多 | P0 | 有（5287 条） |
| **知识点-教材锚点** | 每个知识点对应教材哪一页哪一段 | **P0（新增）** | **缺失，问答可溯源的命门** |
| **向量库** | chunk 级向量，metadata 带 courseId/nodeId/页码/教材版本 | P0 | 缺失 |
| **审核状态机** | draft → 机器校验 → 教师审核 → 已发布，每次变更留痕 | P0 | 只有课程级"待教师审核"，无题目级 |

> 关键设计判断：**"知识点-教材锚点"是整个系统的地基**。没有它，问答只能给出"模型觉得对"的答案；有了它，才能给出"第 3 章第 2 节，教材第 78 页"的可核查答案。这一列必须在 S1 建库时就设计进去，后期补要重跑全量切片。

### 2.2 能力层

| 模块 | 内容 | 优先级 |
| --- | --- | --- |
| **检索（RAG）** | 混合检索（BM25 + 向量）+ 重排；公式双通道（LaTeX 文本 + 语义描述） | P0 |
| **生成与引用** | 回答必须挂 `nodeId + 页码 + 原文片段`；无检索结果时明确拒答 | P0 |
| **符号等价判定** | SymPy/CAS 判定数值、表达式、矩阵等价；不消耗 token | P0（批改客观题的核心） |
| **主观题评分** | rubric 驱动的分步评分，输出"扣分点"而非总分 | P1 |
| **手写/拍照识别** | 数学 OCR（公式 + 手写） | P2（先做电子输入） |
| **掌握度模型** | 知识点级掌握度、错因归类、复习队列 | P1 |
| **题目生成** | 基于知识点与例题生成变式题，需教师审核后入库 | P2 |

## 3. 首发模块一：知识库问答

### 3.1 最小可用闭环（建议 3–4 周，单课程试点）

```
教材 PDF → 切片(保公式) → chunk(带页码/节点锚点) → 向量化
   → 用户提问 → 混合检索 top-k → 重排 → 拼 prompt(限定只依据检索结果)
   → 生成回答 + 强制引用 → 前端渲染 KaTeX + 可点击引用 → 跳转知识点/教材页
```

### 3.2 四个决定成败的细节

1. **切片不能按固定字数切**。数学教材的一个定理包含"条件—结论—证明"，按 512 token 切会把条件切到上一块，导致检索到的片段"看起来相关但缺前提"。建议**按知识点边界切，块内保留定理编号与上下文标题**。
2. **公式检索**。`$\int_0^1 f(x)dx$` 在向量空间里几乎不可检索。做法：每个公式块同时存 LaTeX 原文与一句自然语言释义（可用模型批量生成，但要人工抽检），检索走自然语言，回答里回填 LaTeX。
3. **引用必须可点击且能验证**。引用不是装饰，是这套系统唯一能对抗幻觉的机制。格式统一为"《教材名》第 X 页 · 第 N 节 · 知识点 ID"。
4. **拒答要显式**。检索 top-1 分数低于阈值时，回答"教材本章未涉及该问题"，并给出最接近的 3 个知识点。**宁可拒答也不要编**——数学场景编一个错误定理的代价远高于"没答上"。

### 3.3 验收标准（先定标准，再开发）

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| Top-5 检索命中率 | ≥ 90% | 教师出 50 道有明确教材出处的问题 |
| 引用正确率 | ≥ 95% | 人工核对引用页是否真的包含该结论 |
| 教师"可直接采用"率 | ≥ 70% | 50 条回答盲评 |
| 拒答准确率 | 无检索依据时 100% 拒答 | 20 道教材外问题（如其他课程内容） |

## 4. 首发模块二：作业批改

### 4.1 分三档，不要混在一起做

| 档 | 题型 | 判定方式 | 是否调模型 | 可否自动给分 |
| --- | --- | --- | --- | --- |
| A | 选择、判断、数值填空、表达式化简 | **CAS 符号等价判定**（SymPy） | 否 | 可以 |
| B | 计算题（有过程） | rubric + 模型分步判定 | 是 | 仅给建议，教师确认 |
| C | 证明题、开放题 | 只做"步骤识别 + 疑点标记" | 是 | **不可以** |

**A 档是你应该最先做的**，因为它不花 token、准确率接近 100%、且能立刻省掉教师最多的机械劳动。用 CAS 判定 `1/2` 与 `0.5` 等价、`sin^2x+cos^2x` 与 `1` 等价、`[[1,2],[3,4]]` 与转置后的矩阵不等价——这些都是确定性问题，不需要语言模型。

### 4.2 教师复核台是产品的一部分，不是附属功能

对标 Gradescope 的"答案分组"：AI 把 100 份作业按错误类型聚成 6 组，教师对每组确认一次，而不是逐份看 100 次。**这才是节省时间的来源**。没有复核台的 AI 批改是负资产——教师不敢用、用了要重判、出错没人担责。

### 4.3 验收标准

| 指标 | 目标 |
| --- | --- |
| A 档判定一致率 | ≥ 99.9%（与教师人工判分对比） |
| B 档与教师评分加权 Kappa | ≥ 0.8 才允许上线，0.6–0.8 只做建议 |
| 教师复核耗时 | 比纯人工下降 ≥ 50% |
| 错判可追溯 | 每次 AI 判分记录 model/prompt 版本 + 检索依据 |

## 5. 与现有仓库的接续

### 5.1 目标布局（monorepo，不动现有目录）

```
web/        ← 现有静态站整体迁入（先保留，逐页接后端）
server/     ← 新增：API 服务
pipeline/   ← 新增：教材切片、向量化、知识点对齐
db/         ← 新增：schema + 迁移
scripts/    ← 现有守门员脚本保留
course-packs/  data/  courseware/   ← 现有资产原地保留
```

### 5.2 三条"不要重做"的现有资产

1. **`data/` 的 schema 直接映射成 DB 表**：`course / node / exercise / relationship` 四张表 + 关联表。现有 12 字段节点、6 字段题目已经够用，只需新增 `reviewStatus`、`contentVersion`、`sourcePage` 三个字段。
2. **`config/api-contract.json` 的 23 个端点就是后端 API 的起点**。它已经定义了 `/courses/{id}/knowledge`、`/ai/chat`（含 citations 结构）、`/classes/{id}/assignments` 等。照它实现，前端不用返工。
3. **`npm run check` 的四道守门员保留**，作为"数据入库前"的 gate。数据一旦进 DB，这个逐字节校验能力就没了——所以入库前必须过。

### 5.3 分支策略

`main` 永远可演示（这是给学院汇报的资产）。每个能力切片一个短分支，合回 main：

```
feat/s1-textbook-pipeline   → 教材入库+切片（离线跑通，先不接前端）
feat/s2-kb-qa-api           → 问答后端 + 向量检索
feat/s2-kb-qa-ui            → 前端接入，带引用与跳转
feat/s3-grading-cas         → A 档客观题判定 + 提交回显
feat/s4-grading-rubric      → B 档 + 教师复核台
```

不建 `develop`。理由是单人开发 + 数据是生成物（6.4MB 单行 `courses.js`），长分支合并必然冲突。

## 6. 建议的推进顺序

| 阶段 | 内容 | 周期 | 可演示的成果 |
| --- | --- | --- | --- |
| **S0** | 仓库整理：CI、tag v0.11.0、清理测试残留 | 1 天 | "第一版已归档" |
| **S1** | 教材入库 + 切片管线 + 知识点页码锚点（**单课程试点**） | 2–3 周 | 打开一门课，每个知识点能跳到教材对应页 |
| **S2** | 问答：检索 + 生成 + 引用 + 拒答 | 3–4 周 | 学生问教材内容，答出来且能点开原文 |
| **S3** | 批改 A 档：CAS 判定 + 班級提交 | 2 周 | 教师上传答案，客观题秒判 |
| **S4** | 批改 B 档 + 教师复核台 | 3–4 周 | 教师改 6 组而不是 100 份 |
| **S5** | 学情看板、复习队列 | 后续 | |

**强烈建议 S1 只做一门课**（推荐《数学分析 I》——知识点结构最清晰、公式最多、最能暴露切片问题）。一门课走通再复制，不要 14 门一起上。

## 7. 风险清单

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| **教材版权** | PDF 上传到服务器供检索，属于数字化复制；若系统对外开放则有传播风险 | 系统限校内 IP/账号；向量库不导出；检索结果只回片段不回全文 |
| **模型成本** | 批改 4807 题 × 每次调用，若全走大模型会烧钱 | A 档用 CAS（零成本）；B 档批处理 + 缓存 + 小模型先判、大模型仅处理争议 |
| **幻觉** | 数学问答编造定理会误导学生 | 强制引用 + 拒答阈值 + 教师可标记错误并回灌 |
| **切片质量** | 公式 OCR 出错会污染整个知识库 | 切片后必须有人工抽检环节（建议 10%），错误率高则换工具 |
| **单人维护** | 你一个人 + AI 代理，同时要保演示、做后端、做数据 | 严格按切片推进，每个切片可停可演示；基础设施（CI、部署）先做 |
| **审核责任** | AI 判分若直接进成绩，出了错是学院的责任 | AI 只出建议，教师确认才生效；全程留痕 |

## 8. 三个需要你决策的问题

1. **试点课程选哪门？** 建议《数学分析 I》，但需你确认教师配合度。
2. **教材是否已有可用的结构化文件？** 若出版社提供 XML/Word 版，切片成本下降一个数量级；若只有扫描 PDF，必须先解决公式 OCR。
3. **批改的边界**：A 档（客观题）是否本期就上线给分，还是先只做"练习自测"不进成绩？后者政治风险低得多。
