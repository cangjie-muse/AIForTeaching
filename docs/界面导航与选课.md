# 界面导航与选课

这一页记录一条交互规则，以及为了让这条规则成立而改掉的东西。

## 规则：课程范围的功能，必须先有课程上下文

「知识图谱」「习题与测验」「课程大纲」「AI 助手」「课程资源」「教学工作台」「课件生成」
「建设与学习分析」——这八个入口都属于**某一门课**。没有课程上下文时，它们不该自己猜一门课。

改之前的行为：侧边栏用 `A.course?.id || A.featuredCourse()?.id` 拼链接，于是没打开任何课程时，
点「知识图谱」直接进入辛几何那门示范课。用户的第一反应是"我还没选课，平台怎么替我选了"，
第二反应是"我是不是进错课了"。这不是样式问题，是导航在替用户做决定。

## 三种路由

| 形态 | 例子 | 含义 |
| --- | --- | --- |
| 一级页 | `#/catalog`、`#/study`、`#/content`、`#/review` | 不依赖课程 |
| 课程页 | `#/course/analysis-ii/graph` | 深链，直接进入指定课程的功能 |
| 选课页 | `#/pick/graph` | 先选课程，再进入 `graph` 功能 |

`A.url(page, null)` 对课程页返回 `#/pick/<page>`，对一级页返回 `#/<page>`。
侧边栏不再传默认课程：`A.course?.id || null`。

选课页告诉用户"选完会去哪"：标题、说明、按钮文案随入口变化（知识图谱是"查看图谱"，
习题是"开始练习"，并说明作答后才展开完整解答）。

## 选课页的三层信息

1. **已接入课程**：直接列出，带「N 章 · N 个知识点 · N 道习题」和进入按钮。
2. **待接入课程**：收进 `<details>`（"还有 34 门课程待接入"）。要看得见，但不能把能用的课埋掉。
   待接入的卡不提供假入口——链到课程概览（那里有建设状态），标签写"查看状态"。
3. **上次浏览**：记住上次打开的课程，给一个「继续这门课」。**只提示，不自动跳**：
   选课是用户的动作。

搜索框按课程名、描述、别名过滤；回车直接进第一张可见卡片（已接入的排在前面，所以命中即能用）。

## 老书签兜底

`#/graph`、`#/exercises` 这类没有课程 id 的旧链接，`A.normalizeRoute()` 会转成
`#/pick/graph`、`#/pick/exercises`，不报错也不猜课。`#/course/<id>/<page>` 保持原样。

面包屑说清楚顺序：`课程平台 › 知识图谱 › 选择课程`——先说要去哪个功能，再说还没选课程。

## 当前课程条：进了课就要知道自己在哪

选课页解决了"进来之前"，但进来之后还有第二个问题：**我在哪门课里？** 只靠面包屑不够
（太细、一滚就没），只靠侧边栏高亮也不够（菜单高亮说明的是"在哪一页"，不是"哪门课"）。

所以主内容区顶部加了一条常驻的当前课程条：

```
[网格] 课程中心 / 数学分析II   10 章 · 90 个知识点 · 349 道习题   概览 大纲 图谱 习题 资源   [换课程]
```

- 左边是"从哪来"：`课程中心` 是回课程列表的正路，点课程名回本课概览；
- 规模写清楚，扫一眼就知道这门课有没有内容；
- 本课五个常用页并排，当前页高亮；
- 「换课程」回到 `#/pick/<当前页>`——**换课不丢功能**：从习题页换课，换完还是习题页。

课程条只在有 `A.course` 时出现（选课页、课程中心没有），待接入课程显示"内容待接入"。

### 吸顶

课程条和顶栏一起吸顶：顶栏 `position:sticky; top:0; z-index:30`，课程条
`top:76px; z-index:25`。三个数是一组约定，改一个就得改另外两个：

- 顶栏在上面一层（30 > 25），否则课程条滚动时会盖住菜单按钮；
- `top` 必须等于顶栏高度。桌面 76px，≤720px 时顶栏变 64px，课程条跟着变 64px——
  写死 76px 的手机端会露出 12px 的缝，滚动时内容从缝里穿过去；
- 手机端课程条改成**单行横向滚动**（隐藏规模文字、链接不换行）。两行吸顶会吃掉
  近 1/5 屏，划两下就看不见内容了。

`scripts/test-nav-shell.cjs` 把这组约定钉住了：顶栏 sticky/z-index、课程条 top 与 z-index、
手机端 64px 偏移、单行滚动。少一条就报红——这类问题靠人工滚动才发现，太晚。

## 菜单形状固定

以前「课程概览」「课程大纲」只在打开课程时才出现在侧边栏，其余时候消失。菜单忽隐忽现，
用户会以为进了两套系统。现在课程相关的十项**一直都在**：有课程时带课程 id，没有时指向
`#/pick/<page>`。菜单位置不变，只变链接目标。

## 换课再换回来：接着上次看，而不是重开

`App.courseMemory(courseId)` 存每门课在会话内的"上次看到哪儿"：

| 页面 | 记住什么 |
| --- | --- |
| 知识图谱 | 展开的层级、图谱/表格模式、共用习题开关 |
| 习题与测验 | 搜索词、章节筛选、难度筛选、页码 |

所以"在课程甲展开第二章 → 换到课程乙 → 再换回甲"仍然是第二章。

三个刻意的边界：

- **只存内存，不落 localStorage**：刷新页面回到默认视图。跨天残留一个"上次停在第三章"
  更容易让人困惑；
- **按课程 id 分开存**：课程乙不会继承甲的筛选条件；
- **失效记忆就地纠正**：内容重新发布后旧章节 id 可能不存在，此时退到"全课程视图"
  并改写记忆，而不是白屏或指向一个空节点。

## 会话内的课程是"跟着走"的

在数学分析 II 里点「习题」，仍然是数学分析 II 的习题（侧边栏带当前课程 id）。
换课程有两条路：课程条上的「换课程」（走选课页，保留当前功能），或课程条左边的
「课程中心」（回列表重新挑）。这条是有意的——在同一门课里换功能不该被打断。

`localStorage['whu-math-last-course']` 只用于选课页的「上次浏览」，不参与路由判断。

## 测试

- `scripts/test-view-pick.cjs`（54 项）：链接规则（有/无课程）、三种路由解析、
  老书签收敛、选课页文案与卡片、待接入不给假入口、上次浏览不自动跳、课程条内容与高亮。
- `scripts/test-render-shell.cjs`（19 项）：真的跑一遍 `A.render()`，检查外壳 HTML——
  菜单形状固定、未选课程时指向选课页、进课后课程条出现且「换课程」回选课页。
  外壳藏在 `app.js` 里，视图测试碰不到，而它恰恰最容易悄悄坏。
- `scripts/test-nav-shell.cjs`（26 项）：样式契约——吸顶的三个数、手机端偏移、
  课程中心回链、以及"记忆只进内存"这条否定规则。
- `scripts/test-view-graph.cjs`（12 项）：图谱层级/模式/开关按课程记忆，
  换课再换回不重开，失效章节退到全课程。

`npm run check`（235 项）与 `npm run test:view`（312 项）全绿。

## 还没做

- **多标签页不同课程**：每个标签页各自持路由，互不干扰（这算合理，不是缺陷）。
- **选课页没有键盘方向键导航**：目前是搜索 + 回车 + Tab。
- **课程中心与选课页是两套卡片样式**：课程中心是封面卡（发现课程），选课页是紧凑列表
  （快速进入）。没有合并成一套，因为目的不同。
