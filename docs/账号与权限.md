# 账号与权限

平台的身份分三种：**学生 / 教师 / 管理员**。没有第四种。历史上代码里出现过 `reviewer`
（审核员），现在它是 `teacher` 的别名——`require("reviewer")` 对教师放行，这样老接口
不用逐个改，权限语义也不会分裂成两套。

## 一、谁能看到什么

| 页面 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 课程中心 / 课程概览 / 教学大纲 | ✓ | ✓ | ✓ |
| 知识图谱 / 习题 / 学伴问答 / 作答 | ✓ | ✓ | ✓ |
| 教学工作台 / 课件 / 资源 / 学习分析 | — | ✓ | ✓ |
| 课程内容编辑 | — | ✓ | ✓ |
| 内容审核（习题审核、图谱审核） | — | ✓ | ✓ |
| 学生可见范围（系统管理 → 学生可见范围） | — | ✓ | ✓ |
| 班级与选课（建班、加/移学生、看名单） | — | ✓ | ✓ |
| 建设进程 | — | ✓ | ✓ |
| 账号管理 | — | — | ✓ |
| 模型接口配置 | — | — | ✓ |

- **前端**（`js/auth.js` 的 `PAGE_ROLES`）：没权限的菜单项不渲染；直接输 URL 也只会
  看到一句"当前身份没有这个页面的权限"。
- **后端**（`server/app/auth.py` 的 `require()`）：这才是权威。没登录返回 **401**
  （前端据此跳登录页），登录了但角色不够返回 **403**。

前端藏菜单只是不让老师点进 403，不代表安全边界。任何新接口都必须自己声明 `require(...)`。

### 分工：管理员管人和账号，教师管课程和班级

| 角色 | 负责 |
|---|---|
| 管理员 | 发账号（学生 / 教师 / 管理员）、改角色、停用、重置密码、配模型接口 |
| 教师 | 建设课程内容、内容审核、建教学班、把学生加进自己的课程班 |
| 学生 | 选课学习、作答、问答；**没有**建班、加人、改角色、看别人名单的权限 |

这套分工是"账号由教务处发、课程由教师建"的落地：教师不需要（也拿不到）建账号的权限，
学生永远看不到别人班的名单。细节见[班级与选课.md](班级与选课.md)。

## 二、登录方式

### 账号密码（已可用）

1. 管理员在「账号管理」页建账号，设初始密码（≥ 8 位）。
2. 被建的人用账号 + 密码登录，顶栏显示姓名与角色，点「改密」可改。
3. 连续 5 次密码错误锁定 10 分钟（`AUTH_LOCK_AFTER` / `AUTH_LOCK_MINUTES`）。
4. 默认会话 12 小时（`SESSION_TTL_HOURS`），改密后其它设备上的会话立即失效。

密码只以 PBKDF2-HMAC-SHA256 哈希落库（`pbkdf2_sha256$迭代次数$盐$哈希`），
原文不保存、不打日志。会话令牌同样只存 sha256，cookie 是 `httpOnly` + `SameSite=Lax`，
`APP_ENV=prod` 时自动加 `Secure`。

### 学校统一身份认证（留好口，未接入）

登录页上的「学校统一身份认证」按钮现在是**置灰**的，鼠标悬停显示"待接入"。
点它会提示去看这份文档，而不是假装登录成功。

接入要动的地方只有两处：

1. `server/app/auth.py` 的 `cas_login_url(service)`：拼学校 CAS 登录地址
   （一般是 `https://cas.whu.edu.cn/cas/login?service=<回调地址>`），并把
   `CAS_AVAILABLE` 改成 `True`。
2. `server/app/accounts.py` 的 `cas_callback()`：拿 `ticket` 调学校的
   `serviceValidate`，确认成功后得到学号/工号，然后：
   - 按学号/工号在 `app_account` 里找账号；没有就按默认角色 `student` 建一个
     （教师白名单可做成配置，避免学生自己猜出教师权限）；
   - 调 `auth.issue_session(account_id, request)` 写 cookie；
   - `RedirectResponse` 回原来要去的页面。
3. 设 `AUTH_MODE=cas`，重启后端。

`app_account.password_hash` 允许为空：这样的人只能走统一认证，不能密码登录
（账号管理页会显示"仅统一认证"）。这比给他一个假密码安全。

## 三、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `AUTH_MODE` | `dev` | `dev` / `password` / `cas`。生产必须是后两个，`APP_ENV=prod` 时 `dev` 会直接拒绝启动 |
| `AUTH_DEV_ROLES` | 空 | dev 模式下"没有请求头时"的兜底角色。**默认为空 = 本地也必须登录** |
| `SESSION_TTL_HOURS` | `12` | 会话有效期 |
| `AUTH_LOCK_AFTER` | `5` | 连续失败几次锁定 |
| `AUTH_LOCK_MINUTES` | `10` | 锁定多少分钟 |
| `PASSWORD_MIN_LENGTH` | `8` | 最短密码长度 |
| `COOKIE_SECURE` | `APP_ENV=prod` 时为 1 | 是否只在 HTTPS 下发送 cookie |

`dev` 模式下仍然接受 `X-Actor` / `X-Roles` 请求头（端到端测试与 curl 靠它），
但**只有显式打开"用请求头冒充身份"**（模型接口配置页里的开关，或
`App.local.devActor = true`）前端才会发这两个头。默认不发——否则"没登录也是管理员"，
登录按钮就成了装饰。

`scripts/dev_seed_accounts.py` 会在 `npm run dev:api` 启动时写入三个账号（已存在则不覆盖）：

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `whu-admin-2026` | 管理员 |
| `teacher` | `whu-teacher-2026` | 教师 |
| `student` | `whu-student-2026` | 学生 |

这些口令只用于本地演示，**上线前必须改掉，并把 `AUTH_DEV_ROLES` 保持为空**。
生产建账号走管理员界面，不要跑这个脚本。

## 五、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/auth/providers` | 登录页用：有哪些登录方式、CAS 是否可用 |
| GET | `/api/v1/auth/me` | 当前身份（未登录也返回 200，`authenticated: false`） |
| POST | `/api/v1/auth/login` | 账号密码登录，写会话 cookie |
| POST | `/api/v1/auth/logout` | 退出并吊销会话 |
| POST | `/api/v1/auth/password` | 改自己的密码（需登录） |
| GET | `/api/v1/auth/accounts` | 账号列表（仅管理员，可按 `role` / `query` 筛） |
| POST | `/api/v1/auth/accounts` | 建账号（仅管理员） |
| PATCH | `/api/v1/auth/accounts/{id}` | 改姓名/角色/密码/停用（仅管理员） |
| GET | `/api/v1/auth/cas/login` | 统一认证入口，当前返回 501 |
| GET | `/api/v1/auth/cas/callback` | 统一认证回调，当前返回 501 |

管理员不能把**最后一个管理员**降级或停用——否则平台再也没人能管账号；
也不能停用自己的账号。

## 六、为什么"停用"而不是"删除"

学生的作答记录、审核记录都挂在账号 id 上。删人会让历史数据悬空，
而且"这个学生上学期的记录去哪了"这类问题会变成事故。停用会立刻吊销会话、
登录返回 403，但数据保留。

## 七、测试

```bash
node scripts/e2e-api.cjs            # 含 50 项登录/权限检查（含锁定、改密、越权）
node server/tests/test_auth.py      # 哈希、令牌、角色蕴含、匿名判定（36 项）
node scripts/test-view-auth.cjs     # 登录页、菜单闸门、账号管理页（41 项）
```

端到端里专门验了几件容易糊过去的事：

- 退出后访问受保护接口是 401 而不是 403（前端才能区分"去登录"和"你没权限"）；
- 教师能用 cookie 读审核总表（不需要请求头）；
- 学生读审核队列/改可见范围/看账号列表都是 403，打开 `#/visibility` 也只会看到「没有这个页面的权限」；
- 连续 5 次失败锁定后，**正确的密码也进不去**；
- 改密后旧密码立刻失效；
- 最后一个管理员不能被降级。
