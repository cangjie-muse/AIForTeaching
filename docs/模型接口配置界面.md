# 模型接口配置界面

页面：`#/api-config`（侧栏「系统管理 → 模型接口配置」）
代码：`js/api-config.js`、`styles/admin.css`、`server/app/admin.py`

## 1. 权限：管理员可写，审核员只读

| 角色 | 查看端点列表 | 新增/修改/启停 | 配置密钥 | 自检 |
| --- | --- | --- | --- | --- |
| `admin` | ✅ | ✅ | ✅ | ✅ |
| `reviewer` | ✅ | ❌ 403 | ❌ 403 | ❌ 403 |
| `teacher` | ✅ | ❌ 403 | ❌ 403 | ❌ 403 |
| `student` | ❌ 403 | ❌ 403 | ❌ 403 | ❌ 403 |

为什么让审核员只能看：审核员需要知道"现在用的是哪个模型、这个模型出不出校"，
这影响他对答案可靠性的判断；但改配置属于运维动作，不该由审核流程里的人顺手做。

**前端置灰不是安全边界。** 每个写接口都有 `Depends(require("admin"))`。
前端根据 `/api/v1/admin/whoami` 返回的 `can_edit` 决定按钮是否可点，只是为了
避免"点下去才报 403"的挫败感。

开发期可用页面上的「预览角色」切换 admin / reviewer / student，验证只读分支。
生产环境（`AUTH_MODE=cas`）该切换器不出现。

## 2. 密钥：不入库、不回显、不进日志

这是这个页面唯一的硬设计：

```
浏览器 ──(POST api_key)──> 服务端 ──> secrets/<name>.key  (0600)
                                        │
                                   库里只存 api_key_path
浏览器 <──(key_configured: true)────────┘
```

三个原因：

1. **数据库备份会带走密钥。** 备份、只读副本、讲师临时取的 dump 都不该含密钥。
2. **前端拿到过一次，就等于永久泄露。** 浏览器缓存、开发者工具、截屏、日志，
   任何一处都可能留下它。所以接口只返回 `key_configured` 布尔值。
3. **依赖数据库扩展会让"本地能跑、服务器不能跑"。** 加密入库要么用 `pgcrypto`，
   要么自己实现加密。前者在测试用的 PGlite 上要额外加载扩展（能加载，但多一层前提），
   后者等于手写密码学——对一个教学平台不值得。

代价要写清楚：**密钥和数据库不在同一个备份里。迁移服务器时必须单独搬 `secrets/` 目录**，
否则新机器上所有端点都会显示"未配置"。

## 3. 三条界面不允许改的规则

| 规则 | 在哪拦 | 为什么 |
| --- | --- | --- |
| 向量维度只能是 1024 | 前端 + 后端双重校验 | 库里是 `vector(1024)`，改维度要重建整列并重算全库向量 |
| 出校端点必须写说明 | 数据库 `CHECK` + 后端预检 | 审计问"为什么教材内容会出现在这家公司服务器上"，说明字段就是答案 |
| 同类只能启用一个 | 数据库唯一索引 → 409 | 避免"到底在用哪个模型"说不清 |

还有一条更隐蔽的：**数据范围必须与地址一致**。标成「校内」却填着
`api.deepseek.com`，保存会被拒绝。这种配置错误不会报任何异常，只会让
"这条数据到底出没出校"永远说不清——所以宁可不让它存进去。

## 4. 一次配置流程

1. 新增端点：填名称、用途、地址、模型、数据范围
2. 保存密钥（对话框，输入框是密码类型，保存后不再显示）
3. 点「自检」：真的发一次最小请求（对话发 `ping`，向量发一条文本并核对维度）
4. 点「启用」：停用旧端点、启用新端点
5. 上线后看 `/api/v1/health` 里的 `models` 字段确认实际生效的端点

自检失败会记录 `last_test_note`（截断 300 字）并显示在列表里。
**自检同样要走允许清单**——不能借"测试"这个入口绕过供应商检查。

## 5. 已知缺口

- 本机没有 FastAPI / psycopg / PostgreSQL，`server/app/admin.py` 只做了语法编译与
  纯逻辑测试，**没有对真实数据库跑过接口**。首次部署时要先跑一遍增删改查。
- 前端渲染有冒烟测试（`npm run test:view`，14 项），但没有真实浏览器交互测试。
- 密钥文件在 Windows 上 `chmod 600` 语义有限，生产部署在 Linux 才能严格执行权限。
