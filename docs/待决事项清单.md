# 待决事项清单

用途：把"需要学院/你决定"的事集中在一处，避免散落在对话里丢失。
更新方式：每定一项就改状态，并记到文末的决定记录表。

状态：`待定` / `已定` / `暂缓`

## A. 必须你或学院拍板（不定就会返工）

### A1. 部署在哪里　`已定：校内部署，模型走 API`

| 选项 | 好处 | 代价 |
| --- | --- | --- |
| **学院自建服务器**（已选） | 数据在自己手里，可控 | 要有人运维；但模型走 API，不需要 GPU |
| 学校统一云/信息中心 | 合规最省事，有备份 | 审批流程长，资源申请要排队 |
| 公有云（阿里云/腾讯云） | 开通快，弹性 | 长期费用；数据放在校外机房 |

**已定**：一期放学院自建服务器，模型全部走国内 API，**不需要显卡**。服务器只需 4–8 核、16 GB 内存、200 GB SSD。
**剩下要办的**：采购、域名、公网映射（或学院已有的对外发布通道）。

### A2. 数据能不能出校园网　`已定：可以出校，用国内 API`

具体是三个问题，答案可以不一样（已定的部分）：

1. 教材 PDF 与切片 → **可以**传给国内模型厂商
2. 学生提问内容 → **可以**（但建议不把姓名学号放进提示词）
3. 学生对话记录 → 可存第三方；建议**对话记录仍存校内数据库**，只把请求发出去

**已定**：使用国内大模型 API。仍未定的只剩一条：**教材版权**——数据能出校，不等于有权把受版权保护的教材内容交给第三方，这个要问出版社或教务处（见 D 表）。
**不定会怎样**：技术选型整个反转。
**建议**：教材正文和题干可以出校；**学生姓名、学号不要放进提示词**，对话记录仍存校内数据库。这样既拿到 API 的效果，又不需要额外做个人信息出境的说明。

### A3. 一期做哪几本教材　`已定：数学分析 I + II`

**已定（2026-10-21）**：一期上线**数学分析 I 与 II 两门**，共 765 道题
（I 416 道 / II 349 道）。理由：核心基础课，题目量在人工审核能覆盖的范围内，
又足以暴露多课程并行时的问题（重名、跨课挂载、共享习题边）。

**仍然缺的输入**：这两门课的教材版本信息。现有 14 门课的数据里，
只有"辛几何与数学物理"登记了教材（Arnold 英文第 2 版），其余 13 门
`textbook` 字段为空——这正是 809 条 `source-missing` 的来源。
需要你补：书名、版次、作者、有无电子版 PDF、扫描件还是文字版。

**为什么必须你定**：直接决定切片工作量。文字版一本约两周，扫描件（要 OCR + 公式校对）约两个月。
**不定会怎样**：做到一半发现教材是扫描件，工期翻倍。
**建议**：一期只做**数学分析 I**，且优先选有文字层的版本。做完一本再复制经验。

### A4. 身份认证怎么做　`部分已定：本地账号已可用，统一认证仍是口子`

| 选项 | 说明 |
| --- | --- |
| 接学校统一身份认证（CAS / OAuth2） | 学生不用另设密码，最正规；要与信息中心对接 |
| 先做本地账号 | 自己能做主，但学生要单独注册，且无法与教务数据打通 |

**为什么必须你定**：不接统一认证，学生身份就是"用户自己说了算"，成绩、作业、学伴记忆都不可信。
**不定会怎样**：用本地账号上线，后面换统一认证要迁移所有账号与数据。
**建议期限**：**现在就去问信息中心**。流程比代码慢得多，这是整个项目最长的前置依赖。
**我的建议**：一期用统一认证；如果流程走不完，先用"教师账号 + 临时学生码"过渡，但数据结构必须按统一认证设计（现在已经是）。

**已做（2026-10-21）**：三种角色（学生/教师/管理员）、账号密码登录、会话与锁定、
账号管理页都已可用；统一认证的入口与回调位置留好但**明确未接入**（返回 501，
登录页按钮置灰）。也就是说"先做本地账号"这条已经落地，数据表按统一认证设计
（`app_account` 以学号/工号为用户名，`password_hash` 可为空 = 只能走统一认证）。
还在你手上的只有一件事：**去问信息中心 CAS 的接口与对接时间**，拿到后按
`docs/账号与权限.md` 里的两个函数填即可。

### A5. 问答的教学口径　`已定：分层——先引导，作答后才给完整解答`

**已定（2026-10-21）**：默认**引导式**——只给思路、拆解、反问，不给完整解答；
学生先提交自己的作答，之后才解锁完整解答。这条同时解决了"防抄答案"和
"卡住的学生走不出来"两个问题。

落进代码的三件事：
1. 提问接口要带 `mode`（`guide` / `full`），`full` 需要先有作答记录，否则 403；
2. 作答记录必须落库（表：`student_attempt`），它同时是"因材施教"的数据来源；
3. 提示词分两套，`guide` 那套禁止出现最终答案与完整推导。

下面三个问题仍需要教师确认（不阻塞开发，先按上面的默认做）：

1. **学生问作业题，AI 该直接给答案，还是只给提示？**
2. **作业期间要不要禁用 AI 学伴？**
3. **学生问"我算的对不对"，允许它指出错误，还是只给判断不给过程？**

**为什么必须你定**：这是教学法与学术诚信问题，不是技术问题。做错了学生会骂，教师会反对。
**不定会怎样**：上线后被教师质疑"鼓励抄作业"，整个项目停摆。
**建议**：默认**给提示不给完整答案**，作业截止前 72 小时对已发布作业禁用问答；这两个开关做成配置项，教师可按课程调整。

## B. 我已按默认值推进，你不反对就保持

以下都已落进代码与文档，改起来不难，但改了要动数据：

| 事项 | 当前默认 | 影响 |
| --- | --- | --- |
| embedding 模型与维度 | BGE-M3 / 1024 维 | 改了要全库重算向量 |
| 主键形式 | 复合 `(course_id, id)` | 现有 508/614 处跨课程重名，不改无法入库 |
| 章节建模 | 提升为 `chapter` 表 | 改回去要重写查询 |
| 可信等级 | 三档 + 人工/Lean 两维 | 与"三个层次"的表述一致 |
| 审核发布闸门 | 人工审核 + 已发布 + 许可 | 决定学生能看到什么 |
| 数据库变更方式 | 迁移制，已应用文件不可改 | 改成手改 schema 会有丢数据风险 |
| 中英术语表 | 人工维护，不用机器翻译 | 术语错会直接损害可信度 |
