# 域名与校外访问

现状（2026-10-22 确认）：浏览器用 `http://115.156.72.1/` 在**校内**能到 nginx（一开始看到 403），
**手机 4G 校外访问超时**；还没有域名。

这两个问题是连在一起的，但根因不同：

| 现象 | 根因 | 谁来解决 |
| --- | --- | --- |
| 校外打不开 | 学校出口没给这台机器放行入站 80/443 | 网络信息中心（要申请） |
| 网址是 IP | 没有域名解析 | 网络中心给子域，或自己买域名 |

先说一件**马上会撞上**的事，它比域名更急。

---

## 0. 先说这个坑：prod + http = 登录会掉线

`server/app/auth.py` 里，`APP_ENV=prod` 时会话 cookie 带 `Secure` 标记。
**浏览器不会在 http 请求里回传 Secure cookie**，所以现在的状态是：

```
输账号密码 → 提示登录成功 → 跳到下一页 → 又回到登录页
```

这不是登录逻辑坏了，是 cookie 没被带回来。日志里看不到错误，最容易被当成 bug 查半天。

有三种解法，按推荐顺序：

**A. 上 https（根治）** — 域名 + 证书到位后自动消失，见下面路径一。

**B. 临时关掉 Secure（域名还没批下来时的过渡）** — 在 `.env` 里加一行：

```bash
COOKIE_SECURE=0
sudo systemctl restart whu-teaching
bash deploy/doctor.sh    # 会看到一条黄色提醒，属预期
```

这是一次有意的降级：会话在明文 http 上传输，校内网段内可接受，**拿到证书后必须删掉这一行**。
`scripts/preflight.py` 会一直提醒它，防止忘了。

**C. 不要用 `APP_ENV=dev` 来绕过** — 那会同时打开"后端托管静态站"和"请求头即身份"两条路，
副作用比关 cookie 大得多。

---

## 1. 三条路，先选一条

| 路径 | 需要什么 | 多久 | 代价与风险 | 适合 |
| --- | --- | --- | --- | --- |
| **一、学校域名 + 放行 443**（推荐） | 网络中心开入站 443；一个 `*.whu.edu.cn` 子域 | 1～3 周（走流程） | 需要填表、说明用途；证书通常由学校统一签发 | 长期正式运行 |
| **二、校内对外服务器反代** | 学院/中心已有一台校外可访问的机器，且与这台内网互通 | 几小时（如果机器现成） | 依赖别人的机器；多一跳，排查变复杂 | 有现成对外服务器 |
| **三、内网穿透** | 一台国内有公网 IP 的机器（自购云主机），或商用穿透服务 | 半天 | **教材内容会经过第三方节点**，需报备；云主机每年几百元 | 临时演示、评审 |

判断方法很简单：**能不能让网络中心放行入站 443**。能，就走路径一；短期等不了，用路径三顶几周。

> 红线：不要用境外 CDN/隧道（Cloudflare Tunnel 之类）承载教材内容。教材有版权、内容要留在校内，
> 走境外节点既不合规，也会让问答和上传变慢。

---

## 2. 路径一：申请域名与放行端口

### 2.1 找谁、说什么

一般找**网络信息中心**（或学院信息办）的服务台，提一个"二级域名 + 端口放行"的申请。可直接用这段：

> 老师您好：
>
> 数学与统计学院因教学需要，在 `115.156.72.1` 上部署了一套教学平台（Ubuntu + nginx + PostgreSQL）。
> 现申请两项：
>
> 1. **入站端口放行**：允许校外访问该主机的 **443/TCP**（若方便，80/TCP 也请一并放行，
>    用于证书自动续期）。
> 2. **域名解析**：申请一个二级域名（如 `ai.math.whu.edu.cn`），A 记录指向 `115.156.72.1`。
>
> 用途：本科课程《数学分析》《复变函数》等的习题、知识点图谱与 AI 答疑，仅校内师生使用，
> 需要登录。数据存放在本机，仅调用国内大模型 API（已做域名白名单）。
> 如需备案材料或安全承诺书，我可以补。

### 2.2 顺便问清三件事（决定后面怎么做）

1. **证书**：学校是否统一签发（很多高校有校内 CA 或被认可的商业证书）？有的话直接用，省掉 certbot。
2. **只开 443 还是也开 80**：只开 443 时，Let's Encrypt 的 HTTP-01 验证做不了，得用 DNS-01。
3. **是否需要备案**：`whu.edu.cn` 子域通常已备案；自己买域名指向国内 IP 则必须备案。

### 2.3 拿到域名后（假设是 `ai.math.whu.edu.cn`）

**第一步：DNS 解析生效**

```bash
dig +short ai.math.whu.edu.cn        # 应输出 115.156.72.1
```

**第二步：证书**

学校给了证书就跳过这一步，把 `.crt`/`.key` 放到 `/etc/nginx/ssl/`。

自己申请（80 已放行，用 webroot）：

```bash
sudo apt install -y certbot
sudo mkdir -p /var/www/certbot
sudo certbot certonly --webroot -w /var/www/certbot -d ai.math.whu.edu.cn --email 你的邮箱 --agree-tos -n
```

只放行了 443（80 不可用）时用 DNS-01：

```bash
sudo certbot certonly --manual --preferred-challenges dns -d ai.math.whu.edu.cn
# 它会让你去 DNS 面板加一条 TXT，加完回车
```

手动 DNS 每次续期都要操作一次。想自动，用 `acme.sh` 配域名商的 API（阿里云/腾讯云都支持），
这是唯一能做到"长期免维护"的方式。

**第三步：换 nginx 配置**

```bash
cd /home/aiformath/AIForTeaching
sudo cp deploy/nginx-tls.conf.example /etc/nginx/sites-available/whu-teaching
sudo nano /etc/nginx/sites-available/whu-teaching   # 把 ai.math.example.edu.cn 全换成你的域名
sudo nginx -t && sudo systemctl reload nginx
```

如果 `nginx -t` 报 `unknown directive "http2"`（nginx < 1.25.1），把那一行删掉，
改成 `listen 443 ssl http2;`。

**第四步：把应用配置切到 https**

```bash
nano .env
```

```diff
- CORS_ORIGINS=http://115.156.72.1
+ CORS_ORIGINS=https://ai.math.whu.edu.cn
- COOKIE_SECURE=0
```

`COOKIE_SECURE` 那一行**删掉**（删掉后自动按 `APP_ENV=prod` 带 Secure）。

```bash
sudo systemctl restart whu-teaching
bash deploy/doctor.sh
```

**第五步：验收**

| 检查 | 命令 | 预期 |
| --- | --- | --- |
| 解析 | `dig +short 你的域名` | `115.156.72.1` |
| 跳转 | `curl -sI http://你的域名` | `301` 到 https |
| 证书 | `curl -sI https://你的域名` | `200`，无证书警告 |
| 接口 | `curl -s https://你的域名/api/v1/health` | `{"status":"ok",...}` |
| 登录 | 浏览器登录后刷新 | 不掉线（cookie 带 Secure 且 https 能回传） |
| 续期 | `sudo certbot renew --dry-run` | 成功 |

## 3. 路径二：让一台校内对外服务器反代

如果学院已有一台校外可访问的机器（比如 `teach.math.whu.edu.cn`），在**那台**机器上加：

```nginx
location /ai/ {
    proxy_pass http://115.156.72.1/;      # 注意结尾的 / ，会把 /ai/ 前缀去掉
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 180s;
    client_max_body_size 300m;
}
```

三个必须注意的点：

1. **路径前缀**。上面这种写法，前端资源请求的是 `/ai/js/app.js`、后端是 `/ai/api/v1/...`。
   而前端代码里的接口路径是绝对的 `/api/v1/...`，所以更省事的做法是**用子域而不是子路径**：
   `ai.math.whu.edu.cn` 直接反代到 `115.156.72.1`，前端一行都不用改。
2. **`X-Forwarded-Proto` 要透传**，否则后端以为是 http，Secure cookie 不下发，又是"登录掉线"。
3. 反代机器到 `115.156.72.1` 要**内网可达**（校园网内一般可以，先 `curl -I http://115.156.72.1/` 验证）。

## 4. 路径三：内网穿透（过渡用）

原理：一台有公网 IP 的机器做中转，把外部请求转发到校内的 `115.156.72.1:80`。

自建（frp，需要一台国内云主机）：

```ini
# 云主机 frps.toml
bindPort = 7000
vhostHTTPSPort = 443
```

```ini
# 校内机器 frpc.toml
serverAddr = "云主机IP"
serverPort = 7000
auth.token = "换一个长随机串"

[[proxies]]
name = "whu-teaching"
type = "http"
localIP = "127.0.0.1"
localPort = 80
customDomains = ["ai.example.com"]      # 这个域名要解析到云主机
```

商用穿透服务（花生壳、natapp 等）更省事，但要看清：**免费版限速、二级域名随机、
数据经过服务商节点**。教学平台里有学生姓名与答题记录，是否允许经第三方，需要学院点头。

无论哪种，穿透只是"临时让外面能进来"，域名与端口该申请的还是要申请。

## 5. 等域名期间，怎么给校外的人看

- **评审/汇报用**：在自己电脑上开 SSH 隧道，让对方的浏览器走你的机器？不可行。
  更实际的是**录屏 + 截图**，或让对方连学校 VPN。
- **学校 WebVPN**：多数高校有 `webvpn.whu.edu.cn`，登录后可以访问校内地址。
  优点是零成本、不用开端口；缺点是长连接和文件上传经常出问题，不适合日常教学。
- **只给少数人**：用 `ssh -L` 把人带进来不现实，改用路径三。

## 6. 相关配置一览

| 位置 | 要改什么 | 说明 |
| --- | --- | --- |
| DNS | A 记录 → `115.156.72.1` | 找网络中心或域名商 |
| nginx | `server_name`、证书路径 | `deploy/nginx-tls.conf.example` |
| `.env` | `CORS_ORIGINS=https://域名` | 不能是 `*`，preflight 会拦 |
| `.env` | 删掉 `COOKIE_SECURE=0` | 上 https 后必须删 |
| `.env` | `MODEL_ALLOWED_HOSTS` | 模型 API 域名白名单，与访问域名无关 |

改完统一验证：`bash deploy/doctor.sh` 全绿 + `sudo certbot renew --dry-run` 成功。

---

## 7. 未验证与已知限制

- 本文的命令按仓库里的配置与常见 Ubuntu/nginx 版本写成，**未在真实域名与证书上跑过**。
- 学校是否给子域、是否放行 443、证书由谁签发，取决于你们网络中心的政策，本文只给通用流程。
- `http2 on;` 需要 nginx ≥ 1.25.1（Ubuntu 26.04 满足；24.04 的 1.24 要用旧写法）。
- HSTS 先设 1 天（`max-age=86400`），确认证书稳定后再加到一年，否则证书出问题时会锁住访问。
