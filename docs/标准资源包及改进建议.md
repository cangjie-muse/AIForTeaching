# 标准资源包与后续改进

当前格式已经足以接入网站，无需修改现有数学内容。平台直接解析结构文件与题库文件；参考教材不参与知识提取。网站只需要三份标准文件，以及知识正文或习题实际引用的插图；PDF 原书可以留在来源资料库，不必进入离线网站。

v0.8 已从九门修订交付包重新导入。交付包的课程根 ID 均唯一，旧版 175 组同源题异文和 3 组重复路径均已消除；网站仍将十门课标为“待教师审核”。以下建议为下一轮接口设计，不要求改动本轮已交付的三件套。

## 这轮接入后的接口建议

1. **网站导入时显示更新差异。** 同一课程再次导入时，预览新增、删除和改名的知识点 ID、源题 ID，以及各项数量变化。数值分析两门课各从 383 变为 462 个源题 ID，恰好说明只看总数容易把 ID 命名修复误认为新增题目。差异预览应说明是否会影响已有笔记、收藏和作答记录。现有页面还没有这一功能。
2. **可选的题目审核清单。** 在资源包旁增加机器可读文件，按 `exerciseId` 记录 `reviewStatus`（待核/通过/需修订）、`issueType`、`note`、`sourceReference`。例如偏微分方程 4 个 `-variant-z` 暂定 ID 和数值分析两门课的原书题设冲突，可明确标在具体题目上。当前验收报告只给人阅读，网站不能据此自动定位待判题目，也不能把“同源题异文为 0”当作数学审核完成。
3. **可选的内容版本与校验清单。** `course.json` 记录稳定 `courseId`、`contentVersion`、修订日期和三份核心文件的哈希；网站另计算实际哈希并核对。这样多次交付时能知道某门课是否真的变化，避免重新导入未变的版本。三份标准文件仍是必需输入，元信息文件保持可选。
4. **知识点关系另给可选文件。** 目前图谱只从层级和共题计算连线。若要展示真正的先修、推导或应用关系，应由课程方提供 `sourceId`、`targetId`、`type` 与依据，不从教材或题目共同出现自动推断。

## 目前支持的输入

资源包根目录保留三份文件，名称区分大小写：

```text
一门课程-课程资源包/
  知识节点.xlsx
  知识点.md
  习题.md
  course.json              可选
  资料/                   仅在正文或题目引用插图时需要，路径须与 Markdown 一致
    插图/figure.png
```

Excel 只有一个课程工作表，八列依次为 `1级节点`、`2级节点`、`3级节点`、`4级节点`、`5级节点`、`6级节点`、`知识说明`、`知识点标签`。每行保留完整路径，不以空白单元格表示“同上”。层级不能中间断开，每一个父节点也需有一行。名称可自由修改，稳定身份由 Markdown 锚点决定。

知识点标签示例：

```text
知识内容：知识点.md#kp-ch08-symplectic-definition
习题：习题.md#kp-ch08-symplectic-definition
```

知识内容按显式 HTML 锚点与标题划分。每个节点须在两份 Markdown 中各有一个唯一锚点，无题也保留习题锚点并说明。正文支持 Markdown、`$…$` 与 `$$…$$` 数学公式。

习题示例：

```markdown
<a id="kp-ch08-symplectic-definition"></a>
### 辛流形的定义

<!-- source-exercise:p202-1 -->
1. 完整题干。

   **答案：** 完整简解。

   **难度：1/5；出处：** 教材、章节和书页。**解答来源：** 来源说明。
```

同一题在多个节点下可重复出现，平台以 `source-exercise` 的 ID 去重并合并关联。当前网站对同一 ID 下不一致的题干、答案、难度或出处会保留所有版本，题库标注“待教师核对”；这属于兼容接入，不代表来源资源包已修好。标准交付仍应核对并统一同题的副本；确属不同题目时使用不同 ID。

可选的 `course.json` 当前支持：

```json
{
  "audience": "本科高年级",
  "subject": "专业课程",
  "description": "课程简介。",
  "textbook": "参考书目说明。"
}
```

## 当前文件中的发现

本次资源包具有 259 个层级节点，其中 232 个是实质知识点。题库有 330 道不同习题，392 条节点关联。82 个知识点没有关联题，平台保留为空，不补造题目。

节点 Excel 描述课程—章节—知识点的隶属关系，尚没有先修、推导、例子、应用等类型化边。网站可生成全课程知识点总图与章节关系图；共用习题连线从题库关联即时计算，不猜测学术依赖。

Excel 中的命名空间前缀写法是合法 OOXML；部分读取库未能直接识别。平台在读取时做了内存兼容处理，源工作簿没有被更改。这不是要求重新整理数据的问题。

这里兼容的是本次交付文件规范；没有声称接入雨课堂的私有网络 API，也没有把本地试导入当作雨课堂在线发布。

## 建议后续增加的内容

以下均为建议，不是首版必填项，也未宣称当前已支持导入。

1. **资源包版本与明确课程 ID。** 增加 `schemaVersion`、`courseId`、`contentVersion`、修订日期。一级节点锚点若为通用的 `course-overview`，网站按课程名称匹配规划 ID 或生成稳定 ID；标准交付更宜直接使用互异的一级锚点。版本字段有助于增量更新和回滚。
2. **可选关系文件。** 例如 `关系.json`，每条保留 `sourceId`、`targetId`、`type`、`rationale`、`reviewStatus`。类型先限为先修、推导、例子、应用；由教师确认学术关系。不要为让图谱更密集而自动生成关系。
3. **机器可读的独立题目表。** 当前 Markdown 可以继续作为人可读交付；以后可另外导出 `题库.json`，按 ID 只维护一份题干、解答和 `nodeIds`，减少 Markdown 标记变化带来的解析风险。
4. **来源命名空间。** 当前 `p202-1` 在单教材内有效。引入多教材后，建议带教材标识，例如 `arnold1989:p202-1`，避免页码与题号冲突。
5. **题型、答案可见性和审核状态。** 增加证明题/计算题/选择题、提示与完整解答的区分、教师审核状态，方便以后出卷和控制学生可见范围。
6. **结构化来源位置。** 教材 ID、书页、PDF 页、原题定位、解答来源分别存储，便于一键跳页与 AI 引用。保留原始出处文字用于核对。

目前优先保持文件名、锚点和题目 ID 稳定；数学内容可以继续按现有流程维护。上述扩展可与现有八列表头并存。
