# 后端本地联调与端到端测试

本机没有 PostgreSQL，但后端代码（`server/app/*.py`）里全是手写 SQL。
没有真库跑过，等于没验证过。这里记录怎么在本机把整条链路跑起来。

## 1. 一次性准备

```powershell
# 后端依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt `
  -i https://pypi.tuna.tsinghua.edu.cn/simple

# 测试基建（把 PGlite 暴露成 PostgreSQL 端口）
npm install
```

PyPI 直连在国内经常几十 KB/s，加 `-i` 换清华镜像能快一个数量级。

## 2. 本地联调服务（能在浏览器里点）

```powershell
npm run dev:api
# 打开 http://127.0.0.1:8000/
```

一条命令拉起三样东西：

```
PGlite（WASM PG16） ──socket:55432──> psycopg   （e2e 用 55442）
uvicorn 起 FastAPI:8000，同时托管前端静态文件
数据在 .tmp/dev-db（重启保留，删掉即重来）
```

几个刻意的决定：

- **前后端同源**。审核页要带 `X-Actor` / `X-Roles`，浏览器会先发 OPTIONS 预检。
  前端 8765、后端 8000 时只要有一处 CORS 漏配就整页报错，而错误只有
  "Failed to fetch"，看不出原因。同一个端口就没有这层。
- **只挂白名单目录**（`js/ styles/ assets/ data/ config/ vendor/ course-packs/ reports/`）。
  仓库里还有 `secrets/`、`.env`、`db/`、`server/`，整站挂载等于把它们挂到 HTTP 上。
  实测 `/secrets/...`、`/.env`、`/server/app/admin.py` 都是 404。
- **自动建队**。启动后自动 POST 一次 `/review/queue/build`，打开审核页就有内容，
  不用先点按钮。
- **测试不再抢开发库的端口**。早期 `test:api` 用 55432（与 `dev:api` 相同），跑一次测试
  就得先杀掉开发服务器；开发服务器每被杀一次，正在看页面的人就撞一次"网页打不开"。
  现在 e2e 默认 55442，可以和 `dev:api` 并行跑（要改端口用 `E2E_PG_PORT`）。

示例数据是 `scripts/dev_seed.py`：8 道题，故意覆盖四种问题（未挂知识点、
溯源 unknown、缺书页、原文标"待核"），方便看队列排序是否合理。

## 3. 跑端到端测试

```powershell
npm run test:api
```

做的事：

1. 起一个 PGlite（WASM 版 PostgreSQL 16）实例，用 `@electric-sql/pglite-socket`
   把它的 wire protocol 暴露在 `127.0.0.1:55442`（开发库在 55432，两者**可以同时跑**）；
2. 用 `db/migrate.py --apply` 把 6 个迁移真正跑一遍；
3. 用 FastAPI `TestClient` 发真实 HTTP 请求，psycopg 走真实 PG 协议。

产物是一个临时库，跑完即丢。密钥写在 `.tmp/e2e-secrets/`，结束删除。

## 4. 它验证了什么、没验证什么

**验证**：SQL 语法与列名、约束与触发器、视图、权限拦截、密钥不泄露、审计落库。

**没验证**：性能、并发、pgvector 的向量检索（PGlite 没有 pgvector）。

所以这个测试能回答"接口能不能用"，不能回答"生产够不够快"。

## 5. PGlite 的三个坑（都已在脚本里处理）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `type "vector" does not exist` | PGlite 无 pgvector | `migrate.py --pglite-compat` 把 `vector(1024)` 降级为 `jsonb`、跳过 hnsw 索引 |
| `connection timeout expired` | `spawnSync` 阻塞事件循环，socket 服务端无法 accept | harness 改用异步 `spawn` |
| 一次 SQL 报错后所有 `SELECT` 返回空 | socket 实现在错误后协议错位 | 产生数据库错误的用例排在最后；线上 PG 无此问题 |

还有一条：`pgcrypto` **是可用的**（`@electric-sql/pglite/contrib/pgcrypto`），
但必须在 `PGlite.create({ extensions: { pgcrypto } })` 里显式加载。
之前误判成"没有"，是因为没加载就 `CREATE EXTENSION` 失败了。

## 6. 这轮跑出来的四个真 bug

端到端测试的价值就在这里——它们都不是靠读代码能发现的：

1. **`db.query()` 无条件 `fetchall()`**：所有不带 `RETURNING` 的写入（审计、改密钥、
   自检落库）在真库上直接抛 `ProgrammingError`。
2. **`require()` 把 `current_actor` 当默认值传**：FastAPI 不把它当依赖，
   而会把 `Actor` 当请求体解析，写接口全部变成 422。
3. **`PUBLIC_COLUMNS` 用了视图的列** `key_configured` 却去查表，读接口直接报错。
4. **非 ASCII 请求头**：`X-Actor: 信息化专员` 浏览器根本发不出去（fetch 抛
   `TypeError`），改为 `encodeURIComponent` + 服务端 `unquote`。

另外 `DuplicatePreparedStatement` 说明自动 prepare 在多路复用连接上会撞名，
已在连接池里关掉。

## 7. 上服务器时怎么跑

```bash
# 真库
DATABASE_URL=postgresql://whu:***@127.0.0.1:5432/whu_teaching \
  python db/migrate.py --apply          # 不要带 --pglite-compat

uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000
```

接口自检：

```bash
curl http://127.0.0.1:8000/api/v1/health
```

返回里的 `models` 字段会说明当前用的是哪个端点、数据出不出校。
