# 课程内容工作台（导入 / 生成 / 修改）

这一页把原来的「课程导入」和「教材生成」合成了一个入口。合并的理由不是菜单太长，
而是这两个功能本来就是同一个动作的两条路径，却各存了一套数据：

| 原来 | 数据存哪 | 谁能看到 |
| --- | --- | --- |
| 课程导入 | 浏览器 IndexedDB | 只有这个浏览器 |
| 教材生成 | PostgreSQL | 平台、审核队列、问答检索 |
| 学生端 | 静态课程包（`data/`） | 学生 |

三份内容互不知道。老师改一份，另外两份不变——"这门课的习题不对"就是这么来的。
现在数据库是唯一真源：导入落库、生成落库、修改改库；导出从库里生成。

## 三个标签页

**AI 生成**：上传整本 PDF → 平台按章标题切开（先给预览）→ 每章一个子任务 → 知识点与
习题进审核队列。细节见 [教材生成流水线.md](教材生成流水线.md)。

**导入资源包**：选已有的三件套（`知识节点.xlsx` + `知识点.md` + `习题.md`，可选
`course.json`）。**解析在浏览器里做**——前端本来就有完整的校验器（锚点、层级连续性、
题目关联），服务端不重复实现一遍 xlsx 与 Markdown 解析，也就不用装 `openpyxl`。
校验通过后把解析结果发给服务器落库。

**修改与导出**：直接改知识点（标题、标签、正文）和习题（题干、答案、难度、出处）；
停用走 `retired`；导出三件套（xlsx + 两份 md），用 Excel 改完回到「导入资源包」整体更新。

## 整体更新 = 标记停用，不物理删除

老师导出 Excel 改完再导回来，资源包里"没有的"旧知识点/旧习题会被标记为 `retired`：

- 学生端与课程包不再出现；
- 学生作答、审核决定、修订历史都还在（这些行上挂着数据，删了不可恢复）；
- 只退休**上一次导入带进来的行**（`content_batch` 非空且不是本批次）。
  模型生成、还没审的草稿不会被一次导入顺手清掉——那是老师的工作量，不该被导入动作吃掉。

另有一种「只增改」模式（`mode=merge`），不处理文件里缺失的内容，用于小修小补。

## id 与批次

- 知识点 id、题目 id 由资源包给出，是跨版本对齐的唯一依据。同一个 id = 同一条记录。
- 每次导入生成一个 `content_batch`，记在 course / chapter / knowledge_node / exercise 上，
  同时写一条 `content_import` 审计记录（谁、什么时候、写了多少、停用了多少、有哪些提示）。
  "题怎么少了"必须能查出来。

## 导出格式

导出给的是能**原样再导入**的三件套：

- `知识节点.xlsx`：`1级节点…6级节点 / 知识说明 / 知识点标签` 八列。
  「知识说明」列同时写 `知识点.md#<节点id>` 与 `习题.md#<习题锚点>`——导入器靠它把
  Excel 的行、知识正文、题目三边对上，缺一个引用整包会被拒。
- `知识点.md` / `习题.md`：`<a id="…"></a>` 紧跟标题；题目用
  `<!-- source-exercise:ID -->` 定界，结尾一行 `**难度：n/5；出处：** …`。
- 一级节点（课程根）也要有锚点：导入器按行校验，根节点没有锚点同样会被拒。

## 在线修改

- `PATCH /api/v1/courses/{id}/nodes/{node_id}`：标题、正文、标签、审核状态。
- `PATCH /api/v1/courses/{id}/exercises/{id}`：题干、答案、难度、出处；改出处会**重算溯源**
  （书页、题号、来源类型是从出处文本里解析出来的，不重算就会和文本对不上）。
- `POST …/nodes/{id}/retire`、`POST …/exercises/{id}/retire`：停用。
- 所有写操作进 `audit_log`。

## 接口

```
POST   /api/v1/courses/{id}/content/import     # 导入（admin），mode=replace|merge
GET    /api/v1/courses/{id}/content            # 读内容（reviewer），?include_retired=true
GET    /api/v1/courses/{id}/content/export     # 导出（admin）：nodes + 两份 md
PATCH  /api/v1/courses/{id}/nodes/{node_id}    # 改知识点
POST   /api/v1/courses/{id}/nodes              # 加知识点
POST   /api/v1/courses/{id}/exercises          # 加习题
POST   /api/v1/courses/{id}/nodes/{node_id}/retire
POST   /api/v1/courses/{id}/exercises/{id}/retire
```

## 绝对路径与旧入口

- 导航里只剩「课程内容」。`#/import` 与 `#/generate` 会重定向到对应标签，
  老书签不会变成空白页。
- 原来纯前端的导入（`js/import-ui.js`）已删除。如果之前有导入只存在浏览器里，
  它不会自动迁移到数据库——需要重新导入一次。这一条是这次改动的代价，必须说清楚。

## 还没做的

- **学生端还没接上。** 学生端读的是 `data/` 静态课程包，导入/生成/修改的结果停留在数据库。
  发布流程（把审核通过的库内容导出成学生端能读的数据）仍未实现。
- **图片没跟着导出。** 正文里引用的插图（`资料/`）在导出时不会打包，资源包里的图片
  需要老师从原目录带走。
- **导入是整包事务的一部分，但不是原子替换。** 中途失败会留下已写入的部分（行级 upsert）。
  重新导入同一份包可以修正，但不会回滚。
- **章节不会因导入而删除。** 章节没有 `retired` 状态，旧章节会留着；
  空章节在学生端不显示，但库里仍在。
- **大包会慢。** 逐行 upsert，4800 道题的包在 PGlite 上要几十秒；换成真 PostgreSQL
  会快很多，但没有实测过。
