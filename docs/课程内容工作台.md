# 课程内容工作台（导入 / 生成 / 修改）

这一页把原来的「课程导入」和「教材生成」合成了一个入口。合并的理由不是菜单太长，
而是这两个功能本来就是同一个动作的两条路径，却各存了一套数据：

| 原来 | 数据存哪 | 谁能看到 |
| --- | --- | --- |
| 课程导入 | 浏览器 IndexedDB | 只有这个浏览器 |
| 教材生成 | PostgreSQL | 平台、审核队列、问答检索 |
| 学生端 | 静态课程包（`data/`） | 学生 |

三份内容互不知道。老师改一份，另外两份不变——"这门课的习题不对"就是这么来的。
现在数据库是唯一真源：导入落库、生成落库、修改改库；导出从库里生成。

## 三个标签页

**AI 生成**：上传整本 PDF → 平台按章标题切开（先给预览）→ 每章一个子任务 → 知识点与
习题进审核队列。细节见 [教材生成流水线.md](教材生成流水线.md)。

**导入资源包**：选已有的三件套（`知识节点.xlsx` + `知识点.md` + `习题.md`，可选
`course.json`）。**解析在浏览器里做**——前端本来就有完整的校验器（锚点、层级连续性、
题目关联），服务端不重复实现一遍 xlsx 与 Markdown 解析，也就不用装 `openpyxl`。
校验通过后把解析结果发给服务器落库。

**修改与导出**：直接改知识点（标题、标签、正文）和习题（题干、答案、难度、出处）；
停用走 `retired`；导出三件套（xlsx + 两份 md），用 Excel 改完回到「导入资源包」整体更新。

## 导入时先填课程名称

导入资源包时第一个要填的是**课程名称**，默认取资源包里的课程名。规则只有两条：

| 情况 | 行为 |
| --- | --- |
| 平台里已有同名课程 | 提示「已经有《X》（id：…）」，确认后更新那门课 |
| 没有同名课程 | 提示「还没有这门课」，确认后按资源包里的课程 id 新建 |

名称与资源包里的名字不一致时（例如把「数值线代」写成「数值线性代数」），
确认框会先把两边都写出来再问一次；确认后这个名字会被写进 `course.title`，
不是只做个提示。

课程存在与否由**数据库**回答，不是照页面里那份可能几分钟前的课程列表判断：
点下确认时先重新拉一次 `/api/v1/courses`，再决定是更新还是新建。

导入写完会重新拉一次课程目录（`A.loadCatalog()`），所以课程中心的数量、
「建设中（未发布）」里的知识点与习题数会立刻跟着变；课程总览要等内容审核
并发布后才对学生可见。

## 导入之后为什么课程中心还是「未发布」

导入只写内容，不发布课程。两道门都要过：

1. **内容状态**：导入进来是 `draft`（待审）。知识点不计门禁，题要「已发布」才给学生看。
2. **课程状态**：`course.review_status` 要是 `published`，公开目录里才会出现这门课。

一道题都没有的课（讲义型、还没来得及配题的）**也能发布**，接口会返回 `warning`，
页面上写明「学生只能看知识点」。拦在这里等于让整门课永远不可见。

题从 `draft` 到「已发布」有两条路：

| 路径 | 做法 | 可信度 |
| --- | --- | --- |
| 逐题审 | 「内容审核」里逐题通过 → 课程内容页点「发布到学生端」 | 人工已审 |
| 批量审 | 「内容审核」勾选 → 批量通过 → 点「发布到学生端」 | 人工已审 |
| 整课放出 | 课程内容页「放出全部题目并发布」 | **未经人工校验**（`human_verified_at` 不写） |

「发布到学生端」会把 `teacher-reviewed` 这一档一起放出：审核是逐题的动作，发布是整门课的开关。
`machine-checked` 与 `draft` 不会跟着出去——那些没人看过。

「放出全部题目并发布」是给"整本书的题老师认可"的场景，一次写完 `exercise.review_status='published'`
再发布课程，并在 `audit_log` 里记 `exercise.publish-all`。它不冒充审核：`human_verified_at` 保持空，
所以可见范围设成「仅人工审核」时，这些题仍然不放出来。

## 整体更新 = 标记停用，不物理删除

老师导出 Excel 改完再导回来，资源包里"没有的"旧知识点/旧习题会被标记为 `retired`：

- 学生端与课程包不再出现；
- 学生作答、审核决定、修订历史都还在（这些行上挂着数据，删了不可恢复）；
- 只退休**上一次导入带进来的行**（`content_batch` 非空且不是本批次）。
  模型生成、还没审的草稿不会被一次导入顺手清掉——那是老师的工作量，不该被导入动作吃掉。

另有一种「只增改」模式（`mode=merge`），不处理文件里缺失的内容，用于小修小补。

## 上传前先在本机体检

二十几本教材逐个往页面上传，失败了再回来改，来回十几趟。先在本机跑一遍：

```bash
node scripts/check-pack.cjs "D:\教材资源包"     # 这个目录下所有子目录都当资源包查
node scripts/check-pack.cjs "D:\教材\拓扑学"   # 只查一个
```

它用的是浏览器里同一套解析代码（`js/import-core.js` + `js/xlsx-reader.js`），
输出每个包的：知识点数、题目数、课程 id，以及会被拒的原因。

```
course-analysis  ✓ 159 个知识点 / 416 道题  （课程 id：analysis）

p2-锚点不符  ✗ 习题.md 缺少锚点：analysis
p3-题号顿号  ✗ 知识点 analysis-n9275621 的题目既没有 source-exercise 标记，
                也找不到题号，无法拆分。
    · 有 416 处题号不是"1."格式（是"1、"或"1) "），可能拆不开题
```

这里通过、平台上仍被拒，说明问题在服务端（课程 id 冲突、权限、库约束），
不在文件。反转过来也一样：这里报的错就是页面上会看到的那句话。

## 只传一个文件：单文件增量导入

二十几本教材往往只有一版习题要改，重导整包会把整门课的审核状态打回草稿。
所以「导入资源包」支持只选 `知识点.md` 或 `习题.md`：

| 上传 | 做什么 | 不做什么 |
| --- | --- | --- |
| 只有 `知识点.md` | 按锚点更新这些知识点的正文 | 不动结构、不动题目、不动其他知识点 |
| 只有 `习题.md` | 按锚点增改这些知识点下的题 | 不动正文、不动结构 |
| 两个都传 | 上面两件一起做 | 仍然不动结构与未出现的锚点 |
| 带 `知识节点.xlsx` | 走整包导入（结构 + 内容 + 题目） | —— |

规则与整包导入共用一套解析（锚点、题号、`**答案：**`、`**难度：n/5；出处：**`），
所以同一份 `习题.md` 无论走哪条路，题目 ID 都一样。

几条要说清楚的行为：

- **默认先给预览**（`dry_run=true`）：会说"改几个正文、加几道题、摘掉几道题"，
  确认后才写库。
- **锚点对不上就跳过并点名**：把某门课的文件传到另一门课上，会得到一串
  "这些锚点在本课程里找不到"，而不是静默什么都不改。
- **从知识点上摘下来的题不会删**：解除关联后如果它不再属于任何知识点，标为
  `retired`；学生作答记录还在。
- **不做整体替换**：文件里没出现的知识点/题保持原样。想"缺的标停用"必须走整包导入。
- **一次事务**：中途报错整体回滚，不会留下半份改动。

## id 与批次

- 知识点 id、题目 id 由资源包给出，是跨版本对齐的唯一依据。同一个 id = 同一条记录。
- 每次导入生成一个 `content_batch`，记在 course / chapter / knowledge_node / exercise 上，
  同时写一条 `content_import` 审计记录（谁、什么时候、写了多少、停用了多少、有哪些提示）。
  "题怎么少了"必须能查出来。

## 导出格式

导出给的是能**原样再导入**的三件套：

- `知识节点.xlsx`：`1级节点…6级节点 / 知识说明 / 知识点标签` 八列。
  「知识说明」列同时写 `知识点.md#<节点id>` 与 `习题.md#<习题锚点>`——导入器靠它把
  Excel 的行、知识正文、题目三边对上，缺一个引用整包会被拒。
- `知识点.md` / `习题.md`：`<a id="…"></a>` 紧跟标题；题目用
  `<!-- source-exercise:ID -->` 定界，结尾一行 `**难度：n/5；出处：** …`。
- 一级节点（课程根）也要有锚点：导入器按行校验，根节点没有锚点同样会被拒。

## 在线修改

- `PATCH /api/v1/courses/{id}/nodes/{node_id}`：标题、正文、标签、审核状态。
- `PATCH /api/v1/courses/{id}/exercises/{id}`：题干、答案、难度、出处；改出处会**重算溯源**
  （书页、题号、来源类型是从出处文本里解析出来的，不重算就会和文本对不上）。
- `POST …/nodes/{id}/retire`、`POST …/exercises/{id}/retire`：停用。
- 所有写操作进 `audit_log`。

## 接口

```
POST   /api/v1/courses/{id}/content/import     # 导入整包（admin），mode=replace|merge
POST   /api/v1/courses/{id}/content/import-docs # 单文件增量（admin），dry_run 默认 true
GET    /api/v1/courses/{id}/content            # 读内容（reviewer），?include_retired=true
GET    /api/v1/courses/{id}/content/export     # 导出（admin）：nodes + 两份 md
PATCH  /api/v1/courses/{id}/nodes/{node_id}    # 改知识点
POST   /api/v1/courses/{id}/nodes              # 加知识点
POST   /api/v1/courses/{id}/exercises          # 加习题
POST   /api/v1/courses/{id}/nodes/{node_id}/retire
POST   /api/v1/courses/{id}/exercises/{id}/retire
```

## 绝对路径与旧入口

- 导航里只剩「课程内容」。`#/import` 与 `#/generate` 会重定向到对应标签，
  老书签不会变成空白页。
- 原来纯前端的导入（`js/import-ui.js`）已删除。如果之前有导入只存在浏览器里，
  它不会自动迁移到数据库——需要重新导入一次。这一条是这次改动的代价，必须说清楚。

## 发布出口：学生端看到的内容从哪来

到发布这一步之前，导入/生成/修改的结果都停在数据库里，学生端读的是 `data/` 静态课程包。
现在补上了出口，两级门禁：

1. **课程级**：`course.review_status = 'published'` 且 `published_at` 非空。
   没发布的课，公开目录 `/api/v1/catalog` 里根本不出现。
2. **条目级**：`exercise.review_status = 'published'`。课程发布了，也只放出老师在
   「内容审核」里逐题点过发布的题；仍为 draft / teacher-reviewed 的题不会因为课程发布被顺带放出去。

知识点不设条目级门禁：知识点正文在「课程内容」页由老师直接改，改完即定稿；
再要求逐条发布只会让树缺枝。`retired` 的节点与题始终隐藏。

发布前会先自检（`GET /courses/{id}/publish/status`）：会放出多少题、藏了多少、
上次发布是谁什么时候。**没有任何已发布题时拒绝发布**——否则学生端只能看到一棵没有题的树，
那比空课程更容易让人误判。

发布不是"把当前内容拷一份存起来"，而是**开闸**：公开目录每次请求都从库里现读。
所以发布之后改知识点正文、标签、题干会立刻反映到学生端（题目本身仍须保持"已发布"状态）；
新导入的题要等它在「内容审核」里被发布才会出现。发布动作本身记录 `publish_event`
与 `audit_log`，用来回答"谁在什么时候把哪一版放出去了"。

前端在启动时读 `/api/v1/catalog` 并把已发布课程合并进 `App.courses`：
库里有已发布内容的课覆盖静态包，其余继续用静态包。合并时 `resourceBase`、`textbook`、
`attachments` 三个字段"新值为空就保留旧值"——插图路径只在静态包里，覆盖成空就是一片裂图。
后端不可用时静默退回静态包，页面照常能看。

```
GET  /api/v1/catalog                        # 公开，不带鉴权，只列已发布课程
GET  /api/v1/catalog/{course_id}            # 公开，完整课程对象（前端需要的字段全给）
GET  /api/v1/courses/{id}/publish/status    # 发布自检（reviewer）
POST /api/v1/courses/{id}/publish           # 发布/重新发布（admin），写 publish_event + audit_log
POST /api/v1/courses/{id}/unpublish         # 撤回（admin）
```

## 还没做的

- **学生端数据是"读时合并"，不是"构建时生成"。** 浏览器每次打开都拉一次目录，
  课程多了会变慢；正式环境应该加缓存或改为构建期产物。
- **图片没跟着发布。** 已发布课程沿用静态包的插图路径；新生成的课程没有插图目录，
  正文里引用 `资料/` 的图会裂。
- **练习题/测验的作答记录没按版本隔离。** 内容改了再发布，旧作答仍然算在这道题上。
- **撤回发布不会通知学生。** 学生端下一次刷新才会发现课程消失。
- **导入是整包事务的一部分，但不是原子替换。** 中途失败会留下已写入的部分（行级 upsert）。
  重新导入同一份包可以修正，但不会回滚。
- **章节不会因导入而删除。** 章节没有 `retired` 状态，旧章节会留着；
  空章节在学生端不显示，但库里仍在。
- **大包会慢。** 逐行 upsert，4800 道题的包在 PGlite 上要几十秒；换成真 PostgreSQL
  会快很多，但没有实测过。
