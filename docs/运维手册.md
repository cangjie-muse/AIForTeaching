## 一、先看这四个地方

| 症状 | 先看 | 命令 |
| --- | --- | --- |
| 页面打不开 | 端口是否被旧服务占用 | `sudo ss -ltnp 'sport = :8000'` |
| 接口 500 | 服务日志 | `sudo journalctl -u mathagent-api -n 50 --no-pager` |
| 组卷一直"排队中" | worker 是否在跑 | `sudo systemctl status mathagent-worker` |

`whu-teaching.service` 与 `whu-worker.service`，占着 8000 并抢同一条队列。
现在已停用；若再次出现，用 `bash deploy/cleanup-legacy.sh --apply`。

## 二、组卷不动了

组卷是"API 入队 → worker 求解 → 落库"三段。卡在哪一段可以直接看出来：

```bash
# 1) 有没有任务入队
psql "$DATABASE_URL" -c \
  "select id,kind,status,attempts,created_at from pipeline_job
    where kind='paper-assembly' order by created_at desc limit 10;"

# 2) 运行记录状态
psql "$DATABASE_URL" -c \
  "select id,status,created_at,completed_at from assessment.assembly_run
    order by created_at desc limit 10;"

# 3) worker 最近做了什么
sudo journalctl -u mathagent-worker -n 40 --no-pager
```

- `queued` 不动 → worker 没在跑，或端口/数据库配置错；
- `running` 很久 → 求解规模过大：看 `scripts/load_assembly.py` 的实测（1000 候选/50 槽位约 14s）；
- 运行是 `infeasible` → 这是**正常结论**，不是故障：组卷页会给出"去掉哪一组约束就能解"。

## 三、成绩发布相关

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| 发布报 `review_incomplete` | 有提交项没教师决定 | 在教师复核台补分，再发布 |
| 发布报 `grade_already_published` | 这一版已发布 | 改分要先撤回，再确认新版本，再发布 |
| 学生看不到成绩 | 只显示**已发布**且是当前版本 | 检查 `assessment.grade.current_published_revision_id` |
| 撤回后学生看不到 | 正常：撤回即清空当前发布指针，历史仍保留 | 需要重新发布新版本 |
| 重评后学生仍看不到 | 正常：重评只是草稿 | 教师确认 → 发布 |

改分永远是**追加版本**（0037 的触发器禁止原位改分）。看到有人试图
`UPDATE assessment.grade_revision SET total_score = ...`，直接拦住——会报
`grade_revision_score_is_append_only`。

## 四、QTI 导入导出

```bash
# 导入记录（谁、何时、结果、差异数）
psql "$DATABASE_URL" -c \
  "select id,course_ref,status,item_count,error_count,warning_count,created_at
     from assessment.qti_import_run order by created_at desc limit 10;"

# 某次导入的差异
psql "$DATABASE_URL" -c \
  "select code,severity,message,item_ref from assessment.qti_import_difference
    where run_id='<run id>' order by severity,code;"
```

- 导入结果只可能是 `draft_ready` / `rejected`，**永远不会是 approved**；
- 导出被拒会落 `blocked` + reasons；教师端要能看到 reasons，否则等于没说；
- 空卷导出会被拒（`paper_has_no_slots`）——这是 0038 之后修的行为。

## 五、备份与恢复（上线前必做一次演练）

```bash
# 备份（含 assessment / learning 两个命名空间）
pg_dump "$DATABASE_URL" --format=custom --file=/home/mathagent/backup-$(date +%F).dump

# 恢复到临时库并验证表数
createdb mathagent_restore
pg_restore --dbname=mathagent_restore --no-owner /home/mathagent/backup-*.dump
psql mathagent_restore -c "select count(*) from assessment.paper_version;"
```

恢复演练只在**临时库**做；不要覆盖生产库。

## 六、升级流程

```bash
cd /home/mathagent/mathagent
git pull
set -a; . ./.env; set +a
.venv/bin/python db/migrate.py --apply
.venv/bin/python db/migrate.py --status | tail -3     # 期望 全 [已应用]

sudo systemctl status mathagent-api mathagent-worker --no-pager --lines=5
```

**判断迁移成功只看 `--status`，不看 `--apply` 是否报错**——曾经出现过
`--apply` 没带 `DATABASE_URL` 而"看起来跑完了"的情况。
