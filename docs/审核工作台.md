# 内容审核工作台

## 为什么先做队列，而不是"审核表单"

平台里有 4807 道待审题目、3175 条已标记的问题。这意味着审核的瓶颈不是
"表单填起来顺不顺手"，而是**没人知道 4807 道里先看哪 20 道**。

所以这一页的核心不是编辑框，是**排序**：

- 队列由数据异常自动生成（缺知识点、溯源不明、无精确书页、原文含"待核"），
  不需要人工建任务；
- 优先级按"修补成本 × 影响面"排：未挂知识点最优先（学生按知识点刷题时它压根不会出现），
  其次是溯源不明，再次是页码不精确；
- 每条题目把"机器能判定的事实"和"人才能判断的对错"分开呈现。
  机器只说"这题没挂知识点"，不说"这题答案错了"。

## 页面结构

```
┌─ 大盘：待审 / 已通过 / 已发布 / 未解决问题数 ─────────┐
├─ 问题分类 chip：页码不精确 1270 · 内容待核 1096 …    ─┤
├─ 队列表：优先级 | 题干摘要 | 可信度 | 问题 | 操作     ─┤
└─ 详情（右侧）：题干 / 挂载知识点 / 问题清单 / 决定     ┘
```

详情里的四个动作对应后端状态机：

| 动作 | 结果状态 | 说明 |
| --- | --- | --- |
| 领取 | `in-review` | 声明"我在看"，避免两人重复 |
| 通过 | `approved` | 人已确认，但**还没发布** |
| 退回修改 | `changes-requested` | 打回给编辑者 |
| 修改题目 | 不改状态 | 编辑即生成修订快照，可回溯 |

**"通过"不等于"发布"。** 发布是单独一步（`publish`），因为发布意味着学生真的会看到，
而审核通过的题可能还需要等教材版权确认。这两件事混在一起，出事时说不清是谁的责任。

## 两条刻意的限制

**1. 批量通过只适合机械问题。**
页面允许勾选批量通过，但确认框里写明了：批量通过解决的是"机器标记已处理"，
不代替逐题阅读。缺页码这类机械问题可以批量处理；"内容待核"不行。
如果以后有人抱怨这个提示太啰嗦，那说明它起到了作用。

**2. 前端不重复实现权限。**
页面会隐藏无权身份看不到的按钮，但真正的边界在服务端 `require("reviewer")`。
学生拿到接口地址直接 curl 也一样是 403。前端置灰只是体验，不是安全。

| 验证 | 方式 | 结果 |
| --- | --- | --- |
| 接口能用 | `server/tests/e2e_api.py`（真 PG + 真 FastAPI） | 建队、队列、领取、通过、修订触发器全通 |
| 字段契约 | e2e 断言队列返回包含页面所需的 12 个字段 | 通过（改后端列名会立刻报错） |
| 页面渲染 | `scripts/test-view-review.cjs`（node:vm） | 18 项：无权限、空队列、HTML 转义、未挂载警告等 |
| 代码规范 | `npm run check` | 通过 |

**没做过**：在真实浏览器里点一遍。渲染测试覆盖了"生成的 HTML 对不对"，
但没有覆盖"点下去有没有反应"。这一项等接入统一身份认证、能在浏览器里跑起
带鉴权的后端之后一起做。

## 修订差异

审核员要判断"这版能不能过"，前提是知道"这版改了什么"。

数据来源：触发器 `exercise_snapshot_on_update` 在每次 `UPDATE exercise` **之前**把旧值
写进 `exercise_revision`。所以快照存的是"改之前长什么样"，当前内容在 `exercise` 表里。
界面显示的是「最近一次修改前 → 现在」。

```
GET /api/v1/review/exercises/{course_id}/{exercise_id}/revisions
→ { current, revisions: [{version, prompt_md, answer_md, difficulty, source_page,
                          node_ids, changed_by, changed_at, change_note}], count }
```

差异渲染（`js/diff.js`）：

- **按字符比，不按行比**。数学题经常整段是一行（`$...$` 里没有换行），按行比对会把
  "改了一个 ε"报成"整行都变了"。
- **显示 Markdown 原文，不显示渲染后的公式**。渲染会吃掉空格与反斜杠，
  而这两样恰恰是最常被改坏的地方。
- 算法是 O(n·m) 的 LCS。超过约 1100×1100 字符退化为"整段替换"：仍能看到前后两版，
  只是没有逐字高亮。宁可慢一点也要给准确定位，但不能让页面卡死。
- 难度、书页这类标量并列显示（旧值划掉 → 新值）；挂载知识点显示增减。

没有修订记录时明确写"当前内容就是导入时的样子"，而不是显示一个空白的差异框——
空白会被误读成"没改动过，可以放心通过"。

验证：`scripts/test-diff.cjs`（14 项，含"改一个符号能定位到那一段"、
"LaTeX 原样保留"、"超长文本退化"）、审核页渲染测试（新增 7 项）、
端到端（新增 10 项：两次修改产生两条快照、快照记了改动人与说明、
队列读到修改后的题干、不存在的题目 404）。

开发库会造一条真实修订（走同一个触发器与 `app.actor`，不硬塞 `exercise_revision` 行），
只改难度与书页、不动题干——题干是真题原文，随手改写会让"核对"失去意义。
