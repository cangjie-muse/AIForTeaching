## 二、平台既有的表（**不是**本次 AIForTeaching 旧项目）

这些表来自本仓库更早的计划（`2026-11-04-math-knowledge-foundation.md`），**课程内容、
习题、审核、班级、课件、问答、作业批改**这些功能现在仍在页面里被使用：

| 迁移 | 表 | 用在哪 | 与本次设计的关系 |
| --- | --- | --- | --- |
| 0001 | `course` / `chapter` / `knowledge_node` / `exercise` / `course_asset` 等 | 课程中心、大纲、图谱、习题 | 阶段 A 的 **候选来源**（题目与课程） |
| 0013 | `app_account` / 会话 | 登录、账号管理 | 蓝图的 `actor_ref` 桥接 |
| 0015 | `teaching_class` / `enrollment` | 班级与选课 | **课程范围授权的真源**（`CourseScopeAuthorizer` 查它） |
| 0017 / 0018 | `qa_*` / `ai_message_basis` | AI 学习助手 | 本次设计不使用 |
| 0024 | `homework_*`（含 `public.submission` 链） | 作业批改 | 本次设计不使用 |
| 0025 | `courseware_*` | 课件生成 | 本次设计不使用 |

### 需要留意的一处**名称撞车**（不是错误，但必须写清）

| 域 | 表 | 语义 |
| --- | --- | --- |
| 作业批改（平台既有） | `public.submission` / `public.submission_item` | 学生交作业，教师批改打分 |
| 考试（本次设计） | `assessment.submission` / `assessment.submission_item` | 固定卷交卷，进入评阅队列 |

两者物理上分属不同 schema，代码里也都能看到显式前缀（`server/app/homework.py` 用
`public.submission`，阶段 C 的服务将用 `assessment.submission`）。**风险在于人读代码时
容易搞混**，因此约定：

* 提到"交作业"一律写 `public.submission`；
* 提到"交卷/交卷项"一律写 `assessment.submission`；
* 新代码禁止写不带 schema 的 `submission`（SQL 默认落到 `public`，那正是会出事的地方）。

### `public.assignment` 系列

`public.assignment` / `assignment_item` 由 0001 创建，**代码里没有直接读写**
（全部引用都是 `assessment.assignment`），但它们仍是 `public.submission` 的父表，
删掉会连带作业批改功能。因此保留，并明确：打印/在线作业的真源是
`assessment.assignment`。
