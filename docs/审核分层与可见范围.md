# 审核分层与「学生可见范围」

## 一、分层在哪里：不是新概念，库里早就有

审核分级的数据结构在 `db/schema.sql` 里，不需要新建：

| 层 | 数据来源 | 现在由谁产生 |
| --- | --- | --- |
| **未审核** `none` | 没有 `human_verified_at`，也没有通过校验的 Lean 证明 | 导入 / AI 生成后默认状态 |
| **Lean 形式化验证** `lean` | `lean_proof` 有 `compiled = true` 且 `faithful_status = 'teacher-reviewed'` | **还没有产线**（接口已留，见第五节） |
| **人工审核** `human` | `exercise.human_verified_at` 非空 | 审核页点「通过」即写入（发布也写） |
| **两者都有** `strongest` | 上面两条同时成立 | 同上 |

合成视图是 `v_exercise_verification.tier`（`none / lean / human / strongest`）。
另有一个 `v_publishable_exercise`：只有 `human`、`strongest` 的题才算"可进正式作业与考试"。

页面上能看到它们的地方：

- **内容审核页**（`#/review`）顶部大盘按 `tier` 统计；
- 队列每一行有徽标：未核 / Lean 校验 / 人工通过 / 双重通过；
- 审核详情里勾「人工审核通过」写 `human_verified_at`。

## 二、谁需要审核，谁不需要

| 内容 | 要不要审核 | 为什么 |
| --- | --- | --- |
| **习题** | 要，四档（未审核 / Lean / 人工 / 双重） | 我们的论断，对了才能给学生 |
| **知识图谱** | 要，**只有人工一档** | 审的是"图谱挂得对不对"，不是定理，谈不上形式化验证 |
| **教材片段**（`textbook_chunk`） | 不要 | 原文转载，审的是作者不是我们 |
| **知识点正文** | 不要 | 由教材切片生成，导入即定稿 |

教材片段与知识点正文仍受版权状态约束（`internal-only` 不外传），但**不设审核队列**——
给原文加审核只会制造假工作量。

## 三、缺的是"口径"，不是"分层"

原来学生端只看两件事：课程发布 + 题目 `review_status = 'published'`。
这等于**默认所有已发布的题都发**——即使没人看过内容，只要点了发布就上线。

现在加了第三道闸 `visibility_policy`（迁移 `0011`、`0012`）：

```
学生能看到什么 = 课程已发布 AND 题目已发布 AND 题目等级在允许范围内
```

三档（从严到宽，**习题与问答各自独立**）：

| 档位 | 允许的等级 | 学生端能拿到 |
| --- | --- | --- |
| `human` 仅人工审核通过 | `human`、`strongest` | 只放老师逐题确认过的题 |
| `verified` Lean 验证 + 人工审核 | `lean`、`human`、`strongest` | 加上形式化验证过的题 |
| `all` 全部（含未验证） | 四个全放 | 与引入本表之前完全一致 |

知识图谱单独一档：

| `graph_tier` | 含义 |
| --- | --- |
| `all` | 全放（默认，与引入审核前一致） |
| `human` | 只放人工审核过的节点 |

**默认全是 `all`**：升级不会让学生端突然空掉。三档是包含关系（`human ⊂ verified ⊂ all`），
这条不变式有测试钉住——写错一个等级名，学生端会静默少题或多题。

## 四、开关在哪、怎么用

**不在内容审核页了**：口径是"偶尔调一次但不能调错"的设置，审核是"逐条判断"的活，
放在一起会让人误以为改口径也是审核的一部分。现在它在左侧「系统管理 → 学生可见范围」
（`#/visibility`），教师与管理员可见，学生打不开。

> 2026-10-21 起：内容审核页只剩两块——习题审核、知识图谱审核。可见范围整块搬到系统管理。

- **作用范围**：全局默认（所有课程）或某一门课。选一门课后：
  - 这门课有单独设置 → 显示「这门课单独设置」+ 全局口径作对照 + 「取消本课设置」；
  - 没有 → 显示「跟随全局」，此时保存就会为它单独设置一份。
- **三个下拉**：习题与测验、AI 问答（完整解答）、知识图谱；
- 每个选项后面直接写「学生可见 N 题 / N 节点」——**保存前就能看到后果**；
- 某一档会清空学生端时给橙色警告，并指出两条出路（先去审核 / 换回更宽的档）；
- 选了 Lean 档会提示「Lean 验证尚未接入，当前效果与仅人工审核相同」；
- 保存后立即生效，写 `audit_log`（`visibility.update` / `visibility.reset`）。

口径解析规则只有一条：**课程有覆盖用课程，没有覆盖跟随全局**。合并是逐字段的，
课程只覆盖了习题时，问答与图谱仍跟随全局。

只有 `teacher / reviewer / admin` 能改；学生调用 `PUT/DELETE /api/v1/visibility` 是 403，
打开 `#/visibility` 也只会看到「没有这个页面的权限」。

## 五、知识图谱审核（只有人工）

内容审核页第二个标签「知识图谱审核」，选了一门课才出现。

**为什么从长表格改成章节树**：原来一行一章（"第一章 32 个节点"），老师看不到这章到底挂了
哪些知识点，也就判断不了"挂得对不对"——而这正是图谱审核唯一要判断的事。现在和图谱页一样：
一章一张卡片，展开就是它的子节点，形状和学生看到的一致，不用在两套表达之间换算。

**顺带修掉一个更糟的 bug**：原来按 `coalesce(chapter_id, id)` 分组，而真实导入数据里
`chapter_id` 是空的，结果**每个节点都自成一"章"**——数学分析 II 会列出 135 个"章"，
越长越像灾难。现在按 `parent_id` 往上走到 `level = 2` 的祖先当章，同一门课是 10 章、
每章 1—6 个子节点，和"每一章对应几个子节点"的直觉一致。

- 章头写「N 个知识点 · 已审 M」，已全审的章标「本章已通过」；
- 「整章通过」一次写一章所有节点（`POST /api/v1/review/graph/verify` 传 `chapter_id`）；
- 每个节点一行：「通过 / 撤销」逐条写（传 `node_ids`），「修改」就地改标题；
  改完不会自动通过——**改了就得再看一眼再通过**；
- 已全部通过的章可以「撤销本章通过」；
- 章卡片默认收起，逐节点明细按需展开（14 门课 4146 个节点，全摊开没人看得完）；
- 顶部另给「整门课通过」：学生端的树从课程根节点长出来，只通过各章会得到一棵
  "有枝无干"的树。根节点单列显示，不占章节卡片。

**通过是级联的**：标一章会连同它下面所有子节点一起标（递归 CTE）。原来按 `chapter_id`
更新，在真实数据下一个节点也改不到（changed = 0）——按钮点了没反应，这是本轮修掉的第二个 bug。

节点数据来自 `GET /api/v1/review/graph?course_id=…` 新增的 `nodes[]`（含 `parent_id`、
`chapter_id`、`verified`）；不传 `course_id` 时 `nodes` 是空数组，避免一次吐出四千多条。
就地改标题走 `PATCH /api/v1/courses/{course_id}/nodes/{node_id}`（`{title}`），写 `audit_log`
的 `node.patch`。**这条接口原来只给管理员**——文档里一直写着「教师能改课程内容」，接口却是 admin，
审核时想改个标题会 403；现在放宽到 `reviewer`（教师 / 审核员 / 管理员），学生仍是 403。

知识点**正文不审**，审的是图谱结构。所以这一档只影响"节点及其关系边是否出现在学生端"，
不影响题目。`graph_tier = human` 时未审节点连同挂在它上面的关系边一起隐藏。

## 六、怎么查"这道题标注过什么"

一道题可能同时有多个标注（工作流状态、可信等级、人工审核、Lean 证明、审核后有没有被改）。
按用途分四处看：

1. **审核队列每一行** —— 徽标只说等级（未核 / Lean 校验 / 人工通过 / 双重通过）。
   只覆盖"还在队列里的题"。
2. **审核页「按题号查审核记录」** —— 任意题都能查，**包括已发布、已不在队列里的**。
   先在上面的课程筛选里选一门课，再填题号（如 `pub-a`）点查询。显示：可信等级、
   人工审核时间与审核人、每条 Lean 证明（编译通过与否、忠实性、工具链）、内容版本、
   最近一次审核任务与工作流状态，以及"审核通过后又被改过"的警告。
3. **审核详情** —— 点队列里某条题的「审核」，详情顶部同一块记录会自动带出来，
   不用另外查。
4. **课程审核总表**（审核页，选了课程就出现）—— **这门课的全部题目**，一行一道：
   题号 / 题干摘要 / 可信等级 / 人工审核时间与审核人 / Lean / 工作流状态 / 审核任务状态。
   默认按等级排，**未审核的在最前面**；上面有等级芯片（全部 / 未核 / Lean / 人工 / 双重，
   每个带数量）和题号/题干搜索。点题号直接展开这道题的审核记录。
   队列只装待审的题，总表才是"这门课 400 道题各自什么状态"的答案——没有它，
   "哪些题还没人审"只能靠汇总数字糊过去。
5. **课程内容页**（修改与导出）—— 习题行直接标等级徽标，知识点行标「图谱已审 / 图谱未审」。
   改内容的人必须能一眼看到"这条审过没有"，否则会顺手改坏已审核的内容。

接口：

- `GET /api/v1/review/ledger?course_id=&tier=&question=&limit=&offset=`
  —— 课程审核总表。返回 `items[]`（含 `tier`、`human_verified_at/by`、`lean_confirmed`、
  `edited_after_review`、`task_state`、`prompt` 摘要）、`total`、`counts[]`（各档总数，
  不受筛选影响）、分页参数。`tier` 非法 400，`limit` 上限 500。教师/审核员可读，学生 403。
  排序是按等级权重（未审核最前），不是按题号——打开就是要看哪些还没审。
- `GET /api/v1/review/exercises/{course_id}/{exercise_id}/verification`
（教师 / 审核员 / 管理员；学生 403）。返回 `tier`、`human_verified_at/by`、
`lean_verified_at`、`proofs[]`、`content_version`、`edited_after_review`、
`task`（最近一次审核任务）、`lean_available`。

判读规则：

- `tier` 是视图 `v_exercise_verification` 合成的，不是某处算的——四个值口径唯一；
- **"审核后被改过"** = `updated_at > human_verified_at`。它不撤销"已审核"，
  只是提醒"这个结论是对改之前那一版下的"；
- **`lean_available = false`** 表示 Lean 验证尚未接入，此时 `proofs` 为空是正常的，
  不代表"没有证明"（见第七节）。

## 七、Lean 那一层：接口已留，尚未接入

- 表 `lean_proof` 与视图里的 `lean` 判定**已经存在**：编译通过 + 形式化忠实性人工确认；
- 但**还没有 Lean 编译器接入**：没有产线去生成 `statement_lean`、跑 `lake build`、回填
  `compiled`。所以真实数据里 `lean` 与 `strongest` 目前都是 0 题；
- 因此选「Lean 验证 + 人工审核」这一档，**效果与「仅人工审核」相同**（现在没有 Lean 题）。
  这是数据现状，不是 bug，界面也如实标注了。

留的口子在 `server/app/lean_service.py`：

| 入口 | 作用 |
| --- | --- |
| `LEAN_AVAILABLE` | 界面据它显示「未接入」；接上后自动消失 |
| `run_lean(statement_lean, proof)` | 唯一需要写的地方：编译并返回 `LeanBuild` |
| `LeanBuild` | 编译结果（成功与否、日志、工具链、文件），`log_sha256` 稳定 |
| `verify_exercise(course_id, exercise_id)` | 唯一"验证一道题"入口 |
| `record_proof(...)` | **唯一写库入口**：写 `lean_proof`、算哈希、必要时回填 `lean_verified_at` |

现在 `run_lean()` 会抛 `LeanUnavailable`，`record_proof()` 拒绝空命题，
`test_lean_service.py` 把这些契约钉住。要真做这一层还需要：Lean 4 + mathlib 构建机、
每道题的形式化脚本、"形式化是否忠实于原题"的人工确认流程。这是一期之后的事。

## 八、生效范围

1. **公开目录** `GET /api/v1/catalog`、`GET /api/v1/catalog/{id}`
   题量统计、题目列表、节点树都按口径过滤；题目与图谱互不影响（两个独立档位）。
2. **AI 问答的完整解答模式**（`mode=full`）
   两道条件独立：先要学生有作答记录（作答解锁），再要题目等级在允许范围内（信任解锁）。
   不满足时返回 403 并说明"这道题当前等级不在学生可见范围内，可以先用引导模式"。
   引导模式（`mode=guide`）不受影响——不给完整解答，也就没有"放出未审核内容"的问题。

## 十、还没做

- **Lean 验证没有产线**（见第六节）。分档与接口已就位，`lean` 档现在等价于 `human`。
- **`review_status` 与 `tier` 是两套状态**：一处说"工作流走到哪"，一处说"可信到什么程度"。
  页面上同时显示两者，但还没做"这两个状态不一致"的巡检（如已发布却 `tier=none` 的题）。
  端到端测试是手工造了这种数据来验证闸门有效——生产上应该有个定时报表。
- **图谱审核只有按章/按节点，没有逐节点界面**：`node_ids` 接口有了，页面只暴露整章。
- **问答的教材片段没有等级**：`textbook_chunk` 不审（原文转载），所以问答的检索层
  只能按版权状态过滤（`internal-only` 不外传）。这是刻意的，不是遗漏。
- **改内容不会自动撤销"已审核"**：审核页改题干/答案（`PATCH /review/exercises/…`）与
  内容工作台改节点正文，都不会清空 `human_verified_at`。严格说"人工审核通过"只对当时
  那一版成立，改了之后应该退回未审。现在靠审核员自律，后面应改成"内容变动即重置等级"，
  或在审核页标出"审核后被改过"的题。
