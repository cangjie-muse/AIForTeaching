# 审核分层与「学生可见范围」

## 一、分层在哪里：不是新概念，库里早就有

审核分级的数据结构在 `db/schema.sql` 里，不需要新建：

| 层 | 数据来源 | 现在由谁产生 |
| --- | --- | --- |
| **未审核** `none` | 没有 `human_verified_at`，也没有通过校验的 Lean 证明 | 导入 / AI 生成后默认状态 |
| **Lean 形式化验证** `lean` | `lean_proof` 有 `compiled = true` 且 `faithful_status = 'teacher-reviewed'` | **还没有产线**（接口已留，见第五节） |
| **人工审核** `human` | `exercise.human_verified_at` 非空 | 审核页点「发布」即写入 |
| **两者都有** `strongest` | 上面两条同时成立 | 同上 |

合成视图是 `v_exercise_verification.tier`（`none / lean / human / strongest`）。
另有一个 `v_publishable_exercise`：只有 `human`、`strongest` 的题才算"可进正式作业与考试"。

页面上能看到它们的地方：

- **内容审核页**（`#/review`）顶部大盘按 `tier` 统计；
- 队列每一行有徽标：未核 / Lean 校验 / 人工通过 / 双重通过；
- 审核详情里勾「人工审核通过」写 `human_verified_at`。

## 二、谁需要审核，谁不需要

| 内容 | 要不要审核 | 为什么 |
| --- | --- | --- |
| **习题** | 要，四档（未审核 / Lean / 人工 / 双重） | 我们的论断，对了才能给学生 |
| **知识图谱** | 要，**只有人工一档** | 审的是"图谱挂得对不对"，不是定理，谈不上形式化验证 |
| **教材片段**（`textbook_chunk`） | 不要 | 原文转载，审的是作者不是我们 |
| **知识点正文** | 不要 | 由教材切片生成，导入即定稿 |

教材片段与知识点正文仍受版权状态约束（`internal-only` 不外传），但**不设审核队列**——
给原文加审核只会制造假工作量。

## 三、缺的是"口径"，不是"分层"

原来学生端只看两件事：课程发布 + 题目 `review_status = 'published'`。
这等于**默认所有已发布的题都发**——即使没人看过内容，只要点了发布就上线。

现在加了第三道闸 `visibility_policy`（迁移 `0011`、`0012`）：

```
学生能看到什么 = 课程已发布 AND 题目已发布 AND 题目等级在允许范围内
```

三档（从严到宽，**习题与问答各自独立**）：

| 档位 | 允许的等级 | 学生端能拿到 |
| --- | --- | --- |
| `human` 仅人工审核通过 | `human`、`strongest` | 只放老师逐题确认过的题 |
| `verified` Lean 验证 + 人工审核 | `lean`、`human`、`strongest` | 加上形式化验证过的题 |
| `all` 全部（含未验证） | 四个全放 | 与引入本表之前完全一致 |

知识图谱单独一档：

| `graph_tier` | 含义 |
| --- | --- |
| `all` | 全放（默认，与引入审核前一致） |
| `human` | 只放人工审核过的节点 |

**默认全是 `all`**：升级不会让学生端突然空掉。三档是包含关系（`human ⊂ verified ⊂ all`），
这条不变式有测试钉住——写错一个等级名，学生端会静默少题或多题。

## 四、开关在哪、怎么用

内容审核页顶部「学生可见范围」面板：

- **作用范围**：全局默认（所有课程）或某一门课。选一门课后：
  - 这门课有单独设置 → 显示「这门课单独设置」+ 全局口径作对照 + 「取消本课设置」；
  - 没有 → 显示「跟随全局」，此时保存就会为它单独设置一份。
- **三个下拉**：习题与测验、AI 问答（完整解答）、知识图谱；
- 每个选项后面直接写「学生可见 N 题 / N 节点」——**保存前就能看到后果**；
- 某一档会清空学生端时给橙色警告，并指出两条出路（先去审核 / 换回更宽的档）；
- 选了 Lean 档会提示「Lean 验证尚未接入，当前效果与仅人工审核相同」；
- 保存后立即生效，写 `audit_log`（`visibility.update` / `visibility.reset`）。

口径解析规则只有一条：**课程有覆盖用课程，没有覆盖跟随全局**。合并是逐字段的，
课程只覆盖了习题时，问答与图谱仍跟随全局。

只有 `teacher / reviewer / admin` 能改；学生调用 `PUT/DELETE /api/v1/visibility` 是 403。

## 五、知识图谱审核（只有人工）

面板第二块「知识图谱审核」，选了一门课才出现：

- 按章列出：章节标题、节点数、已审/未审；
- 「整章人工通过」一次写一章所有节点（`POST /api/v1/review/graph/verify`）；
- 已全部通过的章可以「撤销本课通过」；
- 逐节点通过也支持（传 `node_ids`），页面暂时只暴露按章——几百个节点逐个点不现实。

知识点**正文不审**，审的是图谱结构。所以这一档只影响"节点及其关系边是否出现在学生端"，
不影响题目。`graph_tier = human` 时未审节点连同挂在它上面的关系边一起隐藏。

## 六、Lean 那一层：接口已留，尚未接入

- 表 `lean_proof` 与视图里的 `lean` 判定**已经存在**：编译通过 + 形式化忠实性人工确认；
- 但**还没有 Lean 编译器接入**：没有产线去生成 `statement_lean`、跑 `lake build`、回填
  `compiled`。所以真实数据里 `lean` 与 `strongest` 目前都是 0 题；
- 因此选「Lean 验证 + 人工审核」这一档，**效果与「仅人工审核」相同**（现在没有 Lean 题）。
  这是数据现状，不是 bug，界面也如实标注了。

留的口子在 `server/app/lean_service.py`：

| 入口 | 作用 |
| --- | --- |
| `LEAN_AVAILABLE` | 界面据它显示「未接入」；接上后自动消失 |
| `run_lean(statement_lean, proof)` | 唯一需要写的地方：编译并返回 `LeanBuild` |
| `LeanBuild` | 编译结果（成功与否、日志、工具链、文件），`log_sha256` 稳定 |
| `verify_exercise(course_id, exercise_id)` | 唯一"验证一道题"入口 |
| `record_proof(...)` | **唯一写库入口**：写 `lean_proof`、算哈希、必要时回填 `lean_verified_at` |

现在 `run_lean()` 会抛 `LeanUnavailable`，`record_proof()` 拒绝空命题，
`test_lean_service.py` 把这些契约钉住。要真做这一层还需要：Lean 4 + mathlib 构建机、
每道题的形式化脚本、"形式化是否忠实于原题"的人工确认流程。这是一期之后的事。

## 七、生效范围

1. **公开目录** `GET /api/v1/catalog`、`GET /api/v1/catalog/{id}`
   题量统计、题目列表、节点树都按口径过滤；题目与图谱互不影响（两个独立档位）。
2. **AI 问答的完整解答模式**（`mode=full`）
   两道条件独立：先要学生有作答记录（作答解锁），再要题目等级在允许范围内（信任解锁）。
   不满足时返回 403 并说明"这道题当前等级不在学生可见范围内，可以先用引导模式"。
   引导模式（`mode=guide`）不受影响——不给完整解答，也就没有"放出未审核内容"的问题。

## 九、还没做

- **Lean 验证没有产线**（见第六节）。分档与接口已就位，`lean` 档现在等价于 `human`。
- **`review_status` 与 `tier` 是两套状态**：一处说"工作流走到哪"，一处说"可信到什么程度"。
  页面上同时显示两者，但还没做"这两个状态不一致"的巡检（如已发布却 `tier=none` 的题）。
  端到端测试是手工造了这种数据来验证闸门有效——生产上应该有个定时报表。
- **图谱审核只有按章/按节点，没有逐节点界面**：`node_ids` 接口有了，页面只暴露整章。
- **问答的教材片段没有等级**：`textbook_chunk` 不审（原文转载），所以问答的检索层
  只能按版权状态过滤（`internal-only` 不外传）。这是刻意的，不是遗漏。
