# 固定卷组卷与在线作答整套实施计划总控

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在不绕过既有题目、审核和 Release 治理的前提下，依次交付手工固定卷、约束组卷、在线作答、练习评分、QTI 与上线验收。

**架构：** 以共享契约为起点，按可独立验收的垂直切片实施。每个分计划拥有自己的数据库、领域服务、API、前端和测试任务；上游阶段未通过门禁时，下游只能做契约评审，不得用模拟通过代替真实集成。

**技术栈：** Python 3.12、FastAPI、SQLAlchemy 2、Alembic、PostgreSQL 16、OR-Tools CP-SAT、Celery/Outbox、Next.js/React/TypeScript、pytest、Vitest、Playwright、QTI 3。

## 3. 面向 DeepSeek harness 的执行规则

1. **一个任务一个执行单元。** 只向执行代理提供当前任务、它直接依赖的文件和共享契约，避免一次输入整套计划后跳步。
2. **先读后写。** 代理先列出将修改的文件和测试，再开始 TDD；若实际基础接口与计划不同，先修改计划和适配器，不创建同名空壳。
3. **保留失败证据。** 每个任务先运行新测试并看到预期失败，再写最少实现；失败原因不符时不能继续。
4. **真实运行验证。** 未实际运行的迁移、数据库、前端或 E2E 测试必须标为未运行，不能写成通过。
5. **小步审查。** 每个任务完成后进行规格符合性和代码质量审查；通过后再勾选任务并进入下一任务。
6. **提交服从用户策略。** 计划中的 commit 是执行节点建议；只有用户或 harness 明确授权时才实际提交，不推送远端。
7. **不得扩范围。** 不提前实现运行时随机正式卷、IRT、在线监考或供应商特定功能。
8. **不得伪造人工行为。** 测试身份可以模拟数据库中的审核 fixture，但生产代码不能让服务账号签署 review 或 grade。

## 4. 全局阶段门禁

### 4.1 共享基线门禁

- [ ] 所有公共契约 `extra=forbid`，学生 Schema 不含答案、解析、量规和 answer_test。
- [ ] 统一错误结构、Actor 范围权限和 Idempotency-Key 生效。
- [ ] 治理适配器能识别历史 approved 后 revoked、许可失效、贡献者自审和双审同人。
- [ ] canonical hash、分值整数缩放和 UTC 时钟测试通过。
- [ ] CI 中 Schema 漂移、敏感字段和前端共享组件检查通过。

### 4.2 阶段 A 门禁

- [ ] 教师能手工完成真实 100 分固定卷，不依赖求解器。
- [ ] 候选只来自固定 Release Context 中审核有效的题目/实例。
- [ ] 整卷双复核支持两个不同 decision_seq，修改后审核失效。
- [ ] approved paper 不可原位修改，assignment_item 固定来源和实例。
- [ ] 通用 Artifact 注册与对象存储可用，但不要求向量、模型网关或智能体问答上线。
- [ ] 学生卷、答案卷和量规卷分离渲染，学生 PDF 无隐藏答案。
- [ ] 发布与撤回并发、许可失效和普通/严重纠错测试通过。

### 4.3 阶段 B 门禁

- [ ] CP-SAT 硬约束与独立整卷校验结果一致。
- [ ] `OPTIMAL / FEASIBLE / INFEASIBLE / TIMEOUT` 语义真实，不混淆可行与最优。
- [ ] 不可行不自动放松约束，超时无可行解不创建 paper。
- [ ] A/B 卷除明确锚题外无禁止重叠，分别审核和渲染。
- [ ] 练习答案发布与保密正式卷的曝光冲突能阻断。
- [ ] 1,000 候选、50 槽位验收负载有真实报告，不虚称生产 SLO。

### 4.4 阶段 C 门禁

- [ ] 重复开始不消耗额外次数，已有进行中 attempt 优先返回。
- [ ] 自动保存幂等，多标签页冲突返回 409，断线重连不静默覆盖。
- [ ] 手动交卷和到期 worker 并发只产生一个 submission。
- [ ] 截止边界使用服务端时间，提交后保存不能修改快照。
- [ ] 学生 API、SSE、日志和缓存不含答案或隐藏量规。
- [ ] 100 并发开始/保存/交卷负载及撤回测试有实际结果。

### 4.5 阶段 D 门禁

- [ ] 练习检查绑定 response_revision，自动保存不触发检查。
- [ ] `true / false / fail` 分离，CAS fail/超时/不确定不打 0。
- [ ] 练习不写正式 grade，正式成绩教师确认发布率 100%。
- [ ] 改分追加 revision，重评和申诉保留历史。
- [ ] 提示、解析和 Artifact 打开均重新执行策略与曝光检查。

### 4.6 阶段 E 门禁

- [ ] QTI 导入全部进入草稿，不继承外部审核，扩展差异不静默丢失。
- [ ] QTI 导出保持固定槽位和顺序，不绕过 Release 与许可。
- [ ] 组卷、保存、交卷、成绩和安全指标可观测，告警有 runbook。
- [ ] 安全、无障碍、备份恢复、发布回滚和试点任务有签字证据。
- [ ] 不包含 IRT、在线监考和随机正式卷的隐性承诺。

## 6. 全局完成定义

只有同时满足以下条件，才能宣称「整套功能已完成」：

- [ ] 所有分计划任务均完成，且没有以 skipped、未运行或 mock 替代的真实集成检查。
- [ ] 35 项设计验收均有自动化测试、人工验收记录或明确对应的两类证据。
- [ ] 数据库 upgrade/downgrade、RLS 非 owner 测试、worker 重试和并发竞态全部通过。
- [ ] 前端键盘、屏幕阅读器、公式预览、保存/冲突提示和打印检查通过。
- [ ] 没有学生可读的答案副本，没有服务账号人工审核，没有已发布内容原位修改。
- [ ] 监控、备份恢复、撤回、成绩改分、QTI 差异和发布回滚 runbook 可执行。
- [ ] 试点教师和学生完成真实任务；失败项已修复或阻止扩大上线范围。

## 7. 推荐执行方式

优先采用子代理驱动：每个任务使用新代理，任务后进行规格符合性与代码质量两阶段审查。若使用内联执行，则按分计划设置检查点，每个阶段结束暂停并审查实际测试输出。无论采用哪种方式，都不得跨阶段一次性生成全部代码。
