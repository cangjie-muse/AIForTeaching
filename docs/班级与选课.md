# 班级与选课

这一页回答三个问题：班级是什么、谁能操作、学生能不能只看自己选的课。

## 一、数据模型

```sql
teaching_class  一门课 + 一个学期 + 一个班名，带任课教师与创建人
enrollment      班级 ↔ 学生（学号即 app_account.id），记录是谁把学生加进来的
```

- 一个班属于**一门课**（`course_id`），不是"一个班学多门课"。中国高校的教学班通常就是
  "某门课在某学期的一个班"，作业、成绩、名单都按这个粒度走。要多门课，就建多个班。
- `(course_id, term, name)` 唯一：同一门课同一学期不许重名，否则"名单到底交哪一份"没法回答。
- 学期格式固定 `2026-2027-1`（学年-学年-学期），写错直接 400，不做模糊解析。
- `enrollment.student_id` 外键指向 `app_account(id)`，`ON DELETE CASCADE`：删账号不会留下
  幽灵选课。历史脏数据在迁移 `0015` 里先记审计再清掉，否则外键加不上去。
- 删班连带删名单（CASCADE），但审计里留了人数；删人只删这一条选课，学习记录不动。

表在 `0001` 就建好了，但一直是空壳：没有任何接口用过它。`0015` 把该有的字段补齐
（`created_by`、`added_by`、`note`、更新时间），并接上外键与唯一索引。

## 二、谁能做什么

| 动作 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 给学生发账号 / 改角色 / 停用 / 重置密码 | — | — | ✓ |
| 建班、改名、删班 | — | ✓ | ✓ |
| 把学生加进班 / 移出 | — | ✓ | ✓ |
| 看班级名单 | — | ✓ | ✓ |
| 看自己的课（课程中心） | ✓ | ✓ | ✓ |

前端：`PAGE_ROLES.classes = ['teacher', 'admin']`，学生菜单里没有这一项，直接输
`#/classes` 也只会看到"当前身份没有这个页面的权限"。
后端：`classes.py` 每个路由都 `require("teacher", "admin")`——前端藏菜单不是安全边界。
学生调 `GET /api/v1/classes`、`GET /api/v1/students` 一律 **403**，e2e 里有断言。

任课教师默认是**建班的人**；管理员建班时可以指定 `teacher_id`（必须是教师或管理员账号）。
教师目前能管理所有班级，不只是自己任课的班——`course` 表还没有"课程负责人"字段，
这一点写在[待决事项清单](待决事项清单.md)里，不假装已经隔离。

## 三、为什么现在不按班级限制学生可见范围

班级建好、名单齐了，学生**仍然看得到全部已发布课程**。这是有意的：

1. 这一版的目标是"名单与归属"——作业、成绩、学习分析以后都挂在班上，先把数据落好；
2. 一旦按选课收紧，任何漏建班的学生登录后课程中心一片空白，演示环境也会被锁死；
3. 现有 14 门课是"全开放"形态，突然改口径属于产品决策，不该顺手做掉。

要收紧的时候只改一处：`server/app/catalog.py` 里学生目录的过滤条件加
`EXISTS (SELECT 1 FROM enrollment e JOIN teaching_class c ON c.id = e.class_id
WHERE e.student_id = %s AND c.course_id = course.id)`。数据已经就位，不需要再迁移。

## 四、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/classes?course_id=&term=` | 班级列表，带人数与任课教师 |
| POST | `/api/v1/classes` | `{course_id, name, term, teacher_id?, note?}`，重名 409 |
| PATCH | `/api/v1/classes/{id}` | 改名 / 换学期 / 换任课教师 |
| DELETE | `/api/v1/classes/{id}` | 删班，返回连带移除的选课数 |
| GET | `/api/v1/classes/{id}/students` | 名单，含"由谁加入" |
| POST | `/api/v1/classes/{id}/students` | `{student_ids:[...]}`，重复加只记一次 |
| DELETE | `/api/v1/classes/{id}/students/{student_id}` | 移出名单，不在这班则 404 |
| GET | `/api/v1/students?query=` | 学生账号清单（只含学生，给加人选择器用） |

审计：`class.create` / `class.update` / `class.delete` / `enrollment.add` / `enrollment.remove`，
`entity='teaching_class'`，`detail` 里记课程、班名、学期、人数、涉及的学生 id。

## 五、一个必须知道的运维后果

班级挂在 `course(id)` 上。`python scripts/import_seed.py db/seed.sql --truncate` 会
`TRUNCATE course ... CASCADE`，**连带清空所有班级与选课记录**。

脚本现在会先数一遍并打印：

```
注意：清空课程会连带删除 3 个班级、87 条选课记录（外键 CASCADE）。学习记录与账号不受影响。
```

也就是说：重建课程内容（迁移那 14 门课、重导某个资源包）之前，先确认名单是不是还要。
真丢了只能从备份恢复——`docs/回滚与恢复.md`。

## 六、验证

- `node scripts/test-view-classes.cjs`（21 项）：学生无权限、教师建班、展开名单、加人时
  已在班的学生不再出现、班名为空/学期格式错时不提交、删班提示会移除几人。
- `npm run test:api` 的「班级与选课」段（27 项）：403、重名 409、学期 400、课程 404、
  重复加入只记一次、教师账号不能当学生塞、名单记下"由谁加入"、改名、移出、删班、审计齐全。
- 现场验证（`npm run dev:api` 之后）：教师建班 → 加学生 → 名单出现 → 学生登录仍看到 14 门课。
