# 作业拍照批改

学生拍作业照片上传，AI 先把卷面转写成文字，再逐题对照题库里的参考答案给初评；
教师复核确认后，分数才算成绩。

## 为什么分两步，而不是直接让模型打分

| 一步到位 | 两步（转写 → 判分） |
| --- | --- |
| 模型只回一句"整体基本正确"，学生不知道错在哪 | 每题都有题干、学生作答、判定、点评 |
| 认错字和判错理混在一起，查不出原因 | 转写结果落库（`submission_page.transcript`），能回看"当初识别成了什么" |
| 分数不可复核，教师只能信或不信 | 教师可以只改某一题，改的是 `teacher_score`，AI 分保留 |

实测依据：单次调用里"转写失败"是判分错误的主要来源（约 87%），所以转写阶段
禁止模型纠错、禁止补全，只准抄；判分阶段只吃文本，并以题库答案为准。

## 流程

1. 学生选课程、选照片（一页一张，最多 20 页，JPEG/PNG/WebP，单页 ≤10MB）。
2. `POST /api/v1/homework` 建提交 → `PUT /api/v1/homework/{id}/pages/{n}` 逐页上传
   → `POST /api/v1/homework/{id}/grade` 排队。
3. worker（`whu-worker`）领取 `grade-homework` 任务：每页调一次视觉模型转写 → 汇总
   → 取该课程「已发布且有参考答案」的题（最多 60 道）作为候选 → 一次文本模型调用
   做匹配与判分 → 写 `submission_item`。
4. 学生看到每题结果；教师可逐题改判，或「全部确认」。

## 成绩口径（重要）

- `submission_item.auto_score`：AI 初评，**不进成绩**，只作参考。
- `submission_item.teacher_score`：唯一能进成绩的字段。教师「全部确认」时，只把
  **还没有教师分**的题按 AI 分补上，不覆盖已改过的题。
- 页面把两个分数并排显示，未确认时写「尚未确认，仅供自测」。

## 需要配置的模型

| 用途 | 端点 | 模型例子 |
| --- | --- | --- |
| 转写卷面 | `kind='vision'`（没配则回落到对话端点） | `qwen3-vl-plus`、`glm-4.6v`、`deepseek-flash` |
| 匹配与判分 | `kind='chat'` | `deepseek-flash` |

在「模型接口配置」里新增一个用途为「视觉（作业拍照转写）」的端点即可，密钥与对话
端点共用（`secrets/<name>.key` 或 `LLM_API_KEY`）。出校域名仍需在允许清单里。

## 已知限制

- **没有匹配到题库题时**：模型只能自己推导，结果一律标 `needs_review`，界面上
  显示「题库里没有对应题，按模型自己的推导判断」。这类分数不要直接当成绩。
- **手写体识别**：连笔、潦草、反光、斜拍都会掉准确率；模型会写 `[无法辨认]`
  而不是猜，看到这个标记就重拍。
- **部分分的争议**：漏 `+C`、换元没换回来、区间端点这类，模型可能判得过宽或过严，
  所以每题都显示模型自评置信度，低于 0.6 标「识别存疑」。
- **符号等价**没有接 SymPy 校验（`+C`、`=` 的等价形式靠模型与参考答案比对），
  这是下一个该补的点。
- 教师目前能看**全部**作业（不按班级收窄），v1 有意放开，收窄时只改
  `server/app/homework.py` 里的 `_guard()`。

## 运维

- 图片落在 `uploads/homework/<submission_id>-<sha>.jpg`（`UPLOAD_DIR` 可覆盖）；
  删提交会删库里的行，**不会**删磁盘文件，定期清理按前缀找。
- 批改失败时 `submission.status='failed'` 并写 `error`，学生页面上直接显示原因；
  重试用 `POST /api/v1/homework/{id}/grade`。
- 一页一次模型调用；三页作业大约 30–60 秒。页面每 3 秒轮询一次，最多等 3 分钟。
