# 数据与服务接口约定

状态：本地页面已实现，网络端点未连接。此约定属于本项目，不依赖雨课堂私有接口。

## 内容边界

三份标准输入进入同一个 `CourseImport.parsePackage(rows, knowledgeMarkdown, exerciseMarkdown, metadata)` 解析器。Node 导入脚本和浏览器导入使用相同代码。课程源文件统一保存在 `course-packs/<课程 ID>/`；生成的结构化数据在 `data/course-*.json`，浏览器入口为 `data/courses.js`。`course-overview` 等通用一级节点锚点会按课程名称匹配规划 ID，避免多门课互相覆盖。

主要实体：

| 实体 | 核心字段 |
| --- | --- |
| Course | schemaVersion、id、title、audience、subject、description、nodes、exercises、relationships、stats、reviewStatus |
| KnowledgeNode | id、title、path、level、parentId、children、chapterId、kind、content、source、exerciseIds |
| Exercise | id、prompt、answer、difficulty、source、nodeIds；同一源 ID 内容有差异时另有 variants，逐版保存题干、答案、出处与 nodeIds |
| Relationship | source、target、type；存储的标准关系目前仅 contains，界面另从题库关联计算共题连线 |
| Resource | 相对路径及文件类型；浏览器导入保留本地 Blob |
| LearningRecord | 按 courseId 和内容 ID 保存收藏、笔记、作答、已读及自评 |
| TeachingDraft | id、type、title、description、updatedAt；仅本地草稿 |
| CoursewareVersion | courseId、chapterId、versionId、baseVersionId、slideCount、sourceSha256、files、changeLog、reviewStatus；一个章节可保留多版 |

知识点或题目 ID 仅在单门课程内唯一。跨课程引用要同时携带 courseId。课程内容与某个学期的教学班分开，避免每学期复制课程导致 ID 漂移。

## 登录与权限

身份只有三种：`student / teacher / admin`。历史角色名 `reviewer` 由 `teacher` 覆盖
（`require("reviewer")` 对教师放行），不再单独建角色。鉴权规则：
**没登录 401**（前端跳登录页），**登录了但角色不够 403**。
细则见 `docs/账号与权限.md`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/auth/providers` | 登录方式清单；`cas.available=false` 表示统一认证未接入 |
| GET | `/api/v1/auth/me` | 当前身份；未登录也返回 200，`authenticated=false` |
| POST | `/api/v1/auth/login` | `{username, password, next?}`，Set-Cookie `whu_session`（httpOnly、SameSite=Lax） |
| POST | `/api/v1/auth/logout` | 吊销会话并清 cookie |
| POST | `/api/v1/auth/password` | `{current_password, new_password}`；成功后其它会话全部失效 |
| GET | `/api/v1/auth/accounts` | 账号列表（仅管理员），`?role=&query=` |
| POST | `/api/v1/auth/accounts` | `{username, display_name, role, password?, must_change_password?}`（仅管理员） |
| PATCH | `/api/v1/auth/accounts/{id}` | `{display_name?, role?, password?, disabled?, must_change_password?}`（仅管理员） |
| GET | `/api/v1/auth/cas/login` | 统一认证入口；**当前 501**，接好 CAS 后改成 302 |
| GET | `/api/v1/auth/cas/callback` | 统一认证回调；**当前 501** |

账号行字段：`id / username / display_name / role / role_label / has_password /
must_change_password / disabled / locked / last_login_at`。**任何接口都不返回密码哈希。**

审核相关接口的权限统一为 `teacher / admin`（学生 403，未登录 401）：
`/review/summary`、`/review/queue`、`/review/queue/build`、`/review/graph`、
`/review/graph/verify`、`/review/exercises/{course_id}/{exercise_id}/revisions`、
`/review/exercises/{course_id}/{exercise_id}/verification`、`/review/ledger`、
`PATCH /review/exercises/{course_id}/{exercise_id}`、`/review/tasks/{id}/decision`。

前端闸门表在 `js/auth.js` 的 `PAGE_ROLES`，只影响菜单与页面显示；
真正的权限以后端 `require()` 为准。

## 未来网络层

`config/api-contract.json` 包含课程、验证导入、知识图谱、题库、资源、AI、教学班、作业提交、考试、课堂活动、讨论、公告、学习记录与学情的端点清单及主要输入输出。

AI 请求包含 `courseId`、可选 `nodeId` 或 `exerciseId`、question、mode、messages。返回 `answerMarkdown`、citations、model、requestId。引用应指向真实知识点、资源与来源页，不能由前端编造。

当前 AI 页运行本地关键词检索；请求不发送到外部。配置真实服务后再实现后端模型调用与检索增强，不把密钥写在 HTML、JS 或浏览器存储中。

课件生成与修订也尚未连接网络。前端目前从 `courseware/<courseId>/<chapterId>/manifest.json` 的构建索引显示已有版本，按同一层级保存 PPTX 和逐页预览。辛几何第一章的 V1—V4 是初始演示样例，V5 依据教师反馈重排为 26 页，含 27 处 Office Math 公式及文字后备；仍需教师终审。浏览器可保存针对具体版本的修改建议，但“按建议生成新版”只展示未来请求内容，不提交模型任务。未来服务按 `config/api-contract.json` 接收课程、章节、基础版本、建议、公式模式和来源哈希，异步返回任务状态；成功校验后登记不可变的新版本，保留旧版本和修改记录。生成/修订的系统约束见 `prompts/courseware-generate.md`、`prompts/courseware-revise.md`，其它 AI 待办见 `docs/AI接入任务清单.md`。

未来远程适配层应提供超时、取消、JSON 内容类型检查和统一错误结构。上传采用“验证—确认提交”两步，服务端验证必须独立执行，不能信任浏览器传来的校验通过状态。

## 需要后台保证的事项

真正的学生账号、班级隔离、习题答案可见性、作业提交、考试和成绩均需服务端授权。静态页面的角色切换或折叠答案不能提供访问控制。首版用于展示及个人练习，不处理真实多人教学数据。

学习自评与阅读行为不直接视为掌握度、成绩或 AI 判定。班级统计等待真实数据后定义口径。

## 扩展入口

普通新增课程：按同一资源包导入。若今后输入格式变化，新增带版本号的解析适配器，转换为现有 Course 数据结构；页面继续读取统一实体。

浏览器保存用于本地展示。转为正式数据库时，保留稳定 ID，分别迁移课程内容、课程资源、教学班与学习记录，避免将教材和 UI 布局硬编码到同一层。

**2026-10-21 更新：** 课程内容已按这条迁移到数据库。导入改走
`POST /api/v1/courses/{id}/content/import`（浏览器解析、服务端落库），
读取走 `GET /api/v1/courses/{id}/content`，导出走 `…/content/export`。
浏览器 IndexedDB 只保留给历史数据，不再是导入的存储。详见
[课程内容工作台.md](课程内容工作台.md)。

**2026-10-21 更新（可见范围）：** 学生端能不能看到一道题，不再只由发布决定。
新增一道按"验证等级"过滤的闸：

- `GET /api/v1/visibility` —— 读当前范围（习题 / 问答两档）、各等级题量、
  每一档会放出多少道已发布题；公开可读，参数 `course_id` 只用于统计。
- `PUT /api/v1/visibility` —— 改范围，`{exercise_tier, qa_tier, note?}`，
  取值 `human | verified | all`，需要 `teacher / reviewer / admin`，
  写 `audit_log(action='visibility.update')`。

`GET /api/v1/catalog`、`GET /api/v1/catalog/{id}` 已按该范围过滤题目与统计；
`POST /api/v1/qa/ask`（`mode=full`）在作答解锁之后再加一道等级检查。
细节与 Lean 那一层的现状见 [审核分层与可见范围.md](审核分层与可见范围.md)。

课程列表有两个口径，别混：

- `GET /api/v1/courses` —— 库里**全部**课程（含未发布、含知识点/习题计数）。教师端选课、审核页的课程下拉用它。
- `GET /api/v1/catalog` —— 只返回**已发布**课程，学生端目录用它。前端启动时先问前者"库里有哪些课"，
  再取后者的正文：库里没有的静态课程一律不显示，未发布的课学生看不到、教师端列成「建设中」。
  规则与迁移步骤见 [数据来源与课程导入.md](数据来源与课程导入.md)。

口径分两级（`0012`）：全局默认 + 课程覆盖，接口用查询参数区分作用域：

- `GET /api/v1/visibility[?course_id=…]` —— 返回生效口径 `effective`、来源 `source`
  （`course / global / default`）、`global` 与 `override` 各一份、各等级题量、
  每一档会放出多少题、图谱节点统计，以及课程清单（谁有单独设置）。
- `PUT /api/v1/visibility[?course_id=…]` —— `{exercise_tier, qa_tier, graph_tier, note?}`；
  带 `course_id` 是给这门课单独设置，不带是改全局默认。
- `DELETE /api/v1/visibility?course_id=…` —— 取消这门课的单独设置，回到跟随全局。

知识图谱只有人工一档（`graph_tier = all | human`）。审核接口：

- `GET /api/v1/review/graph[?course_id=…]` —— 知识图谱审核数据：
  - `chapters[]`：真正的章（`level = 2` 的节点，如数学分析 II 是 10 章），
    字段 `chapter_id / title / nodes`（章内知识点数，不含章自己）/ `verified` / `self_verified`；
  - `nodes[]`：章内全部节点，`id / chapter_id / parent_id / title / kind / level /
    verified / verified_at / verified_by`，供审核页按章节树渲染；
  - `root`：课程根节点（`level = 1`）的 `id / title / verified`，单列以免变成一张同名章节卡片；
  - **不传 `course_id` 时 `chapters`/`nodes` 为空、`root` 为 null**，只回 `totals`
    （14 门课 4146 个节点，不适合一次全吐）。
  - 章节归属按 `parent_id` 往上走到 `level = 2` 得出。**不要用 `knowledge_node.chapter_id`**：
    真实导入数据里这一列是空的，按它分组会让一门课出现 135 个"章"。
- 节点管理（都需要 `teacher / reviewer / admin`，学生 403）：
  - `GET /api/v1/review/nodes/{course_id}/{node_id}` —— 节点 + 祖先链 + 子节点 + 挂着的题；
    改标题/删除影响的题数看 `counts.subtree_exercises`；
  - `POST /api/v1/review/nodes/{c}/{n}/exercises` `{exercise_ids}` —— 按知识点挂题（幂等）；
  - `DELETE /api/v1/review/nodes/{c}/{n}/exercises/{exercise_id}` —— 解绑（不删题）；
  - `DELETE /api/v1/review/nodes/{c}/{n}` —— 删节点。有子节点或挂着题时回 **409**，
    正文是对象：`{detail, node_id, title, nodes, exercises, subtree[], exercise_ids[]}`，
    确认后带 `?cascade=true` 才真删。课程根节点（`level = 1`）不能删（400）；
  - `GET /api/v1/review/node-options?course_id=&q=` —— 习题侧联想用的扁平知识点；
  - `GET /api/v1/review/exercise-options?course_id=&q=` —— 节点侧挂题用的候选题目。
- **挂载一变就重置**：以上四个写动作、以及 `PATCH /courses/{c}/nodes/{n}` 改标题、
  `PATCH /review/exercises/{c}/{e}` 带 `node_ids`，都会把受影响的题退回未核
  （清 `human_verified_at/by`，已发布的保持 published，其余回 draft），写
  `audit_log` 的 `exercise.mount-reset`。同一次请求里既改挂载又 `human_verified: true` 时，
  以确认后的状态为准（先重置再写回）。
- `POST /api/v1/review/graph/verify` —— `{course_id, chapter_id 或 node_ids, action: verify|unverify}`，
  批量写 `knowledge_node.human_verified_at`，需要 `teacher / reviewer / admin`。
  **会连同整棵子树一起标**（递归 CTE）：只标记容器会让学生端看到"有章无节"的断树；
  整门课通过就传课程根节点的 `id` 作为 `node_ids`。

教材片段与知识点正文**不设审核**（原文转载），只受版权状态约束。

单题审核记录（查"这道题标注过什么"）：

- `GET /api/v1/review/exercises/{course_id}/{exercise_id}/verification` ——
  返回 `tier`、人工审核时间/人、`proofs[]`（Lean 逐条）、`content_version`、
  `edited_after_review`（审核后被改过）、最近一次 `task`、`lean_available`。
  教师/审核员/管理员可读，学生 403。已发布的题不在审核队列里，要靠这个接口查。
- `GET /api/v1/review/ledger?course_id=&tier=&question=&limit=&offset=` ——
  课程审核总表：这门课全部题目（含已发布）的等级、人工审核、Lean、工作流与审核任务状态，
  带各档总数与分页。未审核排最前；教师/审核员可读，学生 403。
- `GET /api/v1/courses/{id}/content` 的习题行现在带 `tier` 与 `human_verified_at`，
  知识点行带 `human_verified_at`——内容页据此显示审核徽标。

### 班级与选课

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/classes?course_id=&academic_year=&term_kind=` | 班级列表（含人数、任课教师） |
| POST | `/api/v1/classes` | `{course_id, name, academic_year, term_kind, teacher_id?, note?}`；同学期重名 409 |
| PATCH | `/api/v1/classes/{id}` | 改名 / 换学期 / 换任课教师 |
| DELETE | `/api/v1/classes/{id}` | 删班，返回连带移除的选课数 |
| GET | `/api/v1/classes/{id}/students` | 名单（含 `added_by`） |
| POST | `/api/v1/classes/{id}/students` | `{student_ids:[...]}`，重复加入只记一次 |
| DELETE | `/api/v1/classes/{id}/students/{student_id}` | 移出名单；不在这班返回 404 |
| GET | `/api/v1/students?query=` | 学生账号清单（只含学生） |

全部 `require("teacher", "admin")`，学生 403。

学期用两个字段：`academic_year`（`2026-2027`，必须是连续两学年）+ `term_kind`
（`秋`/`春`/`夏`），写错 400。返回里另有 `term` 是显示文案（`2026年秋季学期`、
`2027年春季学期`）——前端显示文案、提交结构字段，别再手打学期字符串。
写操作审计为 `class.create / class.update / class.delete / enrollment.add / enrollment.remove`。
模型与取舍见[班级与选课.md](班级与选课.md)。
