## 习题三维标签：难度 × 来源 × 可信度（2026-10-22 第四轮）

口径来自提问「我的习题库分三个层次，有这些标签可以打标」，选择是**三个维度都要，标签是组合**。

做法与不做法都说明一下：**没有建标签表，也没有 `exercise.tags` 列**。三个维度本来就是
`difficulty` / `provenance` / `v_exercise_verification.tier` 三个已有字段，存一份标签就会
出现"字段改了标签没改"的分裂。组合只有 3×6×4 = 72 种，现算的代价可以忽略。

| 轴 | 取值 | 来源 |
| --- | --- | --- |
| 难度档 | 基础 1–2 / 中等 3 / 挑战 4–5 | `exercise.difficulty` |
| 来源 | 教材原题 / 同事导出 / 平台自拟 / 模型生成 / 网上搜集 / 来源未标 | `exercise.provenance` |
| 可信度 | 双证已核 / 人工已核 / Lean 已验 / 未核 | `v_exercise_verification.tier` |

接口把 `tags.labels`（三枚徽标）、`tags.codes`（筛选代码，永远是字符串）、`tags.text`
（供搜索）一起发出去，学生端目录与内容工作台共用同一份派生逻辑。

真数据分布（复变函数 402 道，走 `/api/v1/courses/complex-analysis/content`）：

| 组合 | 道数 |
| --- | --- |
| 中等 · 教材原题 · 人工已核 | 107 |
| 挑战 · 同事导出 · 人工已核 | 100 |
| 中等 · 同事导出 · 人工已核 | 63 |
| 基础 · 教材原题 · 人工已核 | 48 |
| 挑战 · 教材原题 · 人工已核 | 35 |
| 基础 · 平台自拟 · 人工已核 | 17 |
| 基础 · 同事导出 · 人工已核 | 17 |
| 中等 · 平台自拟 · 人工已核 | 14 |
| 挑战 · 平台自拟 · 人工已核 | 1 |

九种组合、402 道，无一道落进"未知"兜底，说明三列字段没有空值。

测试：`npm run check` 660 项（原 620，新增 40 项标签单测）；`npm run test:api` 472 项（原 468）。
视图测试新增 12 项，其中 3 项守的是**老数据没有 `tags` 时页面必须退化成原样**——
升级不能把没打标的课程变成空白页。

未验证：
- 浏览器里的实际观感（三枚小徽标在窄屏会不会挤成两行、五个筛选框在 1024 宽下是否溢出）。
  本机没有浏览器自动化，只做到 DOM 结构与筛选行为这一层。
- 可信度这一维在真数据里没有区分度：402 道全是「人工已核」。要看到「未核」的题，
  得先有一批未审核的导入。
- 自由打标（"含参讨论""易错"）没有做，那是另一张表的事，见数据模型 §3.5。

## AI 问答：知识点正文先入库（2026-10-22 第三轮）

用户的提问是「ai问答界面说暂时没有知识片段，但是我们不是有教材知识点吗，是还要继续处理吗」。
查下来不是检索坏了，是**检索的原料是 0 行**：问答只查 `textbook_chunk`，而切片一直
按约定搁着，14 门课一本教材都没入库。知识图谱的 4485 个知识点在另一套表里，从来没进过问答。

按「全部 14 门课都切」的决定，做的是"知识点正文 → 问答语料"这一层。数字如下：

| 指标 | 值 |
| --- | --- |
| 入库课程 | 14 门 |
| 知识点（有正文） | 4485 个 |
| 切成片段 | **4590 块** |
| 重建耗时 | 8.5–14.2 秒（全量） |
| 引用是否带页码 | **不带**，改标「知识点「标题」（完整路径）」 |

为什么不留页码：知识点溯源里写的是"书页197起"，那是章节起页，不是这个知识点所在页。
拿它当引用页码就是给每条回答盖错章，宁可不写。

本轮真跑出来的四个问题（都是拿真课程数据、走真接口）：

| 问题 | 结果 |
| --- | --- |
| 数列上极限的定义是什么（数学分析I） | 命中「上极限」，随后柯西收敛准则、定义、下极限 |
| 最小二乘问题有哪些解法（数值线性代数） | 命中 CGLS、线性最小二乘问题、LSQR、Tikhonov、三种解法的首项工作量 |
| 图神经网络里消息传递是怎么做的（神经网络） | 拒答（这门课确实没有这个概念的知识点） |
| 秋天的银杏叶为什么会变黄（数学分析I） | 拒答 |

拒答这两条不是失败，是要的行为：没有依据就说没有，不猜。

### 调这一层时踩到的三件事（都写进代码注释了）

1. **章节容器抢位**。第一次跑「QR 迭代与同时幂法」，6 条引用里 4 条是同一章的四个片段，
   内容全是"本章包含以下子主题"的链接清单——命中词多，但答不了问题。改成
   `node_kind='knowledge'` 优先，章节降权不排除（有些问题只有章节级内容能命中）。
2. **同一知识点切多块会占满 top-k**。加 `DISTINCT ON (node_id)`，一个知识点只留最相关的一块。
3. **只取 3 字滑窗太窄**。「上极限」被切成「数列上 / 上极限 / 限的定」，命中面很小；
   改成 2 字滑窗（步长 1）+ 4 字窗，并加「至少命中两个词」的证据门槛——
   只命中一个词不算依据。另外片段正文开头补了知识点标题，因为正文里常写"它的"这种指代，
   标题本身才是检索词（问"同时幂法"，正文可能一次都没出现）。

### 界面上看得见

「模型配置」页（`#/api-config`）多了一块「问答语料」：每门课几个知识点有正文、
切了多少块、是否已入库，右上角一个「全部重建」（仅管理员可点，教师/审核员只读）。
放在这一页是因为语料和模型端点是一件事的两半——端点决定"能不能调用"，
语料决定"有没有东西可引用"。之前那页会拒答，界面上却完全看不出原因，
这个面板就是为这件事加的。

### 验证

- `npm run check`：ESLint + 视图测试 + Python 静态检查全通过。
- `npm run test:view`：问答页引用标签新增"知识点"形态（无页码、带完整路径 title）。
- `npm run test:api`：**468 项通过**（原 447 项），新增 21 项覆盖：重建接口、幂等、
  权限（学生看不了状态、教师不能重建）、检索命中知识点片段、引用 `page is null` /
  `kind='node'` / `node_id` 落库、课程 `chunk_count`、审计、不存在的课程 404。
- `server/tests/test_qa_ingest.py`：16 项切块单测（空文本、短文本、段落合并、
  900 字上限、行间公式不被切断、尾块合并、幂等）。

**未验证**：真实模型回答。本机 `DEV_FAKE_MODEL=1`（演示模式），
且 `model_endpoint` 表为空、`.tmp/dev-secrets` 无密钥；强行关掉演示模式会拿到
`模型返回 401：Authentication Fails`。要真答得在「模型配置」里填可用的 Key。
演示模式的回答文本已改成按知识点标出处（不再印"第 None 页"）。

## 知识图谱：在画布上直接改结构（2026-10-22 第二轮）

上一轮把编辑面板搬到了图谱页，但搬成了一块**页面底部的表单**。用户的反馈很直接：
「修改的功能不能直接加在图谱的画布和表格中吗，右边有一个编辑按钮的开关，点击后就直接在图上修改，然后提交。」
于是一屏之内改了两件事：编辑入口上移到右上角当开关，改结构的主要动作挪回画布。

| 手势 | 落到哪 | 立即生效还是攒批 |
| --- | --- | --- |
| 双击章 / 节 / 知识点改名 | 输入框浮在节点上（`#net-rename`），回车收进草稿 | 攒批 |
| 拖知识点到章/节 | `G.draftMove` 记草稿，虚线预览 + 目标高亮 | 攒批 |
| 点节点 | 右栏 `#network-detail` 渲染 `js/review-node.js` 的面板 | 表单里各动作即时 |
| 表格 / 清单里点知识点 | 编辑模式下改走 `network-edit-point`，开右栏表单 | 即时（表单） |
| 提交 / 放弃 | 顶部浮条 | 逐条 `PATCH`，失败停在那条 |

具体改动：

- `js/graph-view.js`：新增编辑态（`A.state.networkEdit` = 开关 + `drafts` + `busy` + `error`）、
  顶部浮条、草稿层（`#net-drafts`）、就地改名、`submitDrafts/discardDrafts`、
  本地模型补丁（`applyLocal` / `retitleSubtree` / `moveLocally` / `subtreeIds`）；
  **删掉了 `#network-edit` 那块底部面板**，右栏 `#network-detail` 现在既显示只读详情也显示编辑表单。
- `js/graph-interaction.js`：编辑模式下拖动改为"改归属"（`G.reparent`），双击改为就地改名，
  不再自由摆放节点；普通模式下行为不变。
- 章、节也能双击改名：它们单击本来是"进入下一层"，所以编辑模式下 `G.select` 对容器
  先压 260ms（`enterLater`），第二击到了就 `cancelEnter` 并改名。课程根节点不参与
  （根名等同课程名，改它应该走课程设置）。
- `js/graph-atlas.js`：`render(course, escape, {edit})`，编辑模式下点位点开右栏表单。
- `js/review-node.js`：改标题 / 移动 / 删除成功后调 `A.networkLocalChange(...)`，
  画布的内存模型跟着走（否则改完画布上还是旧标题、删掉的节点还挂在图上）。
- `js/graph-view.js` 的 `A.after.graph`：整页重画后把 camera 与选中节点接回来（原来每改一次
  画布就跳回"适应画布"），并处理换课清草稿、深链自动进编辑模式。

验证（本机）：

| 命令 | 结果 |
| --- | --- |
| `npx eslint js scripts/test-view-graph-edit.cjs` | 通过（0 error；函数复杂度 / 嵌套层数都在预算内） |
| `npm run check` | 通过（`scripts/test-view-graph-edit.cjs` 重写为 **52 项**） |
| `npm run test:view` | 通过 |
| `npm run test:api` | **447 项**通过（后端本轮没改，回归确认） |
| 静态服务检查 | dev API 正在返回 `graph-view.js?v=0.16` / `graph-interaction.js?v=0.13` / `graph-atlas.js?v=0.12` / `review-node.js?v=0.3` / `network.css?v=0.11.9` |

视图测试覆盖的是会出错的那一半：开关的学生/教师可见性、双击后回车记成草稿（且不发请求）、
空标题与 Esc 不记、拖动的命中判定（只有容器能当目标）、提交顺序（先改名后移动）、
提交成功后的本地模型（标题 / `parentId` / `level` / `path` / 连线）、
失败时停在哪一条且已成功的仍生效、放弃清空、点节点开的是右栏表单、换课外的本地同步。

**未验证**：真机浏览器里的手感——拖动跟手程度、缩放后改名输入框的落点、虚线预览在
大图上的可读性、窄屏浮条的折行。本机没有浏览器自动化，这几项只能人眼过一遍；
代码里的坐标换算是 `(viewBox - camera) / scale` 再乘 SVG 的屏幕缩放，逻辑有测试但像素没验证。

**还没做**（保留上一轮的两条）：真正的「学生视角切换」（只画已审节点）；
用键盘完成"换归属"（现在下拉可达，拖动不可达）。

## 知识图谱：审核页只审不改、编辑搬到图谱页（2026-10-22）

起因是用户的一句判断：「知识图谱的内容和内容审核中的知识图谱是否重叠了」。
确实是同一棵树的两套界面：图谱页只读（连"未审"都显示不出来），审核页既审又改。
定下来的分工是**图谱页是结构工作台，审核页只审不改**。

| | 知识图谱页 `#/graph` | 内容审核页 `#/review` |
| --- | --- | --- |
| 谁看 | 学生（只读）+ 教师/管理员 | 教师/管理员 |
| 做什么 | 改标题、挂题、解绑、换父节点、删节点 | 通过 / 撤销、整章通过、整门课通过 |
| 显示 | 每节点已审/未审、整门课「未审 N / M」 | 逐行状态与挂题数、去图谱页的深链 |

具体改动：

- 节点编辑面板（`js/review-node.js`）从审核页搬到图谱页的知识点详情里，
  原地展开在 `#network-edit`（第二轮把它换成"画布上直接改"，`#network-edit` 已删除，见上一节）；
  审核页每行只留「去图谱里改」（`?node=` 深链，到了就打开面板）。
- `PATCH /courses/{c}/nodes/{n}` 新增 `parent_id`（换父节点）：整棵子树重算 `level`/`path`，
  三道闸（目标必须是容器、不能成环、最多 6 层）。节点详情新增 `move_targets`，
  前端用它渲染下拉。
- 修掉一个**会让审核结论失真**的缺陷：原来改标题只重置挂着的题，`knowledge_node.human_verified_at`
  不动——节点改完名还顶着绿色的「已通过」。现在改标题会连节点自己的审核标记一起清掉。
- 图谱页的「未审」标记来自 `/review/graph`，和审核页**同一个数据源**（原来图谱页读
  `/courses/{id}/content`，那套模型连 `verified` 都没有，所以显示不出未审）。

验证（本机）：

| 命令 | 结果 |
| --- | --- |
| `npm run check` | 通过（含新增 `scripts/test-view-graph-edit.cjs` 11 项） |
| `npm run test:view` | 通过 |
| `npm run test:api` | **447 项**通过（原 433，新增 14 项：移动、成环、非容器、404、空串、标题重置、学生 403、审计） |
| 手工 smoke | 登录 admin → 移动一个知识点再搬回，接口 200、`level`/`path` 按预期变化 |

**未验证**：真机浏览器里的实际点击与视觉（面板高度、下拉在窄屏的折行、
画布选区与面板的联动）。本机没有浏览器自动化，这一层只有 `node:vm` 的视图测试
和接口测试作证据，像素级效果需要人眼过一遍。

**还没做**：真正的「学生视角切换」（只画已审节点）。现在的折中是给教师一个
「未审 N / M」的计数和逐节点徽标；按已审过滤要动 `js/graph-model.js` 的构图与共享题边，

## 账号 / 班级 / 名单的 Excel 导入导出（2026-10-22）

需求原话是「创建账号和创建班级，新加学生，这些增加 excel 表格导入导出功能」。
三个入口都做了导入 + 导出 + 模板下载，**先预览再落库**。

| 入口 | 导入 | 导出 | 模板 |
| --- | --- | --- | --- |
| 账号（管理员） | 账号/姓名/角色/初始密码 | 账号/姓名/角色/状态/登录方式/最近登录/创建时间 | 有 |
| 班级（教师） | 课程/班级名称/学年/学期/任课教师/备注 | 同上 + 人数 | 有 |
| 名单（教师） | 学号/姓名/初始密码 | 学号/姓名/加入时间/加入人 | 有 |

**自动建号**（用户已定）：名单里出现库里没有的学号、又填了姓名时，自动建学生账号，
随机初始密码（去掉 `0O1lI`）、首次登录强制改密，并给一张「初始密码发放表」下载。
没填姓名则报错——不建无名账号。

实现上分了三层，各管一件事：

- `js/xlsx-sheet.js`：读（含前缀非法的 xlsx 兜底）与写（表头样式、冻结首行、中文列宽、
  第二页填写说明），只认 `.xlsx`；
- `js/roster-io.js`：三种表的表头规格、预览表、结果表、密码表、导出列，一套代码三处复用；
- `server/app/imports.py`：三个接口，`dry_run` 与真导入共用同一段校验。

验证：

    数字学号不走样、工作表名超 31 字截断、假文件报错而不是返回空表；
  - `scripts/test-view-roster-import.cjs`（24 项）：表头乱序映射、缺列提示、真实行号、

    名单导入打到当前班、请求失败把原因写页面上、取消回到初始态；

  手填密码不强制改密、班级学年不连续被拦、同班重名跳过、名单自动建号并只回一次密码、
  重复导入跳过、审计 `account.import / class.import / enrollment.import`、空表 400。

**未验证**：本机没有浏览器自动化，**没有真的在浏览器里点「选择文件」**，所以"选完文件出预览"
这一步的鼠标级行为、下载下来的文件在 Excel/WPS 里打开的样子**未逐像素看过**。

填两行 → 选择文件 → 对着预览确认。

## 图谱改树状表、节点可改/可挂题/可删（2026-10-21 夜）

接上一轮：章里的节点从"一串行"改成**树状表**——缩进 + 导引线表现层级，右侧固定列显示

**"重置"的口径**（这条是本轮最需要说清的决定）：挂载或知识点标题一变，受影响的题
