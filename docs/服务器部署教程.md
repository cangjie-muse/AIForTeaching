# 服务器部署教程

这份是**操作手册**：一台空服务器从零到能登录、以后怎么更新、出问题先看哪里。
为什么这么设计（选型、出校策略、embedding 维度）写在
[服务器部署与迁移指南](服务器部署与迁移指南.md)，两份不重复。

适用：Ubuntu 22.04 / 24.04 / 26.04，单机部署，全新或已有 PostgreSQL 都可以。
本文按 `115.156.72.1`、用户 `aiformath`、目录 `/home/aiformath/AIForTeaching` 写，
换机器时把这三处替换掉即可。

---

## 0. 先看清这套东西由什么组成

| 组件 | 是什么 | 端口 | 谁在跑 |
| --- | --- | --- | --- |
| 前端 | 纯静态文件（`index.html` + `js/` + `styles/` + `assets/` + `vendor/`） | 80/443 | **nginx 直接发** |
| 后端 | FastAPI（`/api/v1/*`），代码在 `server/app/` | 127.0.0.1:8000 | systemd：`whu-teaching` |
| 数据库 | PostgreSQL + pgvector | 127.0.0.1:5432 | 系统服务：`postgresql` |
| 生成 worker（可选） | 教材 → 知识点/习题 的异步任务 | 无 | systemd：`whu-worker` |
| 上传目录 | 教材 PDF 与抽出的 markdown | — | `uploads/` |

三件必须记住的事：

1. **`APP_ENV=prod` 时后端不托管前端**。`server/app/main.py` 只在非 prod 下挂静态目录，
   所以 nginx 必须自己发 `index.html`。只起 uvicorn 时首页 404、API 正常，是这个原因。
2. **`db/seed.sql` 不在 git 里**（12 MB，由 `data/course-*.json` 现场生成）。
   服务器上 clone 下来必须**先生成再导入**。
3. **问答语料也不在 seed 里**。seed 只带知识点正文，`textbook_chunk` 是空的，
   必须跑一次 `scripts/rebuild_qa_corpus.py`，否则 AI 问答一直说"暂时没有知识片段"。

数据都存在哪：

| 数据 | 位置 | 备份 |
| --- | --- | --- |
| 课程、知识点、习题、账号、审核、问答记录 | PostgreSQL 库 `whu_teaching` | `deploy/backup.sh` |
| 教材 PDF、抽取的 markdown | `uploads/` | 定期 rsync |
| 模型 API Key | `SECRETS_DIR`（默认 `secrets/`，**不入库**） | 单独搬，权限 600 |
| 代码 | git 仓库 | GitHub |

## 1. 一次装完基础环境

```bash
cd /home/aiformath
git clone https://github.com/cangjie-muse/AIForTeaching.git
cd AIForTeaching
bash deploy/bootstrap.sh
```

它做四件事：装系统包（python/nginx/postgresql/build 工具）→ 装 pgvector（系统包没有就源码编译）
→ 建 `.venv` 并装 Python 依赖（先试清华镜像，失败回退官方源）→ 生成 `db/seed.sql`。

先只看缺什么、不动系统：

```bash
bash deploy/bootstrap.sh --check
```

**如果 GitHub 拉不下来**（校园网常见），改用 MobaXterm 的 SFTP 上传：

1. 本地把仓库打成 zip（排除 `.venv`、`.tmp`、`node_modules`、`.git`）；
2. 拖进 `/home/aiformath/`；
3. `unzip AIForTeaching.zip && mv AIForTeaching-main AIForTeaching`，再跑 `bootstrap.sh`。

装完后自检一下：

```bash
.venv/bin/python -c "import fastapi, uvicorn, psycopg, pgvector; print('依赖 OK')"
ls -lh db/seed.sql
```

## 2. 建库与扩展

```bash
sudo -u postgres psql <<'SQL'
CREATE ROLE whu LOGIN PASSWORD '换成你的口令';
CREATE DATABASE whu_teaching OWNER whu ENCODING 'UTF8' TEMPLATE template0;
SQL

# 扩展必须由超级用户建，普通角色会 permission denied
sudo -u postgres psql -d whu_teaching <<'SQL'
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
SQL

# 中文排序：不设的话"张"会排在"李"前面，教师端列表看着像乱序
sudo -u postgres psql -d whu_teaching -c "ALTER DATABASE whu_teaching SET lc_collate = 'zh-x-icu';"
```

三个容易踩的点：

- `TEMPLATE template0` 不能省。模板库带别的 locale 时，`lc_collate` 会建不进新库。
- 如果 `sudo -u postgres` 报 peer 认证失败，用 `sudo -i -u postgres psql`。
- 数据库**只监听 127.0.0.1**，不要改成 `0.0.0.0`，也不要放行 5432。

## 3. 建表、导入课程、建管理员、生成语料

```bash
export DATABASE_URL='postgresql://whu:你的口令@127.0.0.1:5432/whu_teaching'

# 3.1 建表：17 条迁移，逐条记版本与校验和
.venv/bin/python db/migrate.py --apply
.venv/bin/python db/migrate.py --status        # 期望：17 条全部「已应用」

# 3.2 导入 14 门课（整脚本一个事务，失败全回滚）
.venv/bin/python scripts/import_seed.py db/seed.sql
# 期望：课程 14、习题 4807、知识点 4485

# 3.3 第一个管理员（交互式输口令，自动标记"首次登录必须改密"）
.venv/bin/python scripts/create_admin.py --username admin

# 3.4 知识点正文 → 问答语料（14 门课约 4590 块，十几秒）
.venv/bin/python scripts/rebuild_qa_corpus.py
```

三个禁令：

- **服务器上不要加 `--pglite-compat`**。那是给本机 WASM 版 PostgreSQL 用的，
  加了会把 `embedding` 降级成 `jsonb`，向量检索废掉，事后要重建整列。
- **不要用 `psql -f db/seed.sql`**。它边执行边提交，中途出错会留半截数据。
- **不要在生产库跑 `scripts/dev_seed_accounts.py`**。它塞的是文档里的默认口令（等于后门），
  `APP_ENV=prod` 时它会自我拒绝并指向 `create_admin.py`。

## 4. 配置环境变量

```bash
cp deploy/env.example .env
chmod 600 .env
nano .env
```

必改的只有四项，其余保持默认即可：

| 项目 | 值 | 不改的后果 |
| --- | --- | --- |
| `DATABASE_URL` | 第 2 步建的口令 | 连不上库，服务起不来 |
| `CORS_ORIGINS` | `https://你的域名`（或先用 `http://115.156.72.1`） | preflight 判阻断 |
| `LLM_API_KEY` | DeepSeek / Kimi / 百炼任一 | 问答报 502，其余功能正常 |
| `UPLOAD_DIR` | `/home/aiformath/AIForTeaching/uploads` | 教材上传写不进去 |

`APP_ENV=prod`、`AUTH_MODE=password`、`DEV_FAKE_MODEL=0` 三行不要动：
prod + dev 身份、或 prod + 演示模式，都会被 preflight 直接判阻断，理由写在
[服务器部署与迁移指南 §1](服务器部署与迁移指南.md)。

```bash
mkdir -p uploads secrets
chmod 700 secrets
```

## 5. 起后端（systemd）

```bash
sudo cp deploy/whu-teaching.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now whu-teaching

systemctl status whu-teaching --no-pager | head -12
curl -s http://127.0.0.1:8000/api/v1/health
```

健康检查返回 `{"ok": true, ...}` 才算起来。起不来就看：

```bash
sudo journalctl -u whu-teaching -n 60 --no-pager
```

最常见的三条：`.env` 里 `DATABASE_URL` 口令错、`EnvironmentFile` 路径写错、
`WorkingDirectory` 不是 `…/server`（那样 `app.main:app` 导入不到）。

教材生成任务需要 worker（不跑也不影响浏览与问答）：

```bash
# 可选：让"上传教材 → 生成知识点/习题"的队列真的被消费
sudo tee /etc/systemd/system/whu-worker.service >/dev/null <<'UNIT'
[Unit]
Description=WHU teaching generation worker
After=network.target postgresql.service whu-teaching.service

[Service]
User=aiformath
WorkingDirectory=/home/aiformath/AIForTeaching
EnvironmentFile=/home/aiformath/AIForTeaching/.env
ExecStart=/home/aiformath/AIForTeaching/.venv/bin/python scripts/run_worker.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload && sudo systemctl enable --now whu-worker
```

## 6. 起前端（nginx）

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/whu-teaching
sudo sed -i 's/math.example.edu.cn/_/' /etc/nginx/sites-available/whu-teaching   # 还没域名时先用 IP
sudo ln -sf /etc/nginx/sites-available/whu-teaching /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
curl -sI http://127.0.0.1/ | head -3          # 期望 HTTP/1.1 200
```

配置里三行不能删，每一行对应一个"看起来正常、其实坏了"的症状：

| 配置 | 删掉的症状 |
| --- | --- |
| `client_max_body_size 300m;` | 教材 PDF 一上传就 413（默认 1 MB） |
| `proxy_set_header X-Forwarded-Proto $scheme;` | 后端以为在 http 上，Secure cookie 不下发：登录成功、一刷新掉线 |
| `location ~ ^/(secrets\|db\|server\|scripts\|deploy\|\.env\|\.tmp\|uploads)/ { deny all; }` | 密钥、seed 脚本、后端源码、原始 PDF 都能被直接下载 |

防火墙（如果开着 ufw）：

```bash
sudo ufw status
sudo ufw allow 80,443/tcp
```

## 7. 验收清单

按顺序跑，每项都有明确预期；有一项不对就先修，别继续。

| # | 命令 | 预期 |
| --- | --- | --- |
| 1 | `curl -s http://127.0.0.1:8000/api/v1/health` | `{"ok": true, ...}` |
| 2 | `curl -s http://127.0.0.1/api/v1/health` | 同上（证明 nginx 反代通了） |
| 3 | `curl -sI http://127.0.0.1/` | `200`，`Content-Type: text/html` |
| 4 | 浏览器打开 `http://115.156.72.1/` | 课程中心能看到 14 门课 |
| 5 | 用第 3.3 步的 `admin` 登录 | 强制改密 → 进后台 |
| 6 | `#/api-config` 页 | 「问答语料」显示 14/14 门、约 4590 块 |
| 7 | 任意课程 → 习题与测验 | 题卡上有三枚标签（难度档 / 来源 / 可信度） |

## 8. 配模型（两条路，选一条）

**A. 环境变量（推荐，改完重启生效）**

```bash
nano .env    # 填 LLM_API_KEY / EMBEDDING_API_KEY
sudo systemctl restart whu-teaching
```

**B. 管理页（免 SSH，密钥落到 `SECRETS_DIR`）**

登录后进 `#/api-config`，新建/编辑端点并填 Key。Key 写到
`secrets/<name>.key`（权限 600），数据库里只存路径，`api_endpoint` 视图
读不到密钥本身——这样导库、只读副本都不会把 Key 带走。

填完在页面上点「自检」，能返回模型回复才算通。**没有 Key 时问答返回 502**，
此时先别把问答入口推给学生。

## 9. 日常运维

### 9.1 更新代码

```bash
cd /home/aiformath/AIForTeaching
bash deploy/update.sh --dry-run     # 先看会更新哪些提交
bash deploy/update.sh               # 拉取 → 装依赖 → 跑迁移 → 重启 → 自检
bash deploy/update.sh --with-corpus # 知识点正文变了才需要（会整体替换语料）
```

脚本存在的意义是**不漏第三步的迁移**。手工更新跳了它，症状是"某个接口突然 500"，
而不是"迁移没跑"，排查很久。

### 9.2 备份

```bash
bash deploy/backup.sh                 # 写到 ~/backup，保留 30 天
bash deploy/backup.sh --dir /mnt/bak  # 放另一块盘更好
bash deploy/backup.sh --verify-only   # 校验最新一份能否被 pg_restore 读出目录
```

装进 cron（每天 3:20）：

```bash
crontab -e
20 3 * * * cd /home/aiformath/AIForTeaching && bash deploy/backup.sh >> ~/backup/backup.log 2>&1
```

恢复步骤见 [回滚与恢复](回滚与恢复.md)。**只备份不恢复演练 = 没备份。**

### 9.3 常用命令

| 目的 | 命令 |
| --- | --- |
| 看服务状态 | `systemctl status whu-teaching` |
| 看日志（跟随） | `sudo journalctl -u whu-teaching -f` |
| 看最近 200 行 | `sudo journalctl -u whu-teaching -n 200 --no-pager` |
| 重启 | `sudo systemctl restart whu-teaching` |
| 改完 nginx | `sudo nginx -t && sudo systemctl reload nginx` |
| 看迁移状态 | `.venv/bin/python db/migrate.py --status` |
| 看语料状态 | 登录后 `#/api-config`，或 `curl -b cookie /api/v1/admin/qa-corpus` |
| 手工重建一门课语料 | `.venv/bin/python scripts/rebuild_qa_corpus.py --course analysis` |

### 9.4 十分钟排障表

| 症状 | 先查 | 多半是 |
| --- | --- | --- |
| 首页 404，API 正常 | `ls index.html`；nginx `root` 指向 | `APP_ENV=prod` 下后端不发静态站，nginx 没托管 |
| 首页空白、控制台 404 | `curl -I http://IP/js/app.js` | nginx `root` 少了一层目录 |
| 登录成功但刷新掉线 | nginx 是否带 `X-Forwarded-Proto` | Secure cookie 没下发 |
| 上传教材 413 | `client_max_body_size` | nginx 默认 1 MB |
| 问答一直"没有知识片段" | `#/api-config` 的语料面板 | 没跑 `rebuild_qa_corpus.py` |
| 问答 502 | `journalctl` 里 `模型返回 401` | Key 没填或填错 |
| 接口 500，日志 `UndefinedColumn` | `migrate.py --status` | 代码比库新，迁移没跑 |
| 服务起不来，`can't open file` | `WorkingDirectory` | 不在 `…/server` |
| `permission denied to create extension` | 第 2 步 | 扩展没用超级用户建 |
| 中文排序乱 | `lc_collate` | 建库时没设 `zh-x-icu` |

## 10. 以后要改东西，改哪里

| 想改什么 | 改哪里 | 改完做什么 |
| --- | --- | --- |
| 课程内容（知识点/习题） | 平台「课程内容工作台」在线改；或改 `data/course-*.json` | 在线改立即生效；改 JSON 要 `build_seed.py` → `import_seed.py` |
| 前端页面/交互 | `js/*.js`、`styles/*.css` | **改 `index.html` 里的 `?v=` 版本号**，否则浏览器用缓存的旧文件 |
| 接口逻辑 | `server/app/*.py` | `sudo systemctl restart whu-teaching` |
| 问答提示词与检索 | `server/app/qa.py` | 重启；改检索后建议重建语料 |
| 表结构 | 新增 `db/migrations/0018_xxx.sql` | `migrate.py --apply`，再 `migrate.py --concat` 重生成 `db/schema.sql` |
| 习题标签口径 | `server/app/exercise_tags.py` | 重启；无需迁移（标签是派生值） |
| 部署参数 | `.env`、`deploy/*` | 重启服务 / reload nginx |

两条规矩：

1. **已应用的迁移文件不许改**。`migrate.py` 会校验和，改了就报错；要改就新加一个文件。
2. **前端改动一定要升 `?v=`**。这是本地开发也适用的坑：文件在服务器上换了，
   浏览器还在用缓存，看到的仍是旧行为，很容易误判成"没生效"。

## 11. 换一台服务器 / 灾难恢复

有备份时，重建一台的顺序是：第 1、2 步 → `migrate.py --apply` → **恢复 dump**（不跑 seed）
→ `create_admin.py` → 拷 `secrets/` 与 `uploads/` → 第 4～6 步。

```bash
.venv/bin/python db/migrate.py --apply
pg_restore --no-owner --no-privileges --clean --if-exists -d "$DATABASE_URL" ~/backup/whu_teaching_日期.dump
```

`--clean --if-exists` 会先删同名对象再建；只在**空库或确认可覆盖**时用。
恢复完跑 `migrate.py --status` 与 `preflight.py` 双重确认。

## 12. 已知限制（别当成 bug 查）

- **没有接学校统一身份认证**。`AUTH_MODE=password` 是账号口令；`cas` 分支留了入口，
  但没实现。学生账号目前由管理员批量导入（Excel）。
- **向量检索还没接**。`embedding` 列与 `llm.embed()` 都在，但检索走的是关键词
  （`ILIKE`）。开向量需要 `EMBEDDING_API_KEY`，且要写一批 `textbook_chunk.embedding`。
- **教材 PDF 切片没做**。现在的问答语料来自知识点正文，引用标「知识点」不标页码；
  有 PDF 后再补切片与页码对齐。
- **教材生成是"逐章调模型"**，一章几十秒到几分钟，必须有 worker 才动；没 worker 时
  任务会停在队列里，页面上表现为"一直等待中"。
- 本文与 `deploy/*` 脚本在本机做过语法检查（`bash -n`）与路径核对，
  但**未在真实 Ubuntu 服务器上跑过**——第一次部署时按验收清单逐项确认。
