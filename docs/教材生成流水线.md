# 教材生成流水线（第一章切片）

老师上传教材 PDF，平台排队调用模型，生成**知识点 + 习题**并进审核队列。
这一页说明它怎么跑、边界在哪、哪些地方还没验证。

## 链路

`
老师：上传 PDF（教材生成页）
  → POST /api/v1/textbooks            原始字节，落 uploads/<sha256>.pdf，顺手探测页数与文字层
  → POST /api/v1/textbooks/{id}/generate   入队 pipeline_job(kind='generate')
  → worker：python scripts/run_worker.py
      1. 取该章文字（textbook.text_path，没有就用 pypdf 抽一次并存下）
      2. 拼 prompt，调模型（一章一次调用）
      3. 校验模型输出：知识点必须有正文，题目必须挂得上知识点，页码不能跑出本章
      4. 落库：chapter / knowledge_node / exercise，provenance 由代码判，review_status='draft'
      5. 写资源包：course-packs/<课程>/generated/job-<id>/{知识点.md,习题.md,知识节点.json}
  → 审核页：这些题出现在队列里，人工过一遍才发布
`

## 为什么拆成这么多步

prompts/Course-Building-Standalone.md 是给**智能体**的：它要求读 PDF、翻页核对、写 xlsx。
一次对话调用给不了这些能力。拆开之后职责是：

| 谁 | 负责什么 |
| --- | --- |
| 代码 | PDF → 带页号文本、书页/PDF 页换算、id、溯源标签、xlsx |
| 模型 | 这一章有哪些知识点、每道题的题干与解答 |

这不是把提示词削弱了，而是把**机器可读字段从模型手里拿走**。现有 4807 道题里
809 条溯源无法判定、1270 条没有精确页码，追根都是让模型写书目信息：它写
主教材习题一·2，导入器只能猜。现在书页由代码从真实 PDF 注入，溯源按
有没有教材原题号判定，这类噪声在生成端就不会出现。

## 跑一次

`ash
# 1. 建表（含 0007 迁移）
python db/migrate.py --apply

# 2. 抽文本（只需一次；没有 pypdf 时先装）
python scripts/extract_pdf.py 教材.pdf --out uploads/book.md

# 3. 起 worker（另开一个终端，常驻）
python scripts/run_worker.py

# 4. 打开平台「教材生成」页，选课程、填起止页、上传 PDF
`

开发期没有模型 Key 时，DEV_FAKE_MODEL=1 会走演示模型：结构真实、内容是占位，
任务照常入库进审核，用来打通链路。生产环境禁止该开关（main.py 会拒绝启动）。

## 边界与未验证项

- **扫描件没验证过。** 上传会显示无文字层，但 OCR 链路（pipeline_job.kind='ocr'）
  还没接。扫描件目前会失败在这一章没有抽到文字这一步，错误信息是明确的。
- **PDF 解析依赖 pypdf。** 这个环境装不上（无网络），所以测试用的是已经抽好的文本
  这条路径；probe_bytes 不依赖任何库，页数与文字层探测是真的跑过的。
- **没有失败重试的自动退避。** pipeline_job.attempts 有记录，但重试要手动。
- **整本书还没串起来。** 目前一次生成一章（一次调用）；整本 = 多次提交，
  拆章与父子任务字段（parent_id）已在表里，调度还没写。
- **生成结果不会自动出现在学生端。** 学生端读的是课程包静态数据，生成结果只进数据库和审核队列；
  发布流程（导出到 data/）还在设计。

## 成本

一章一次调用（约 1.2 万字上下文，输出 3–8 千字）。按 DeepSeek 的公开价格，
一章在几分钱到一毛钱之间；一本书十章不到一块钱。真正的成本是**人工审核**。
