# 习题页的分层与作答解锁

教学口径是「先引导，作答后解锁完整解答」。这不是文案，是**行为**：没作答时，完整解答
必须真的看不到。之前页面上写着"完整解答已解锁"，而参考简解就摆在折叠面板里，谁都能点开——
说的和做的不一致，分层等于没有。

## 一张题卡的三层

1. **引导（默认折叠，可展开）**
   不剧透，只给"想清楚这几件事"的材料：这道题用到哪些知识点、属于哪一章、出处定位，
   最后一句提示"先把思路和要用到的定理写下来"。
   这些全部来自已有元数据（`nodeIds`、`chapterId`、`source`），**没有让模型编提示**——
   编出来的"提示"很可能就是解题方向上的一句错的暗示。
2. **我的作答**
   文本框 + 保存。本地先存，再尝试提交后端；断网时学生的字不能丢。
3. **完整解答与来源**
   作答前是一个锁定条：说明"先写一句思路，保存后自动解锁"，并留一个出口
   「我卡住了，直接看解答」（弹一次确认，记下解锁时间，卡片标注"未作答查看"）。

## 解锁的四个来源

任一成立即解锁：

| 来源 | 写入时机 | 目的 |
| --- | --- | --- |
| 本机作答 | 保存非空作答 | 正常路径 |
| 本机"卡住了" | 点确认后写时间戳 | 明确放弃思考，但要留痕 |
| 后端有本人作答 | 进习题页时按课程拉一次 `/api/v1/attempts` | 换浏览器/换设备不必重答 |
| —（不存在） | — | 不提供"全课程一键解锁" |

服务端记录比本地缓存可信，所以进页面时会同步一次；学生之外的账号（教师/管理员）调用
作答接口会 403，静默跳过，不影响浏览。

## 顺带修掉的一个文案 bug

提交成功后原来的判断是 `result.status === 'submitted'`，而后端返回的是
`unlocks_full` 与 `attempt_no`，没有 `status`。于是成功也走 else 分支，弹出
「undefined；作答只保存在本机」——学生刚答完题就看到一句 undefined，会以为提交失败。

现在按 `unlocks_full` 判断，文案覆盖三种结果：

- 后端确认：`已提交到后端（第 N 次），完整解答已解锁。`
- 断网/未入库：`完整解答已在本机解锁，作答只保存在本机。`（先说解锁，再说局限）
- 其他错误：`提交失败：<原因>（完整解答已在本机解锁，作答已保存）`

空作答保存会明确说「仍然锁定」，不再假装保存成功。

## 测试

`scripts/test-view-exercises.cjs`（29 项）：未作答时答案字符串不出现在 HTML 里、
引导层与出处、保存后自动解锁、另一道未作答的题仍锁着、"我卡住了"要确认并记账、
空作答不解锁、提交成功/断网/未入库三种文案都不含 undefined、服务端记录也能解锁。

## 还没做

- **提示是元数据拼的，不是真正的分级提示**（例如"先考虑用单调有界原理"）。要做分级提示，
  需要在资源包里加 `hint` 字段并由老师审核——模型生成的提示不能直接给学生看。
- **作答版本与内容版本没绑定**：课程内容改了再发布，旧作答仍算在这道题上，解锁状态也跟着旧题走。
- **教师视角**看不到"哪些题学生普遍先看答案再看"：`revealed` 只存在本地，没有上传。
  这个数据对教学有用，但要先定隐私边界。
- **多设备解锁依赖 `/api/v1/attempts`**：目前每进一次习题页查一次，没有缓存；
  课程题目多时这个请求会变重。
