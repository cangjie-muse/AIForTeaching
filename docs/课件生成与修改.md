# 课件生成与修改

教师在「课件生成与修改」页选一个**章**或**节**，填目标页数和侧重点，点「生成初版」，
平台用这门课自己的知识点正文与已发布习题生成一版 PPT；之后教师写一句修改意见，
就能再出一版。每一版都留档，可下载、可回到旧版、可标记「已确认」。

## 现在能做什么

| 动作 | 说明 |
| --- | --- |
| 生成初版 | 范围选「章」会合并该章所有节；选「节」只做这一节 |
| 目标页数 | 6–40 页，默认 12。页数由内容决定，系统按它掌握详略 |
| 侧重点 | 一句话要求，如「多给一个反例」「删掉数值计算」 |
| 按意见改一版 | 输入意见 → 出新版本，旧的保留；列表里能对比 |
| 确认这一版 | 状态 `待教师确认 → 已确认`；确认后仍可继续改 |
| 下载 pptx | 任何生成成功的版本都能下载 |
| 过期提醒 | 本章知识点或习题改过，旧版本会标「内容可能已过期」 |

## 链路

```
教师：选章/节 → 生成初版
  → POST /api/v1/courseware          建 deck（一门课一个章/节一份）+ 建 version(pending)
  → pipeline_job(kind='courseware-generate')
  → worker：
      1. 取本地资料：该章/节及其下所有知识点的 content_md + 已发布习题（含答案）
      2. 调模型 → 结构化页面计划（标题/要点/公式文本/来源 ID/讲稿）
      3. 规范化：LaTeX 降级成 Unicode、来源 ID 只留本章有的、页数封顶
      4. slidedeck.py 渲染 pptx（排版、分页、页脚、备注全在代码里）
      5. 落库 version(needs-review) + 文件 uploads/courseware/<version>.pptx

教师：写意见 → 按建议改一版
  → POST /api/v1/courseware/{deck}/revise   带 base_version
  → pipeline_job(kind='courseware-revise')
  → worker：把"基础版本的计划 + 意见 + 同一份本地资料"一起给模型
       → 新计划 → 代码 diff 出 change_log → 渲染 → 新版本
```

## 为什么"计划"和"渲染"分开

| 谁 | 负责什么 |
| --- | --- |
| 模型 | 这一节讲什么、分几页、每页要点与公式、给教师看的讲稿 |
| 代码 | 字号、留白、分页、页脚、溢出拆页、文件名、版本号、变更清单 |

理由是排版的可预测性：**排版错一次会出现在每一页上**，而模型每生成一次都可能错。
代码错了改一次就永远对。

`change_log` 也是代码 diff 出来的，不用模型自报——模型说"只改了第 3 页"没法验证，
比较两版计划得到的差异可以。

## 公式：原生 OMML + 文字后备

幻灯片上的每条公式都写成 `mc:AlternateContent`：

```xml
<mc:AlternateContent>
  <mc:Choice Requires="a14"><a14:m>…OMML…</a14:m></mc:Choice>
  <mc:Fallback><a:r><a:t>ω = dθ</a:t></a:r></mc:Fallback>
</mc:AlternateContent>
```

- 支持 `a14` 的 PowerPoint / WPS：公式是**对象**，双击进公式编辑器，教师能直接改分式与根号。
- 不支持的渲染器：显示后备的 Unicode 文字，读到的是同一个式子，不会出现空白或乱码。

模型每条公式给两个字段：`text`（Unicode 可读写法，作后备）与 `latex`（标准 LaTeX，
供生成 OMML）。转换器 `server/app/omml.py` 只覆盖课堂幻灯片上真会出现的构造——
分式、根式、上下标、积分与求和、希腊字母、常用运算符、`\text{}`。
**遇到不认识的命令就抛 `Unsupported`，这一处退回文字**，绝不整页失败：一处公式是文字，
好过一整版空白。

为什么不用 PNG 逐页预览（这条是并行的另一个需求，暂时不做）：

| | 原生 OMML（已做） | PNG 逐页预览（未做） |
| --- | --- | --- |
| 解决 | 教师后续**改公式**的成本 | 下载前**看版面**的成本 |
| 代价 | 纯代码，转换器 ~350 行 | 服务器装 LibreOffice（约 400MB）+ pptx→图链路 + 中文字体 |
| 现状 | 已实现并校验 `a14:m` 数量 | HTML 版式预览已能看内容与顺序，差的只是字号与溢出 |

先做 OMML 的依据：这个产品的定位是"教师拿去继续改"，数学课要改的大概率是公式；
而版面问题我们已经在渲染时用拆页规则挡了一道。等真的出现"版面对不上"的反馈，再补 PNG。

**未验证**：WPS 里对这批 OMML 的实际渲染效果（本地无法启动 WPS）；`a14:m` 的兼容写法
沿用演示课件 V5 的结构，V5 在 WPS 里可用，但那是手工核对的 27 处，与批量生成不完全等价。

## 状态与版本

- 版本状态：`pending`（排队/生成中）→ `needs-review`（待确认）→ `approved`（已确认）；
  失败留在 `failed` 并写 `error`。
- 版本不可变：修订产生新行，旧行不动；`based_on` 记住从哪一版改的。
- 删除版本只允许管理员，且只删库里的行（磁盘文件留着，便于事后查证）。

## 成本

一节一次调用，上下文约 1.4 万字（知识点正文上限），输出 2–4 千字。按 DeepSeek 公开价格，
一次几分钱到一毛。改一版同样一次调用。真正的成本仍是教师读一遍。

## 限制（都是有意留的）

- **只读本地资料**：不联网、不读教材 PDF 原文（PDF 全文入口还没接到课件这条链上），
  所以"资料里没有的"确实生成不出来——这是设计，不是缺陷。
- **只取 `published` 习题**：草稿题连教师都没确认，拿它当课件素材会把错误带进课堂。
- **不自动发布给学生**：课件只在教师端；学生端读的是课程包静态数据。
- **教师能看全部课程的课件**：v1 不按班级收窄。
- **修订不做逐页锁定**：模型会重排整份计划，可能顺手动到无关页（diff 里看得见）。
  需要"只改第 3 页"这种硬约束时，下一步加 page-level lock。
