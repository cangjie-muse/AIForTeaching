总览：准确率来自一条证据链

不是选择一个大模型就能得到可靠数学教学。准确率由原文解析、语义切片、人工审核、混合检索、确定性计算、教师评测和版本治理共同决定。

设计边界：带「官方」或「论文」链接的内容是外部资料支持的事实；未带链接的尺寸、阈值和门禁均为本项目初始设计值，不是行业结论。厂商未公开的切片参数和模型不作为事实引用，厂商榜单也不代替校内教材实测。本页面是技术设计基线，不代表这些指标已经在现有系统实测通过。

为什么不用固定字数切片

固定 500 字可能把定理前提和结论分开，也可能把两个不同定义混在一块。对数学文本，语义完整性优先于块大小。

决策：按定义、定理、证明、例题和习题的结构切片，token 尺寸只作检索优化。

为什么不只依赖大模型

语言流畅不能证明数学正确，引用真实教材也可能漏掉关键条件。向量相似度只负责找候选，不负责宣布答案正确。

决策：精确匹配 + 稀疏 + dense + 图谱 + 重排，最终由证据检查、CAS 和教师盲评把关。

知识切片：结构优先，语义完整

实例：一个定理如何切

父切片 · 定理

定理 2.4.3　设 f 在闭区间 [a,b] 上连续，则 f 在 [a,b] 上一致连续。

必须一起保存：闭区间条件、连续性假设、一致连续结论、定理编号、所属章节、书页/PDF 页。

子切片 · 证明步骤

证明按逻辑步骤拆分，但每一步都带「定理 2.4.3」和必要上下文。检索命中证明步骤后，可以扩展回完整定理。

错误做法与修正

按页切定理跨页时条件丢失 → 按原文块跨页重组。
按 500 字切定义和例题混杂 → 先识别数学块类型。
让 LLM 改写原文可能改变量词与条件 → 原文和检索投影分离。
公式只存图片无法检索和校验 → LaTeX + AST + 原图 + 相邻说明。
整本翻译后覆盖无法追溯误译 → 原文与审核翻译独立版本关联。

内容类型切片规则初始检索尺寸不能破坏的条件
定义编号、名称、条件、符号、脚注组成原子单元100—800 tokens不能切断定义条件
定理/引理前提、结论、编号和引用完整保留200—1,200 tokens超长可保留，不能强切

Token 按当前 Embedding tokenizer 计算，不用中文字符数估算。尺寸是初始调参值，不是数学完整性的上限。

多语言教材的额外规则

按块识别语言

保存 BCP 47、文字系统、方向和 OCR 版本，支持混排、RTL、竖排与公式块。

原文与翻译独立

翻译绑定原文版本；新原文不能搭配旧翻译发布，历史 release 保留固定配对。

按语言分别验收

新语种先做 30—50 页和 50—100 问测试，不能由模型宣传推导平台效果。

向量化：多语言基线 + 可替换索引

向量只负责语义候选召回。选择模型时同时看数学证据、跨语言能力、隐私、硬件、成本和可回放性，而不是只看通用榜单。

→
检索投影模板版本 + 父级路径
→
动态批处理模型 revision + tokenizer

独立索引HNSW cosine + 构建清单
document_embedding = embed(model_revision, retrieval_text,
                           role="document", normalize=True)
query_embedding = embed(model_revision, query, role="query",
                        instruction=query_instruction_version, normalize=True)

index build: HNSW(vector_cosine_ops), m = 16, ef_construction = 128
query transaction: hnsw.ef_search = 100, iterative_scan = strict_order

模型 revision、tokenizer、query/document 指令、运行精度和归一化全部写入不可变配置。同名模型不同 revision 不混用。ef_search 是查询期参数，不是 HNSW 构建参数；strict_order 也不等于精确最近邻。pgvector 对近似索引的普通过滤发生在索引扫描之后，权限/Release 过滤可能造成候选不足；0.8.0+ 可用 iterative scan，但仍须实测召回、扫描上限与延迟（pgvector 官方说明）。

混合检索，而非向量单路

① 权限固定先固定 release_context、数据许可和可见范围；数据库强制过滤，LLM 不参与授权决定。
② 多路召回初始值：概念/别名 20 + 稀疏 60 + dense 60 + 图谱扩展 ≤20。
③ 合并重排初始值：RRF k=60，前 30 进入 multilingual reranker；k 值来自常用起点而非普遍最优（Cormack 等，2009）。
④ 完整证据从前 20 候选选 5—8 个证据，初始上下文 ≤8,000 tokens；子块命中后扩展已审核父块。
⑤ 答案检查检查关键条件、引用支持、数学正确性和过度拒答。

模型替换的硬门槛

  • 问题级 Hit@5 绝对提升 ≥3 个百分点，多证据题另报 evidence Recall@5；
  • 同一隐藏问题集 paired bootstrap 95% CI 下界 >0；
  • 每个关键语种召回下降 ≤2 个百分点且仍过门禁；
  • 检索 P95 ≤ 基线 1.2 倍且满足 SLO；
  • 月度 Embedding + rerank 成本 ≤ 基线 1.2 倍且未超预算；
  • 创建新 index_version 与 retrieval_config_version，历史 release_context 不漂移。
为什么：避免因为一次演示、单一榜单或新模型热度，重建全部向量并改变历史检索结果。
回放缺口已补齐：索引相同不代表检索相同。release_context 必须同时固定 retrieval_config_version，内容包括 query/document 指令、稀疏分词器、reranker revision、RRF k、各路候选数、图谱扩展规则、HNSW 查询参数、父块扩展和上下文预算。修改任一项都创建新配置，不在原配置上 UPDATE。

三类 Release，不共享可见性

学院目录独立 knowledge_approval，服务学院公共概念。
课程公共知识固定 base_college_release，不随学院最新版漂移。
班级教学材料固定 base_course_release，任课教师 teaching_confirmation。

历史作业与 agent_run 保存完整 release_context，包括三 release 和三 index_version。

发布与索引的数据库一致性约束

  • index_version 对 (id, release_id) 建唯一约束；Release 的 active index 用复合外键保证属于本 Release，循环外键采用可延迟约束。
  • release_context 的每个 release/index 对同样用复合外键校验，禁止把课程 Release 配上学院索引。
  • context 另固定 retrieval_config_version_id；索引维度、模型 revision 与配置必须兼容。
  • 历史 context 只负责可回放，不代表永久可用；内容纠错、许可撤回或安全事件可紧急禁用。
  • 新问答、打开、下载和签名 URL 续期必须检查当前撤回集合；特权审计回放只读并明确标记「历史版本」。
  • 撤回事件单独持久化，不能改写历史 Release 或审核记录来「消除痕迹」。

为什么现在不引入 Neo4j 和独立向量数据库

当前收益
  • 发布、权限、审核和向量能在同一事务/快照协作；
  • 递归 CTE 可处理先修链和图关系；
  • 减少两套数据同步和一致性问题；
  • 便于备份、回放和迁移。
未来拆分条件
  • 真实图查询经基准证明 PostgreSQL 不足；
  • 向量召回、P95 或构建时间持续不达标；
  • 独立扩缩容收益高于运维成本；
  • 新引擎仍是投影，不成为第二业务真源。

准确率：每道门禁单独验收

以下是 go/no-go 目标，不是当前成绩。不能用平均准确率掩盖定理条件错误、小语种失败、证明误判或越权发布。

统计判定：主课程至少 400 问（开发 ≥200、隐藏 ≥200），关键分层/语言隐藏样本 ≥100。正向指标以 95% CI 下界过线，错误率以 CI 上界过线；点估计达标但区间不达标不能上线。零观察到错误仍需报告置信上界。样本量必须按目标、预期点估计和 CI 方法反推；隐藏样本不足时结论是「未判定」，不是「通过」。
先冻结指标协议：每个指标先写清分子、分母、问题级/证据级单位、分层规则、缺失与超时处理、置信区间方法和代码版本。比例指标用适合二项数据的方法，模型对照在同一案例上配对；不得看结果后更换口径或删除失败案例。
正式发布底线：知识点、图谱节点与边、习题、答案、解析、量规和公开切片的人工审核有效率为 100%。抽样评测用于估算质量，不替代全项人工审核。

Lean 与人工审核

人工责任Lean 通过不能替代人工审核，也不能自动证明自然语言题意一致。
验证对象绑定 exercise、answer、solution、rubric、形式命题和依赖决策。

数学语义与评测：比文本知识库再多一层

数学准确率不能只靠文本相似度。平台需要知道教材约定、命题条件、量词、变量定义域、证明依赖和答案测试，并把评测集本身作为受治理的数据资产。

渐进式原则：不要求把整本教材形式化。首期只对试点章节建立 structured 语义；原文仍是教材证据，AST 是可审核的派生语义，Lean 是更高级但独立的验证层。

实例：不能只存 LaTeX

「对任意 ε > 0，存在 δ > 0……」

{
  statement_kind: "definition",
  formula_ast: ["forall", "ε>0", ["exists", "δ>0",
    ["implies", ["and", "x,y∈I", "|x-y|<δ"],
                "|f(x)-f(y)|<ε"]]],
  convention: "course-real-analysis-v3",
  semantic_level: "structured"
}

同样的符号在不同教材或章节可能有不同含义。symbol_binding 保存变量类型、自由/约束关系和来源位置，防止只做字符串拼接。

显示层保存 LaTeX 与 Presentation MathML，必要时增加 intent 以改善语音/盲文消歧；语义层可选 Content MathML 或 OpenMath。MathML 4 明确区分 Presentation 与 Content，并定义 intent / arg（W3C MathML 4）。显示标记不能替代受审核 AST。

教材约定不是错误

自然数有的教材包含 0，有的从 1 开始。
递增有的表示严格递增，有的表示非递减。
对数log 的默认底数需要课程或教材上下文。
处理方式课程 release 固定 convention_version；真正冲突才进入审核，不由模型自动统一。

借鉴 STACK：数学判题分两步 官方 Answer Tests

输入校验语法、类型、缺失括号、非法输入
→
数学性质测试代数等价、定义域、矩阵、容差
→

STACK 的答案测试可返回 true / false / fail，并携带错误、反馈与备注；本平台必须把 fail 当作「无法判定」转人工，不能折算为学生答错。STACK 还建议预生成、测试并部署随机变体，且在每个部署变体上运行全部题目测试（官方部署说明）。

参数化题目：模板审核与确定性测试不替代实例治理。每个具体 seed/参数实例仍需通过全部测试、渲染检查及匹配的人工决策，才能进入班级或公共 Release；失败实例不得靠重抽 seed 静默消失，须记录原因。

多解法、反例与交互数学

  • 多解法：solution_version 保存不同方法，不只给一条模型答案。
  • 反例实验室：必须验证满足全部前提且否定结论，不能只生成看似合理的例子。
  • 交互数学：公式、参数、代码、图形和数据联动，借鉴 GeoGebra 的探索方式。
  • 证明复核：优先定位第一处可疑步骤，不以整段相似度给证明判分。

答案分组复核

借鉴 Gradescope：AI 可建议答案分组，教师查看建议组后用 rubric 和评论评分；其公开说明中的 AI 建议组面向固定模板作业的选择、数学填空和文本填空等题型，并非开放证明自动判分（官方指南）。本平台让学生可申诉，所有改分保留审计。

不做：让 AI 一次性阅读整份作业后直接批量发布成绩。

分组是减少重复工作，不是取消教师判断；开放证明仍需要逐步复核。
