## 一、直接影响设计的事实

### 1. Embedding 与重排

- BGE-M3 官方资料列出 1,024 维、最长 8,192 tokens、100+ 种语言，并支持 dense、sparse 与 multi-vector。首期仍只用 dense，避免把「支持」误写成「已经启用并验收」。
- Qwen3-Embedding-0.6B 为 1,024 维、32K 上下文，支持指令与 MRL。检索指令用于 query，document 不添加指令；对照实验固定维度，避免维度变化成为混杂因素。
- bge-reranker-v2-m3 是多语言 cross-encoder。重排分数仍不是数学正确性证明。

### 2. OCR 与文档解析

- Docling 官方资料支持 PDF/扫描文档转换、公式处理与阅读顺序等能力。
- PaddleOCR-VL-1.6 于 2026-05-28 发布；官方报告 OmniDocBench v1.6 总分 96.33%。该数字不是本校教材的字符准确率、公式完全匹配率或阅读顺序准确率。
- 因此 v1.4.0 把 `Docling + PaddleOCR-VL-1.6` 标为「OCR 基线候选」，而非已验收生产选择。
- OmniDocBench 论文覆盖多种文档来源，并提供文本、表格、公式、阅读顺序及端到端评价。校内仍需单独建立教材金标准。

### 3. pgvector 与可回放检索

- pgvector 官方 README 说明：HNSW/IVFFlat 近似查询的普通过滤发生在索引扫描后，可能导致返回数量不足。
- pgvector 0.8.0 起支持 iterative index scans。`strict_order` 保持已扫描结果的距离顺序，`relaxed_order` 可改善过滤场景的召回与性能，但最终严格排序需另行处理。
- `hnsw.ef_search` 是查询期设置，不是索引构建参数。蓝图已将 `m`、`ef_construction` 留在 `index_version`，将 `ef_search`、迭代扫描及扫描上限移入 `retrieval_config_version`。
- 仅固定 `index_version` 不足以回放：query/document 指令、稀疏分词器、reranker revision、RRF k、候选数、图扩展、父块扩展与上下文预算均须版本化。
- RRF k=60 只是常用初值，不是对本数学语料普遍最优的保证。

来源：

- [pgvector 官方 README：Iterative Index Scans](https://github.com/pgvector/pgvector#iterative-index-scans)
- [pgvector 0.8.0 发布说明](https://github.com/pgvector/pgvector/blob/master/CHANGELOG.md#080-2024-10-30)

### 4. STACK、Lean 与 MathML

- STACK Answer Tests 可返回 true、false、fail，并携带错误、反馈与备注；`fail` 必须转人工，不能当作学生答错。
- STACK 建议预生成、测试并部署随机变体，在每个部署变体上运行全部题目测试。本平台仍保留具体实例人工发布门禁。
- Lean `#print axioms` 可列出声明直接及传递依赖的公理。蓝图将 `sorryAx`、未批准自定义公理及策略外 native-eval 信任纳入拒绝规则。
- W3C MathML 4 区分 Presentation 与 Content，并定义 `intent` / `arg`。显示、可访问性标注与受审核语义 AST 是不同层次。

## 二、新增安全、合规与落地章节

### 1. 安全控制

OWASP RAG Security 建议将访问控制元数据与向量块共同保存，在检索时执行权限，隔离租户，并独立授权模型发起的工具调用。蓝图据此增加：

- 教材与检索内容中的指令一律视为数据；
- RLS / 安全视图、查询过滤与返回前复核共同防止越权；
- 工具与 Artifact 每次独立鉴权；
- 模型、分词器、OCR、后处理与容器 digest 锁定；
- 隐藏评测集使用独立授权与日志通道；
- `revocation_event` 作为紧急拒绝集合，历史记录保留但不得继续用于新问答或下载。

来源：

- [OWASP RAG Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html)
- [OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/)
- [NIST AI 600-1：Generative AI Profile](https://doi.org/10.6028/NIST.AI.600-1)

### 2. 数据与适用规则

- 《个人信息保护法》第六条要求目的明确、直接相关、影响最小与收集最小范围；第五十五条列出须事前开展个人信息保护影响评估的情形。
- JY/T 0643—2025 是智慧教育平台个人信息保护的重要教育行业参考；涉及未成年人时须核对专门规则。

## 三、同时修正的评测歧义

这些属于本项目指标定义，不是外部厂商结论：

- 将「Top-5 证据召回」拆为问题级 Hit@5 与多证据 evidence Recall@5。
- 将「引用支持准确率」拆为引用支持精确率与引用完整率。
- 公式 OCR 完全匹配以人工转写为 gold；数学等价但转写不同不算 OCR 完全匹配。
- OCR 字符准确率明确对应 CER，并要求报告替换、删除、插入。
- 隐藏样本不足时结论为「未判定」，不能视为通过。
- 新增 Release/index 复合外键、retrieval_config_version 和 revocation_event 的逻辑表结构。
